## 1.1. Объект автоматизации

Сервис **«ДИТ.Калькулятор»** в составе системы **ДИТ.Интеллект** (в документах встречаются наименования: «Сервис "ДИТ.Калькулятор"», «ДИТ.Интеллект. Сервис "Калькулятор"», «ДИТ.Интеллект Калькулятор 2.0»). Назначение сервиса по совокупности документов — **автоматизированный расчёт стоимости работ (РСЗ) по заявкам/работам в рамках государственных контрактов (ГК) и служебных заданий (СЗ) по методике 3-Р**, ведение НСИ для расчёта, формирование отчётной документации (ЧТЗ, ПЗ, ПМИ, ПОЗ, ОИО) и сопровождение процесса согласования расчётов между ДИТ и подрядчиками.

Типовая структура подсистем, повторяющаяся в БП (например, `БП - Формирование РСЗ по заявке…`, `БП - Работа с расчетами…`):
- Модуль управления расчетами (расчёты стоимости);
- Модуль «Работы» (заявки/работы, этапы);
- Модуль НСИ (контракты, задания, системы, подсистемы, справочники);
- Модуль формирования отчётной документации (редакторы ЧТЗ/ПЗ/ПМИ/ПОЗ, печатные формы).

## 1.3. Бизнес-цели (To-be)

1. **Достоверность расчёта**: исключить ошибки РСЗ из-за неполной НСИ; автоматические проверки заполненности НСИ и полноты коэффициентов перед согласованием (`БП - Проверка заполненности НСИ…`, `БП - Изменение логики заведения ГК v1/v2`).
2. **Сквозной процесс «заявка → расчёт → согласование → отчётная документация»** с минимизацией ручного ввода: автозаполнение из НСИ/СПУ/Техпортала/ДИТ.Мета, импорт ФОИ из Excel, автоподтягивание БП в документы (`БП - Интеграция с СПУ`, `БП - Интеграция с Тех. порталом`, `БП — Интеграция… с ДИТ.Мета`, `БП - Добавить возможность загружать ФОИ из Excel…`, `БП - Изменение логики для подтягивания БП в ПЗ и ЧТЗ`).
3. **Управление жизненным циклом**: статусные модели для Закупки, ГК, Этапа ГК, Работы/Заявки, СЗ, Этапа СЗ, Внутренней работы, ФОИ (в т.ч. с фиксированной стоимостью), РСЗ; автоматические переходы (`БП - Создание статусной модели…` ×2, `БП - Статус ФОИ с фиксированной стоимостью`).
4. **Расширение контура на внутренние работы ДИТ** (служебные задания) наряду с подрядными ГК (`БП - Карточка служебного задания (СЗ)`, `БП - Создание реестра _Внутренние работы_`, `БП - Календарный план СЗ`).
5. **Прозрачность финансов и планирования**: календарные планы ГК/СЗ, дашборд «Бюджеты и закупки», бюджетно-закупочная вкладка карточки Системы (`БП - Календарный план ГК/СЗ`, `БП - Создание дашборда…`, `БП - Создание вкладки _Бюджеты и закупки_…`).
6. **Качество отчётной документации**: соответствие шаблонам (ГОСТ/децимальные номера, нумерация разделов, единое представление пустых данных, ставка НДС по дате согласования) (`БП - Нумерация…`, `БП - Незаполненные данные…`, `БП - изменение ставки НДС…`, `БП - Заполнение децимального номера…`, `БП - Правки в шаблон ПЗ`).
7. **Снижение нагрузки на СТП**: самостоятельная работа аналитиков со статусами ФОИ, выгрузка замечаний, база знаний, раздел помощи (`БП — Изменение статуса ФОИ…`, `БП - Выгрузка замечаний к РСЗ`, `БП - База Знаний Калькулятора`, `БП - Создание раздела Помощь`).
8. **UX-единообразие и адаптивность**: выравнивание реестров, адаптивная вёрстка, кликабельные сущности, сокращение шагов навигации (`БП - Выравнивание реестров`, `БП - _Сделать интерфейс… адаптивным…`, `БП - Модернизация логики переходов…`).

## 1.5. Ограничения области (Scope exclusions / границы, явно указанные в источниках)

- Все доработки, касающиеся **Внутренних работ**, будут производиться после написания/реализации требований по добавлению в систему Служебного задания (`БП - Создание вкладки _Бюджеты и закупки_ в карточке _Системы_`).
- БП по статусной модели СЗ должна быть реализована строго после статусной модели Закупки/ГК/Этапа ГК/Работы (`БП - Создание статусной модели для СЗ, Этапа СЗ и Внутренней работы`).
- Механизмы работы с данными из СПУ/Техпортала «должны в дальнейшем дорабатываться» — текущие БП задают базовый контур (`БП - Интеграция с СПУ`, `БП - Интеграция с Тех. порталом`).
- Состав загружаемых атрибутов из ДИТ.Мета «в будущем может расширяться» (`БП — Интеграция ДИТ.Калькулятор с ДИТ.Мета`).
- Внесение коэффициентов трудоёмкости руководителями проектов — «предполагается в будущем»; сейчас — зона ответственности Администратора (`БП - Изменение реестра подсистем`, `БП - Разделение полей ФТ…`: «Администратор (временно)… Руководитель проекта (в будущем)»).
