исходного репозитория (`.doc` → `.extract/txt/`). Два уровня:

## Уровень 2. Первичные требования по каждой БП — `by_bp/`

- `by_bp/INDEX.md` — индекс 68 карточек с метриками объёма;
- `by_bp/enriched/<БП>.md` — **обогащённая карточка** из трёх слоёв:
  - **Слой А** — структурированная карточка по Вигерсу: термины → подсистемы → компоненты → цель → бизнес-цели и процессы → пользовательские требования (УТ, дословно) → функции системы (ФС) → раздел 5 целиком → варианты использования (п.6) → пользовательские сценарии и алгоритмы (п.7) → функции системы (п.8) → требования к данным (п.9) → внешние системы (п.10) → прочие задачи (п.11) → критерии приёмки (п.12) → внутренние вопросы/неясности → особенности структуры источника (отсутствующие/нестандартные разделы);
  - **Слой B** — артефакты вне нумерованных разделов и нестандартные разделы (>12), дословно;
  - **Слой C** — полный оригинал без сокращений.

## Гарантии полноты («не потерять ни буквы»)

1. Слой C каждой карточки содержит весь текст источника; автоматическая проверка вхождения нормализованного оригинала выполнена для всех файлов: **68/68 OK**.
2. Там, где таблица п.5 заполнена нестандартно, УТ извлекаются поиском формулировок «Пользователь должен / Пользователю необходимо / Необходимо обеспечить / Система должна / Требуется» по всему тексту БП и помечаются ⚠️ (ничего не перефразируется).
3. Пустые/отсутствующие разделы шаблона помечаются явной пометкой, а не удаляются молча (см. файл 12).
4. Противоречия и вопросы фиксируются на месте (A.15/A.16 в карточках, файлы 07 и 09 в SRS).

Инструменты сборки: `/workspace/.tools/enrich2.py` (карточки), `aggregate.py` (реестры 10–11, карта 12), `verify.py` (проверка неиз_losslessности слоя C), `mkindex.py` (INDEX).
