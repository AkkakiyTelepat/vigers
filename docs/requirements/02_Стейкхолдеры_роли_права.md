# 02. Стейкхолдеры, роли и права (Stakeholder Requirements / User Profiles)

## 2.1. Стейкхолдеры, прямо упомянутые в документах

| Стейкхолдер | Роль в системе / процессах | Источник |
|---|---|---|
| Департамент информационных технологий г. Москвы (ДИТ) | Заказчик системы; сотрудники выступают аналитиками, РП, администраторами | практически все БП |
| Подрядчики (аналитики подрядчика) | Формируют расчёты стоимости заявок (РСЗ), вносят ФОИ/БП | `БП - Формирование РСЗ…`, `БП — Изменение статуса ФОИ…` и др. |
| СТП (Служба технического сопровождения / «служба технической поддержки») | Вносит данные в НСИ сейчас; принимает обращения по ошибкам/откатам; целевая нагрузка снижается | `БП - Проверка заполненности НСИ…`, `БП - База Знаний Калькулятора`, `БП — Изменение статуса ФОИ…` |
| Пользователи бэкофиса (менеджеры закупки) | Инициаторы правок текстов ПОЗ | `БП - [Шаблон ПОЗ] Правки в текст ПОЗ…` |
| Буц Василий Алексеевич | Указан как лицо, тестирующее дашборд «Бюджеты и закупки» (проверка корректности данных/графиков) | `БП - Создание дашборда _Бюджеты и закупки_` |
| Руководители направлений / продуктов | Целевая аудитория дашборда бюджетов | `БП - Создание дашборда…` |

## 2.2. Ролевая модель (упомянутые роли)

Извлечение по всем 57 документам; роль указана в том виде, в каком встречается в источниках (названия ролей непоследовательны — см. `07_Противоречия…`, раздел Конфликты C-8).

| Роль | Полномочия (подтверждённые источниками) | Источники |
|---|---|---|
| **Администратор** | Полный доступ к системе: редактирование карточек ГК/Работ/Расчётов; запуск ручных синхронизаций (СПУ, Техпортал, НСИ); получение уведомлений об ошибках интеграций; изменение статусов из любого статуса (Работы, РСЗ, ФОИ); ведение справочников НСИ (Тип работ, Дорожные карты, задачи Jira); заполнение коэффициентов 3-Р и «Количества ФТ» (временно, до передачи РП); установка уровня языка разработки подсистем; публикация новостей в ТГ-канал; создание папок/статей Базы знаний; просмотр столбца «Стоимость» (единственная роль, для которой он отображается); видимость всех сценариев обучения в Базе знаний | большинство БП |
| **Администратор НСИ** | Управление записями НСИ: справочник «Тип работ», Системы/Подсистемы, СЗ/Этапы СЗ/Внутренние работы (переводы статусов, архив, корзина); добавление записей в справочник «Дорожная карта»; контроль заполненности обязательных полей перед переводом объектов в «Согласование РП» | `БП - Создание реестра _Закупки_`, `БП - Создание статусной модели для СЗ…`, `БП - Создание вкладки _Дорожная карта_…`, `БП - Создание вкладки _Бюджеты и закупки_…` |
| **Руководитель проекта (ДИТ) / РП ДИТ / РП** | Перевод ГК из «Черновик» в «Согласование РП» и далее; согласование расчётов на этапе «Согласование РП» (статусы «Согласовано РП» / «Отклонено РП»); редактирование блока «Размер команды» пока расчёт в статусе «Согласование РП»; доступ к вкладке «Ресурсное планирование» (только эта роль); добавление периодов работы по заявке; перевод Этапов ГК в «Оплачено»; работа с календарными планами; целевая аудитория дашбордов | `БП - Создание статусной модели для Закупки, ГК…`, `БП - Изменение блока _Размер команды_`, `БП - Модернизация логики переходов…`, `БП - Корректировка интерфейса расчета для РП`, `БП - Календарный план ГК/СЗ` |
| **Аналитик (Подрядчика)** | Создание и редактирование ФОИ/РСЗ; добавление ФОИ из НМЦК и вручную; загрузка файлов БП; перевод ФОИ «На согласование» из «Не согласовано»/«В работе»; замена ФОИ/ФТ из НМЦК; in-line редактирование полей «Уточняющая часть» и «Краткое описание» ФОИ в статусе «Черновик»; удаление БП в статусах «В работе»/«На доработке» без зависимостей | `БП - Формирование РСЗ… v2`, `БП - замена ФОИ из НМЦК…`, `БП - Работа с расчетами, как с таблицами в Excel`, `БП - Конструктор РСЗ`, `БП - Незаполненные данные…` |
| **Аналитик (ДИТ) / Проверяющий ДИТ / Аналитик качества (ДИТ)** | Согласование ФОИ (статус «Согласовано»); перевод ФОИ с «Согласовано» на любой статус при условии, что расчёт ≠ «Согласовано»; выставление замечаний (справочник замечаний, комментарии к ФОИ); проверка описаний ФОИ фиксированной стоимости (по одному ответственному аналитику); выгрузка замечаний к РСЗ | `БП - Изменение процесса работы с ФОИ внутри итераций`, `БП - Внедрение справочника замечаний к РСЗ`, `БП - Статус ФОИ с фиксированной стоимостью`, `БП - Выгрузка замечаний к РСЗ` |
| **Пользователь СПУР** | Заполнение полей созданного экземпляра документа и отправка на согласование (права проверяются СПУР) | `БП_СП интеграция… СПУР…` |
| **Пользователь (обобщённо)** | В разных БП определяется как «пользователь, обладающий одной из ролей: Аналитик Подрядчика, Аналитик Качества, Аналитик ДИТ, РП ДИТ, Администратор» либо иное сочетание | `БП - Выравнивание реестров`, `БП - Незаполненные данные…`, `БП - Правки в шаблон ПЗ` и др. |

> Во многих постановках актуальные права отнесены к внешнему артефакту: **«Матрица ролей и полномочий»** (`БП — Изменение статуса ФОИ пока РСЗ на согласовании`, `БП — Интеграция… с ДИТ.Мета`, `БП — Объединение реестров…`). Сама матрица в репозитории отсутствует — это пробел документации (см. OI-4 в файле 07).

## 2.3. Подтверждённые правила доступа (выборка конкретных формулировок)

1. Столбец «Стоимость» в списке ФОИ отображается **только для роли Администратор** (`БП - Формирование РСЗ… v2`).
2. Вкладка «Ресурсное планирование» на ЭФ «Работа» доступна **только для роли РП ДИТ** (`БП - Модернизация логики переходов…`).
3. Все поля в карточке ГК заблокированы для редактирования роли «Администратор» при определённых статусах (формулировка источника — см. Conflict C-3 в файле 07) (`БП - Изменение логики заведения ГК v1 (архив)`).
4. Редактирование блока «Размер команды»: доступно РП ДИТ, пока расчёт в статусе «Согласование РП»; блокируется при переводе в «На согласовании аналитика» (`БП - Изменение блока _Размер команды_`).
5. Откат статуса расчёта РСЗ из «Согласовано»: операция доступна **только роли Администратор** (по обращению в СТП) (`БП - Изменение процесса работы с ФОИ внутри итераций`).
6. Смена статуса ФОИ с «Согласовано» разрешена Аналитику ДИТ только при статусе расчёта ≠ «Согласовано» (там же); в другой БП — разрешено, пока расчёт не ушёл со стадии «Согласовано РП» (`БП — Изменение статуса ФОИ пока РСЗ на согласовании`) → противоречие C-1.
7. Справочник «Тип работ» доступен только роли Администратор; автозаполняется из связанных карточек Работ (`БП - Создание справочника _Тип работ_…`).
8. Доступ к вкладке «Бюджеты и закупки» имеют роли: Администратор, Администратор НСИ, Руководитель проектов, Аналитик ДИТ, Аналитик качества ДИТ; иные получают сообщение об отсутствии прав (`БП - Создание вкладки _Бюджеты и закупки_…`).
9. В Базе знаний пользователь видит только те папки/статьи, доступ к которым разрешён его роли; Администратор видит всё без фильтрации (`БП - База Знаний Калькулятора`, `БП MVP1…`).
10. Публиковать новости в Telegram-канал может только Администратор; при отсутствии прав — сообщение об ошибке (`БП на вывод данных из ТГ канала`).
11. Обновление данных из ДИТ.Мета по кнопке доступно ролям, имеющим право на обновление; иначе действие недоступно (`БП — Интеграция… с ДИТ.Мета`).
12. In-line редактирование таблицы ФОИ разрешено только для ФОИ в статусе «Черновик» (`БП - Работа с расчетами, как с таблицами в Excel`).
13. Удаление БП в Конструкторе РСЗ доступно Аналитику подрядчика только для статусов «В работе»/«На доработке» без зависимостей; заблокировано для «Согласовано» (`БП - Конструктор РСЗ`).
14. В диаграммах распределения сотрудников: администратор — добавление/удаление/редактирование, остальные — только просмотр (`БП на реализацию диаграмм…`).
15. Управление уровнем языка разработки подсистемы (смена значения) — роль Администратор; изменение автоматически синхронизируется с расчётами и фильтрацией ФОИ (`БП - Фильтрация ФОИ по low-code и типу методики`).

## 2.4. Целевые пользователи новых модулей

- **База знаний**: все авторизованные пользователи; онбординг-презентация автозапускается для всех ролей, кроме Администратора (`БП - База Знаний Калькулятора`).
- **Раздел «Помощь»** (чат-ассистент): пользователь + оператор поддержки; чат-бот отвечает по статьям Базы знаний, при недостижении консенсуса — передача оператору (`БП - Создание раздела Помощь`).
- **Дашборд «Бюджеты и закупки»**: РП (ДИТ), Руководитель направления, Руководитель продукта; регулярность использования — ежедневно (`БП - Создание дашборда…`).
- **Календарные планы ГК/СЗ**: руководители проектов, администрация (`БП - Календарный план ГК`, `БП - Календарный план СЗ`).
- **Telegram-виджет**: все пользователи приложения (просмотр), Администратор (публикация) (`БП на вывод данных из ТГ канала`).
