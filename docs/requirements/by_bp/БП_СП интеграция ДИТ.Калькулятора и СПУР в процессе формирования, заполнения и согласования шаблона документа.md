# 4. Цель и концепция решения

## 4.1. Цели и обоснование необходимости развития

Целью работ является реализация сквозного процесса подготовки и согласования шаблона документа между ДИТ.Калькулятором и СПУР без повторного ручного ввода данных . Решение затрагивает редактор документа, интеграционный модуль и модель хранения связей между документами систем.

- Автоматизировать создание нового экземпляра документа СПУР по команде пользователя из ДИТ.Калькулятора.
- Передавать исходные и предзаполненные данные из системы-владельца в СПУР.
- Обеспечить однозначное определение актуального экземпляра СПУР при наличии нескольких итераций.
- Возвращать в ДИТ.Калькулятор все поля актуального экземпляра после отправки на согласование.
- Исключить изменение влияющих данных ДИТ.Калькулятора во время согласования и восстановить возможность изменения после отката.

## 4.2. Описание проблем и решения

| Проблема | Влияние | Решение |
|---|---|---|
| Повторный ввод уже известных данных в двух системах. | Риски ошибок, увеличение сроков подготовки документа. | Предзаполнение полей СПУР данными ДИТ.Калькулятора при создании экземпляра. |
| Возможность нескольких итераций документа без явного источника актуальных данных. | Данные старого экземпляра могут перезаписать актуальное состояние. | Хранить все связи с экземплярами и единственный явный признак актуальности. |
| Изменение исходных данных во время согласования. | Расхождение данных в системах и нарушение целостности процесса. | Блокировать связанный функционал после отправки на согласование; снимать блокировку по событию отката. |

# 6. Автоматизация бизнес-процессов

Объект автоматизации

## Целевой процесс (to be)

1. Пользователь открывает документ в ДИТ.Калькуляторе; система отображает предзаполненные и доступные для редактирования данные.
2. Пользователь нажимает «Перейти к формированию шаблона». ДИТ.Калькулятор проверяет статус и обязательные поля.
3. ДИТ.Калькулятор передаёт в СПУР запрос на создание нового экземпляра с идентификатором документа, предзаполненными полями и идентификатором корреляции.
4. СПУР создаёт экземпляр и возвращает его идентификатор. ДИТ.Калькулятор сохраняет связь и назначает экземпляр актуальным.
5. Пользователь заполняет в СПУР только поля своей зоны ответственности и отправляет документ на согласование.
6. СПУР передаёт в ДИТ.Калькулятор все поля актуального экземпляра и его статус. ДИТ.Калькулятор сохраняет данные и блокирует связанный функционал.
7. При откате согласования СПУР передаёт событие отката; ДИТ.Калькулятор снимает блокировку.
8. При повторном запуске формирования ДИТ.Калькулятор создаёт новый экземпляр СПУР, снимает актуальность с предыдущего и назначает актуальным новый экземпляр.

Предусловия

1. Пользователь авторизован в ДИТ.Калькуляторе.
2. Пользователь имеет права на редактирование документа и запуск формирования шаблона.
3. Документ ДИТ.Калькулятора существует и открыт в экранной форме редактора.
4. Документ находится в статусе, допускающем формирование шаблона, например «Черновик» или «Возвращён после отката».
5. Документ не заблокирован вследствие активного согласования актуального экземпляра СПУР.
6. Предзаполненные поля документа сформированы и сохранены в ДИТ.Калькуляторе.
7. Значения обязательных полей, необходимых для создания документа СПУР, заполнены и валидны.
8. API СПУР доступно для обработки запросов на создание документа.

Постусловия при успешном завершении

1. В СПУР создан новый экземпляр документа.
2. В созданном экземпляре СПУР сохранён ID документа ДИТ.Калькулятора - calculatorDocumentId.
3. В созданный экземпляр СПУР переданы предзаполненные поля из ДИТ.Калькулятора.
4. В ДИТ.Калькуляторе сохранён ID нового экземпляра СПУР - spurDocumentId.
5. Документ ДИТ.Калькулятора связан со всеми созданными по нему экземплярами документов СПУР, включая новый экземпляр.
6. Для нового экземпляра в ДИТ.Калькуляторе установлен явный признак актуальности, например isActual = true .
7. Если до создания нового экземпляра уже существовал актуальный экземпляр СПУР, у него снимается признак актуальности: isActual = false.
8. Новый экземпляр СПУР становится единственным актуальным экземпляром, связанным с документом ДИТ.Калькулятора.
9. Документ ДИТ.Калькулятора остаётся доступным для редактирования до момента отправки актуального экземпляра СПУР на согласование.

Основной поток

1. Пользователь открывает документ в редакторе ДИТ.Калькулятора.
2. ДИТ.Калькулятор отображает поля документа.
3. Система автоматически отображает значения полей, полученные из НСИ, входящей в состав ДИТ.Калькулятора, и из родительских сущностей.
4. Пользователь при необходимости заполняет или корректирует поля, доступные для редактирования в ДИТ.Калькуляторе.
5. Пользователь нажимает кнопку «Перейти к формированию шаблона» .
6. ДИТ.Калькулятор проверяет: существование документа; статус документа; отсутствие блокировки; заполненность обязательных данных; валидность значений; доступность операции создания нового экземпляра.
7. ДИТ.Калькулятор формирует интеграционный запрос в СПУР.
8. В запрос включаются как минимум: calculatorDocumentId ; тип или вид документа; предзаполненные поля; сведения об инициаторе, если они необходимы СПУР; correlationId для трассировки операции.
9. ДИТ.Калькулятор вызывает API СПУР для создания нового документа.
10. СПУР создаёт новый экземпляр документа, присваивает ему уникальный spurDocumentId .
11. СПУР сохраняет переданный calculatorDocumentId в созданном экземпляре документа.
12. СПУР сохраняет значения предзаполненных полей, переданные из ДИТ.Калькулятора.
13. СПУР возвращает в ДИТ.Калькулятор успешный ответ с spurDocumentId .
14. ДИТ.Калькулятор сохраняет связь между документом ДИТ.Калькулятора и новым экземпляром СПУР.
15. ДИТ.Калькулятор устанавливает новому экземпляру СПУР признак isActual = true .
16. Если документ ДИТ.Калькулятора ранее был связан с другим актуальным экземпляром СПУР, ДИТ.Калькулятор снимает у предыдущего экземпляра признак isActual.
17. ДИТ.Калькулятор отображает пользователю уведомление об успешном создании документа в СПУР.

Альтернативные потоки

A1. Не заполнены обязательные поля ДИТ.Калькулятора

1. На шаге 6 ДИТ.Калькулятор выявляет незаполненные или невалидные обязательные поля.
2. ДИТ.Калькулятор не вызывает API СПУР.
3. Система отображает пользователю ошибки валидации.
4. Пользователь корректирует данные.
5. Пользователь повторно нажимает кнопку «Перейти к формированию шаблона».
6. Выполнение продолжается с шага 6 основного потока.

A2. Документ заблокирован активным согласованием

1. На шаге 6 ДИТ.Калькулятор определяет, что по актуальному экземпляру СПУР документ находится на согласовании.
2. ДИТ.Калькулятор не вызывает API СПУР.
3. Система отображает пользователю сообщение: «Редактирование и повторное формирование шаблона недоступны, так как актуальный экземпляр документа находится на согласовании в СПУР. Для внесения изменений необходимо выполнить откат согласования.»
4. Use case завершается без создания нового экземпляра СПУР.

A3. СПУР отклоняет запрос по бизнес-валидации

1. На шаге 10 СПУР получает запрос, но выявляет ошибку данных: недопустимый тип документа, неверный формат поля, нарушение внутреннего правила СПУР или иной бизнес-ошибочный сценарий.
2. СПУР не создаёт документ.
3. СПУР возвращает в ДИТ.Калькулятор код и описание ошибки.
4. ДИТ.Калькулятор отображает пользователю сообщение об ошибке.
5. В ДИТ.Калькуляторе новая связь с документом СПУР не создаётся.
6. Признак актуальности существующих связей не изменяется.

Исключительные ситуации

E1. СПУР недоступен или истёк таймаут

1. На шаге 9 ДИТ.Калькулятор не получает ответ от API СПУР по причине технической ошибки, недоступности или таймаута.
2. ДИТ.Калькулятор фиксирует ошибку интеграции в журнале.
3. Новый экземпляр СПУР в ДИТ.Калькуляторе не считается созданным.
4. Пользователь получает сообщение о временной технической недоступности СПУР.
5. Документ ДИТ.Калькулятора остаётся в исходном доступном для редактирования состоянии.
6. Пользователь может повторить операцию позднее.

E2. Документ СПУР создан, но связь не сохранена в ДИТ.Калькуляторе

1. СПУР успешно создаёт документ и возвращает spurDocumentId.
2. На шаге 14 ДИТ.Калькулятор не может сохранить связь с новым экземпляром СПУР.
3. ДИТ.Калькулятор фиксирует ситуацию как частично успешную операцию.
4. Система сохраняет технические данные для восстановления связи: calculatorDocumentId, spurDocumentId, correlationId, дату и причину ошибки.
5. Пользователю отображается сообщение о том, что документ в СПУР создан, но связь требует технического восстановления.
6. Служба сопровождения либо автоматический механизм повторной обработки должны восстановить связь.

| Первичный актор | Пользователь СПУР |
| Вторичные акторы | СПУР, ДИТ.Калькулятор |
| Триггер | Пользователь в СПУР нажимает кнопку «Отправить на согласование» |
| Частота выполнения | Один раз для каждого экземпляра СПУР в рамках его цикла согласования |
| Приоритет | Высокий |

Предусловия

1. В СПУР существует документ, созданный по запросу ДИТ.Калькулятора.
2. Документ СПУР связан с документом ДИТ.Калькулятора по calculatorDocumentId.
3. На стороне ДИТ.Калькулятора связь с данным spurDocumentIdимеет признак isActual = true .
4. Экземпляр СПУР находится в статусе, допускающем редактирование и отправку на согласование, например «Черновик».
5. Пользователь авторизован в СПУР.
6. Пользователь имеет права на заполнение и отправку данного документа на согласование.
7. Предзаполненные поля, полученные из ДИТ.Калькулятора, отображаются в СПУР в режиме только для чтения.
8. ДИТ.Калькулятор доступен для приёма обратной синхронизации либо СПУР способен гарантированно повторить доставку сообщения.

Постусловия при успешном завершении

1. Документ СПУР переведён в статус «На согласовании» или эквивалентный статус.
2. СПУР передал в ДИТ.Калькулятор все поля текущего экземпляра документа.
3. ДИТ.Калькулятор проверил, что источник данных - актуальный экземпляр СПУР.
4. ДИТ.Калькулятор сохранил все поля, полученные из актуального экземпляра СПУР.
5. Документ ДИТ.Калькулятора переведён в состояние «На согласовании».
6. В ДИТ.Калькуляторе заблокирован весь функционал, связанный с редактированием данных данного документа.
7. Пользователь не может изменить влияющие на шаблон данные в ДИТ.Калькуляторе до отката согласования.

Основной поток

1. Пользователь открывает документ в СПУР.
2. СПУР отображает форму документа.
3. СПУР отображает предзаполненные поля, поступившие из ДИТ.Калькулятора, в режиме только для чтения.
4. СПУР отображает поля, предназначенные для ввода пользователем в СПУР.
5. Пользователь заполняет обязательные поля СПУР и при необходимости необязательные поля.
6. Пользователь нажимает кнопку «Отправить на согласование» .
7. СПУР выполняет валидацию: заполненность обязательных полей; соответствие форматов; допустимость значений; выполнение бизнес-правил; права пользователя на запуск согласования.
8. СПУР переводит экземпляр документа в статус «На согласовании».
9. СПУР фиксирует дату и время отправки на согласование.
10. СПУР формирует сообщение обратной синхронизации для ДИТ.Калькулятора.
11. В сообщение включаются: calculatorDocumentId; spurDocumentId; статус документа СПУР; все поля текущего экземпляра СПУР; дата и время направления на согласование; correlationId.
12. СПУР передаёт сообщение в API ДИТ.Калькулятора.
13. ДИТ.Калькулятор находит связь с экземпляром СПУР по spurDocumentId.
14. ДИТ.Калькулятор проверяет признак актуальности связи.
15. ДИТ.Калькулятор подтверждает, что экземпляр СПУР является актуальным.
16. ДИТ.Калькулятор сохраняет все полученные из СПУР поля в документе ДИТ.Калькулятора.
17. ДИТ.Калькулятор устанавливает статус документа, соответствующий нахождению на согласовании.
18. ДИТ.Калькулятор блокирует весь связанный функционал документа.
19. ДИТ.Калькулятор возвращает в СПУР успешный ответ о приёме данных.
20. СПУР отображает пользователю подтверждение успешной отправки документа на согласование.

Альтернативные потоки

A1. Не заполнены обязательные поля СПУР

1. На шаге 7 СПУР выявляет незаполненные обязательные поля.
2. СПУР не изменяет статус документа.
3. СПУР не передаёт данные в ДИТ.Калькулятор.
4. СПУР отображает пользователю список ошибок и подсвечивает поля.
5. Пользователь корректирует данные.
6. Пользователь повторно выполняет шаги 5–7 основного потока.

A2. Пользователь не обладает правами на отправку

1. На шаге 7 СПУР определяет отсутствие у пользователя прав на отправку документа на согласование.
2. СПУР не изменяет статус документа.
3. СПУР отображает пользователю сообщение о недостаточности прав.
4. Use case завершается.

A3. Экземпляр СПУР уже находится на согласовании

1. На шаге 1 или 6 СПУР определяет, что документ уже находится в статусе «На согласовании» или ином статусе, не допускающем редактирование.
2. СПУР открывает форму в режиме просмотра.
3. Кнопка отправки на согласование недоступна.
4. Пользователь не может изменить документ в рамках данного UC.
5. Для изменения документа требуется выполнить UC-03.

Исключительные ситуации

E1. ДИТ.Калькулятор недоступен при обратной синхронизации

1. На шаге 12 СПУР не может передать данные в ДИТ.Калькулятор.
2. СПУР фиксирует техническую ошибку и данные сообщения для повторной доставки.
3. Статус документа СПУР остаётся «На согласовании».
4. СПУР запускает повторную передачу в соответствии с техническим регламентом либо ставит сообщение в очередь.
5. В ДИТ.Калькуляторе блокировка может не наступить до успешной обработки сообщения.
6. Служба сопровождения контролирует рассинхронизацию до получения подтверждения от ДИТ.Калькулятора.

E2. ДИТ.Калькулятор получает данные неактуального экземпляра СПУР

1. На шаге 14 ДИТ.Калькулятор определяет, что поступивший spurDocumentIdсвязан с документом, но имеет признак isActual = false.
2. ДИТ.Калькулятор не сохраняет поля из такого сообщения в качестве актуальных данных документа.
3. ДИТ.Калькулятор не меняет статус и не изменяет блокировку актуального документа на основании этого сообщения.
4. ДИТ.Калькулятор возвращает в СПУР ошибку, например 409 Conflict: non-actual SPUR instance.
5. СПУР фиксирует ошибку интеграционного взаимодействия.
6. Данные актуального экземпляра СПУР остаются неизменными.

E3. Часть полей не удалось сохранить в ДИТ.Калькуляторе

1. ДИТ.Калькулятор получил сообщение от СПУР, но не смог сохранить все поля.
2. ДИТ.Калькулятор не должен подтверждать частично успешную синхронизацию без явно определённого правила частичной обработки.
3. ДИТ.Калькулятор возвращает СПУР техническую или бизнес-ошибку.
4. СПУР фиксирует необходимость повторной передачи.
5. Данные должны быть синхронизированы повторно в полном составе, чтобы не возникло частичного состояния.

UC 3

UC-03. Откатить согласование и сформировать новый экземпляр СПУР

| Атрибут | Значение |
|---|---|
| Идентификатор | UC-03 |
| Наименование | Откатить согласование и сформировать новый экземпляр СПУР |
| Цель | Снять актуальный экземпляр документа с согласования, разблокировать документ ДИТ.Калькулятора, изменить предзаполненные данные и создать новый актуальный экземпляр СПУР |
| Первичный актор | Уполномоченный пользователь СПУР |
| Сопутствующий актор | Пользователь ДИТ.Калькулятора |
| Вторичные акторы | СПУР, ДИТ.Калькулятор |
| Триггер | Возникает необходимость изменить предзаполненные поля документа, владельцем которых является ДИТ.Калькулятор |
| Частота выполнения | По необходимости при корректировке документа после направления или завершения согласования |
| Приоритет | Высокий |

Предусловия

1. Документ ДИТ.Калькулятора связан хотя бы с одним экземпляром СПУР.
2. Экземпляр СПУР, по которому выполняется откат, имеет признак isActual = true  в ДИТ.Калькуляторе.
3. Экземпляр СПУР находится в статусе, при котором допустим откат согласования согласно правилам СПУР.
4. Пользователь СПУР имеет права на выполнение отката.
5. В ДИТ.Калькуляторе документ заблокирован либо должен быть разблокирован по результату отката.
6. После отката пользователь ДИТ.Калькулятора имеет право редактировать необходимые предзаполненные поля и повторно запускать формирование шаблона.
7. API ДИТ.Калькулятора доступно для приёма события об откате.

Постусловия при успешном завершении

1. Предыдущий актуальный экземпляр СПУР переведён в статус «Откатан», «Возвращён в доработку» или иной эквивалентный статус.
2. ДИТ.Калькулятор снял блокировку с документа.
3. Пользователь изменил необходимые поля в ДИТ.Калькуляторе.
4. Пользователь повторно выполнил UC-01.
5. По API СПУР создан новый экземпляр документа.
6. Новый экземпляр связан с тем же документом ДИТ.Калькулятора.
7. У предыдущего экземпляра СПУР установлен isActual = false.
8. У нового экземпляра СПУР установлен isActual = true .
9. После отправки нового экземпляра на согласование ДИТ.Калькулятор принимает и сохраняет все поля именно из этого нового экземпляра.
10. Предыдущие экземпляры СПУР сохраняются как связанные, но не являются источником актуальных данных.

Основной поток

Часть 1. Откат согласования

1. Уполномоченный пользователь открывает актуальный экземпляр документа в СПУР.
2. Пользователь инициирует действие «Откатить согласование» .
3. СПУР проверяет: права пользователя; допустимость отката для текущего статуса; отсутствие иных ограничений, запрещающих откат.
4. СПУР переводит актуальный экземпляр документа в статус «Откатан» или «Возвращён в доработку».
5. СПУР формирует событие для ДИТ.Калькулятора.
6. В событие включаются: calculatorDocumentId; spurDocumentId; новый статус экземпляра; дата и время отката; correlationId.
7. СПУР передаёт событие отката в ДИТ.Калькулятор.
8. ДИТ.Калькулятор находит связь с экземпляром СПУР.
9. ДИТ.Калькулятор проверяет, что данный экземпляр имеет признак isActual = true .
10. ДИТ.Калькулятор снимает блокировку связанного функционала документа.
11. ДИТ.Калькулятор изменяет статус документа на «Возвращён после отката» или эквивалентный.
12. ДИТ.Калькулятор подтверждает успешную обработку события.
13. СПУР отображает пользователю подтверждение отката согласования.

Часть 2. Изменение данных и создание нового экземпляра

1. Пользователь ДИТ.Калькулятора открывает разблокированный документ.
2. Пользователь изменяет доступные предзаполненные поля.
3. Пользователь сохраняет изменения.
4. Пользователь нажимает кнопку «Перейти к формированию шаблона» .
5. Выполняется UC-01 «Сформировать шаблон документа в СПУР».
6. ДИТ.Калькулятор вызывает API СПУР.
7. СПУР создаёт новый экземпляр документа.
8. ДИТ.Калькулятор сохраняет связь с новым spurDocumentId.
9. ДИТ.Калькулятор снимает признак isActualс предыдущего откатанного экземпляра.
10. ДИТ.Калькулятор устанавливает isActual = true для нового экземпляра.
11. Новый экземпляр становится единственным источником актуальных данных для обратной синхронизации.

Альтернативные потоки

A1. Откат согласования запрещён

1. На шаге 3 СПУР определяет, что откат недоступен: например, у пользователя нет прав, документ находится в финальном необратимом статусе либо действует иное бизнес-ограничение.
2. СПУР не изменяет статус документа.
3. СПУР не передаёт в ДИТ.Калькулятор событие об откате.
4. ДИТ.Калькулятор сохраняет блокировку документа.
5. Пользователь получает сообщение с причиной невозможности отката.
6. Use case завершается.

A2. Пользователь выполнил откат, но не запускает повторное формирование

1. Часть 1 основного потока успешно завершена.
2. Документ ДИТ.Калькулятора разблокирован.
3. Пользователь не вносит изменения или не нажимает кнопку «Перейти к формированию шаблона».
4. Новый экземпляр СПУР не создаётся.
5. Предыдущий экземпляр остаётся актуальным с точки зрения связи isActual, но находится в откатанном статусе.
6. Документ ДИТ.Калькулятора остаётся доступным для редактирования до повторного запуска UC-01.

A3. После отката изменены только поля СПУР

1. После отката пользователь определяет, что изменения требуются исключительно в полях, заполняемых в СПУР.
2. Согласно принятому правилу новый цикл всё равно должен быть сформирован через ДИТ.Калькулятор, так как повторное использование старого экземпляра СПУР не допускается.
3. Пользователь запускает UC-01.
4. СПУР создаёт новый экземпляр.
5. Пользователь заполняет или корректирует поля СПУР в новом экземпляре.
6. Дальнейшее выполнение продолжается по UC-02.

Исключительные ситуации

E1. ДИТ.Калькулятор недоступен при передаче события об откате

1. На шаге 7 СПУР не может передать событие об откате в ДИТ.Калькулятор.
2. СПУР фиксирует факт отката у себя и сохраняет сообщение для повторной доставки.
3. ДИТ.Калькулятор остаётся заблокированным до получения и успешной обработки события.
4. СПУР повторяет передачу события по техническому регламенту.
5. После успешной доставки выполняются шаги 8–13 основного потока.

E2. Событие об откате поступило от неактуального экземпляра

1. На шаге 9 ДИТ.Калькулятор определяет, что сообщение поступило от экземпляра, у которого isActual = false.
2. ДИТ.Калькулятор не снимает блокировку и не изменяет статус документа на основании этого сообщения.
3. ДИТ.Калькулятор возвращает ошибку о неактуальном экземпляре.
4. СПУР фиксирует исключительную ситуацию.
5. Актуальные данные и статус документа ДИТ.Калькулятора не изменяются.

E3. Ошибка при создании нового экземпляра после отката

1. Часть 1 основного потока выполнена успешно: документ разблокирован.
2. На шаге 19–20 API СПУР возвращает ошибку или становится недоступным.
3. Новый экземпляр СПУР не создаётся либо его создание не подтверждено.
4. Предыдущая связь сохраняется.
5. Предыдущий экземпляр остаётся откатанным.
6. Документ ДИТ.Калькулятора остаётся разблокированным.
7. Пользователь может повторно выполнить UC-01 после устранения ошибки.

Общие правила трассировкиДля всех трёх UC должны выполняться следующие правила:

- Каждый вызов API и каждое интеграционное сообщение должны содержать correlationId.
- В СПУР у каждого экземпляра документа должен храниться calculatorDocumentId.
- В ДИТ.Калькуляторе для каждого связанного экземпляра СПУР должен храниться spurDocumentId.
- Для одной записи документа ДИТ.Калькулятора допускается несколько связанных экземпляров СПУР.
- Для одного документа ДИТ.Калькулятора в каждый момент времени должен существовать ровно один экземпляр СПУР с признаком isActual = true .
- Данные, статусы и события от экземпляров с isActual = falseне должны перезаписывать актуальное состояние документа ДИТ.Калькулятора.
- При создании нового экземпляра СПУР прежний актуальный экземпляр становится неактуальным.
- Предзаполненные поля принадлежат ДИТ.Калькулятору и в СПУР недоступны для редактирования.

Поля, заполняемые в СПУР, принадлежат СПУР и после направления на согласование возвращаются в ДИТ.Калькулятор в полном составе только от актуального экземпляра

|---|---|---|

| SD-02. Отправка на согласование и синхронизация | UC-02 | Основной успешный сценарий |
| SD-03. Откат и разблокировка | UC-03 | Первая часть сценария корректировки |

# 8. Функции системы

## 1. Инициация формирования шаблона

ДИТ.Калькулятор должен предоставлять на форме документа кнопку «Перейти к формированию шаблона» и перед вызовом API проверять существование документа, его статус, обязательные поля и отсутствие запрета на запуск нового цикла.

## 2. Создание экземпляра СПУР

ДИТ.Калькулятор должен вызвать API СПУР для создания нового экземпляра. СПУР должен создать экземпляр с уникальным идентификатором и сохранить ID документа ДИТ.Калькулятора.

## 3. Управление связями и актуальностью

ДИТ.Калькулятор должен хранить все созданные экземпляры СПУР. У одного документа в каждый момент времени может быть только один экземпляр с признаком актуальности.

## 4. Ограничение редактирования в СПУР

СПУР должен отображать предзаполненные поля только для чтения и не принимать их изменение при попытке обхода интерфейса.

## 5. Обратная синхронизация

После отправки на согласование СПУР должен передать все поля, статусы и служебные атрибуты текущего экземпляра. ДИТ.Калькулятор применяет данные только от актуального экземпляра.

## 6. Блокировка и разблокировка

ДИТ.Калькулятор должен блокировать связанный функционал после синхронизации события отправки на согласование и снимать блокировку после события отката.

## 7. Обработка повторного формирования

После отката новый цикл должен создавать новый экземпляр СПУР. Предыдущие экземпляры не удаляются, но не участвуют в актуальной синхронизации.

## 8. Контроль и аудит

Системы должны журналировать операции, использовать идентификатор корреляции, поддерживать идемпотентность обработки и фиксацию интеграционных ошибок.

## 10.1. Общие требования

- Интеграция между ДИТ.Калькулятором и СПУР является двусторонней.
- Каждая операция должна содержать технический идентификатор корреляции для трассировки.
- Должна быть предусмотрена защита от повторной обработки одного сообщения и от дублирующего создания экземпляров при техническом повторе запроса.
- Передача данных выполняется с соблюдением требований разграничения доступа и информационной безопасности.
