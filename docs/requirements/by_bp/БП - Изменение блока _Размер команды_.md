# 8. Функции системы

8.1 Развитие ЭФ Итерации в части добавления реестра "Размер команды" для рефакторинга

На ЭФ Итерации необходимо добавить новый реестр "Размер команды (по рефакторингу)" (рис.2). Реестр должен быть аналогичен старому реестру "Реестр команды" по атрибутивному составу и функциональным возможностям.

Старый реестр "Размер команды" необходимо переименовать в " Размер команды (по созданию/развитию) "

Реестр "Размер команды (по созданию/развитию)" должен отображаться на экранной форме в случае если в последней актуальной итерации расчета присутствует хотя бы одна функция без признака "рефакторинг" или в согласованных функциях предыдущих итераций расчета присутствует хотя бы одна функция без признака "рефакторинг"

Реестр "Размер команды (по рефакторингу)" должен отображаться на экранной форме в случае если в последней актуальной итерации расчета присутствует хотя бы одна функция с признаком "рефакторинг" или в согласованных функциях предыдущих итераций расчета присутствует хотя бы одна функция с признаком "рефакторинг"

Если в расчете присутствуют функции как с признаком рефакторинга так и без него, то на экранной форме должны отображаться оба реестра.

Оба реестра должны быть обязательны для заполнения (при их наличии). Текст уведомления об обязательности заполнения необходимо заменить на: "Необходимо заполнить блок - "Размер команды"" .

8.2 Развитие алгоритма расчета индикатора "Предельная трудоемкость"

Необходимо изменить логику расчета показателя "Предельная трудоемкость" (теперь он должен учитывать оба реестра (при наличии)

Старая формула = Сумма значений "Стоимость заявки, рублей" по каждому периоду работ по заявке / "Ставка по ГК на создание / развитие системы"

Новая формула = ( "Стоимость по ФОТ, рублей"  / "Ставка по ГК на создание / развитие системы") + ("Стоимость по ФОТ, рублей"  / Ставка по ГК на рефакторинг)

В случае отсутствия на ЭФ одного из реестров, часть формулы отвечающая за пустой реестр должна быть равно 0.

Индикатор "Предельная трудоемкость" - должен быть всегда с белой заливкой

8.3 Развитие алгоритма ограничения доступа к редактированию блока "Размер команды" для РП ДИТ

Необходимо изменить логику работы алгоритма ограничения доступа к редактированию сведений в блоке "Размер команды" (для обоих реестров).

Заполненные значения должны быть доступны для редактирования пользователю с ролью РП ДИТ в любой момент, если расчет находится в статусе "Согласование РП". При переводе расчета в статус "На согласовании аналитика", редактирование значений должно блокироваться.
