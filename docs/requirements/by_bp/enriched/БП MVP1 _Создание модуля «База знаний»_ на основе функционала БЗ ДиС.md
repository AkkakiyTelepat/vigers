### A.4 Цель и концепция решения

Целью реализации Модуля является предоставление пользователям возможности ознакомления с обучающими материалами, собранными в базу знаний Подсистемы , а также возможности для администраторов управлять структурой и содержанием базы знаний Подсистемы.


## 4.2 Описание проблем и решения

Модуль предоставит пользователям обучающие материалы по Подсистеме, что позволит повысить эффективность использования возможностей Подсистемы пользователями и снизить время на их освоение, а администраторам следить за актуальностью базы знаний Подсистемы и своевременно обновлять статьи .

# 5 Требования к результату

В рамках реализации Модуля должны быть реализованы следующие функции для всех пользователей Подсистемы:

- Просмотр статей базы знаний Подсистемы;
- Полнотекстовый поиск по материалам статей базы знаний;
- Скачивание руководств пользователя и администратора;
- Скачивание файлов внутри статьи.

Т акже должны быть реализованы следующие функции только для администратора Модуля:

- Внесение статей в базу знаний;
- Изменение статей в базе знаний;
- Удаление статей из базы знаний;
- Управление структурой папок;
- Загрузка руководств пользователя и администратора.

## 7.2 Описа ние алгоритмов


### 7.2.1 Добавление и редактирование папок и статей базы знаний

При добавлении или редактировании папок и статей базы знаний администратору необходимо заполнить обязательные поля (отмечены "*") в интерфейсе:

- Расположение (для папок, за исключением корневых);
- Наименование.

При добавлении или редактировании корневой папки поле "Расположение" пустое и заблокировано для ввода.

Для перемещения папки в корень необходимо воспользоваться функцией drag-and-drop. Перемещение папки в корень через функцию редактирования должно быть недоступно.

Для перемещения корневой папки в другую папку необходимо воспользоваться функцией drag-and-drop. Перемещение корневой папки в другую папку через функцию редактирования должно быть недоступно.

Также, при добавлении или редактировании папок и статей базы знаний можно настроить доступ к записи, заполнив поля "Право" и "Условие".

- Поле "Право" определяет, какие именно разрешения позволяют пользователю увидеть эту папку или статью. Можно выбрать одно или несколько таких разрешений;
- В поле "Условие" выбирается правило проверки выбранных разрешений. Правило определяет, достаточно ли пользователю иметь одно любое выбранное разрешение или же у него должны быть все выбранные разрешения одновременно.

Таким образом, папка или статья станут видны пользователю только при выполнении заданных условий доступа. Если поля "Право" и "Условие" не заполнены, элемент будет доступен всем пользователям.


### 7.2.2 Удаление папок из базы знаний

При наличии в удаляемой папке статей/внутренних папок должна отображаться экранная форма с ошибкой о невозможности удаления по причине наличия в папке содержимого.

При отсутствии в удаляемой папке статей/внутренних папок алгоритм должен позволять проводить удаление папки из базы знаний.


### 7.2.3 Преобразование разметки статьи для просмотра пользователем

При открытии статьи в режиме просмотра должно автоматически отображаться её отформатированное содержание, полученное путём преобразования исходной Markdown-разметки статьи в HTML.

- Для указания стиля заголовка перед текстом необходимо добавить символ "#" (например, # Раздел 1) - для пользователя текст отобразится как крупный, структурно выделенный заголовок статьи. Уровень заголовка определяется количеством символа "#" : чем больше количество данного символа, тем ниже иерархический уровень заголовка;
- Для выделения выбранного фрагмента текста полужирным начертанием текст обрамляется двойными звёздочками (например, **ключевой термин**);
- Для выделения выбранного фрагмента текста курсивным начертанием текст обрамляется одиночными звёздочками (например, *ключевой термин*);
- Для выделения выбранного фрагмента текста подчеркнутым начертанием текст обрамляется двойными плюсами (например, ++ключевой термин++);
- Для оформления текста в виде маркированного списка перед каждой строкой списка ставится тире (например, - пункт списка);
- Для оформления текста в виде маркированного списка перед каждой строкой списка ставится номер пункта с точкой (например, 1. первый пункт списка);
- Для переноса текста на новую строку необходимо поставить дополнительный отступ, используя клавишу ввода (Enter);
- Добавление вложения в виде ссылки возможно с помощью соответствующей кнопки прикрепления ссылки ;
- Допустимым является загрузка файлов в форматах JPG/JPEG, PNG, GIF, SVG, PDF и DOCX, размер которых не превышает 30 МБ.


### 7.2.4 Поиск статьи по текстовому запросу

При вводе текста в поисковую строку должны отображаться все статьи , которые содержат в себе введенное в поле поиска значение. Поиск осуществляется по полному совпадению введенного значения, без учета регистра.


### 7.2.5 Просмотр папок и статей в зависимости от роли пользователя

При переходе в раздел базы знаний пользователь видит только те папки и статьи, доступ к которым разрешён его роли и правам доступа. Отображение содержимого базы знаний динамически формируется и изменяется в соответствии с назначенной пользователю ролью, а также с учётом прав и условий видимости, указанных для каждой папки и статьи.

# 4 Цель и концепция решения

## 4.1 Цели и обоснование необходимости развития

Целью реализации Модуля является предоставление пользователям возможности ознакомления с обучающими материалами, собранными в базу знаний Подсистемы , а также возможности для администраторов управлять структурой и содержанием базы знаний Подсистемы.

## 4.2 Описание проблем и решения

Модуль предоставит пользователям обучающие материалы по Подсистеме, что позволит повысить эффективность использования возможностей Подсистемы пользователями и снизить время на их освоение, а администраторам следить за актуальностью базы знаний Подсистемы и своевременно обновлять статьи .

# 5 Требования к результату

В рамках реализации Модуля должны быть реализованы следующие функции для всех пользователей Подсистемы:

- Просмотр статей базы знаний Подсистемы;
- Полнотекстовый поиск по материалам статей базы знаний;
- Скачивание руководств пользователя и администратора;
- Скачивание файлов внутри статьи.

Т акже должны быть реализованы следующие функции только для администратора Модуля:

- Внесение статей в базу знаний;
- Изменение статей в базе знаний;
- Удаление статей из базы знаний;
- Управление структурой папок;
- Загрузка руководств пользователя и администратора.

## 7.2 Описа ние алгоритмов

### 7.2.1 Добавление и редактирование папок и статей базы знаний

При добавлении или редактировании папок и статей базы знаний администратору необходимо заполнить обязательные поля (отмечены "*") в интерфейсе:

- Расположение (для папок, за исключением корневых);
- Наименование.

При добавлении или редактировании корневой папки поле "Расположение" пустое и заблокировано для ввода.

Для перемещения папки в корень необходимо воспользоваться функцией drag-and-drop. Перемещение папки в корень через функцию редактирования должно быть недоступно.

Для перемещения корневой папки в другую папку необходимо воспользоваться функцией drag-and-drop. Перемещение корневой папки в другую папку через функцию редактирования должно быть недоступно.

Также, при добавлении или редактировании папок и статей базы знаний можно настроить доступ к записи, заполнив поля "Право" и "Условие".

- Поле "Право" определяет, какие именно разрешения позволяют пользователю увидеть эту папку или статью. Можно выбрать одно или несколько таких разрешений;
- В поле "Условие" выбирается правило проверки выбранных разрешений. Правило определяет, достаточно ли пользователю иметь одно любое выбранное разрешение или же у него должны быть все выбранные разрешения одновременно.

Таким образом, папка или статья станут видны пользователю только при выполнении заданных условий доступа. Если поля "Право" и "Условие" не заполнены, элемент будет доступен всем пользователям.

### 7.2.2 Удаление папок из базы знаний

При наличии в удаляемой папке статей/внутренних папок должна отображаться экранная форма с ошибкой о невозможности удаления по причине наличия в папке содержимого.

При отсутствии в удаляемой папке статей/внутренних папок алгоритм должен позволять проводить удаление папки из базы знаний.

### 7.2.3 Преобразование разметки статьи для просмотра пользователем

При открытии статьи в режиме просмотра должно автоматически отображаться её отформатированное содержание, полученное путём преобразования исходной Markdown-разметки статьи в HTML.

- Для указания стиля заголовка перед текстом необходимо добавить символ "#" (например, # Раздел 1) - для пользователя текст отобразится как крупный, структурно выделенный заголовок статьи. Уровень заголовка определяется количеством символа "#" : чем больше количество данного символа, тем ниже иерархический уровень заголовка;
- Для выделения выбранного фрагмента текста полужирным начертанием текст обрамляется двойными звёздочками (например, **ключевой термин**);
- Для выделения выбранного фрагмента текста курсивным начертанием текст обрамляется одиночными звёздочками (например, *ключевой термин*);
- Для выделения выбранного фрагмента текста подчеркнутым начертанием текст обрамляется двойными плюсами (например, ++ключевой термин++);
- Для оформления текста в виде маркированного списка перед каждой строкой списка ставится тире (например, - пункт списка);
- Для оформления текста в виде маркированного списка перед каждой строкой списка ставится номер пункта с точкой (например, 1. первый пункт списка);
- Для переноса текста на новую строку необходимо поставить дополнительный отступ, используя клавишу ввода (Enter);
- Добавление вложения в виде ссылки возможно с помощью соответствующей кнопки прикрепления ссылки ;
- Допустимым является загрузка файлов в форматах JPG/JPEG, PNG, GIF, SVG, PDF и DOCX, размер которых не превышает 30 МБ.

### 7.2.4 Поиск статьи по текстовому запросу

При вводе текста в поисковую строку должны отображаться все статьи , которые содержат в себе введенное в поле поиска значение. Поиск осуществляется по полному совпадению введенного значения, без учета регистра.

### 7.2.5 Просмотр папок и статей в зависимости от роли пользователя

При переходе в раздел базы знаний пользователь видит только те папки и статьи, доступ к которым разрешён его роли и правам доступа. Отображение содержимого базы знаний динамически формируется и изменяется в соответствии с назначенной пользователю ролью, а также с учётом прав и условий видимости, указанных для каждой папки и статьи.

# 8 Функции системы

## 8.1 Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах Системы в части предоставления сведений базы знаний, в том числе руководства пользователя, руководства администратора (с учетом ролевой модели) с возможност ью просмотра рисунков, текста, а также поиска по статьям

Необходимо реализовать экранную форму базы знаний для пользователя. Экранная форма необходима для того, чтобы пользователь мог ознакомиться с подробной информацией по работе в том или ином разделе Системы. Информация должна быть представлена структурированно по модулям.

В рамках создания экранной формы должны быть реализованы следующие функции:

- поиск статей;
- просмотр статьи с отображением рисунков и текста.

Внешний вид формы базы знаний для пользователя приведен на макетах UI.3.1 - UI.6.1 настоящей бизнес-постановки.

При реализации функции "Поиск" должен быть реализован алгоритм, описанный в пп. 7.2.4 настоящей бизнес-постановки.

## 8.2 Создание функции экспорта в фай л или на печать без обработки данных, хранящихся во внутренних файлах Системы, руководства пользователя и руководства администратора

Функция должна предоставлять пользователям возможность скачивания вложенных в статью файлов в том формате, в котором они были загружены в статью пользователем с ролью "Администратор". Это необходимо для сохранения оригинального содержания, авторского форматирования и структуры документа, а также для гарантии корректного открытия и использования файлов без риска повреждения данных из-за автоматического преобразования.

Необходимо реализовать функцию, которая должна автоматически определять видимость каждой папки и статьи для текущего пользователя на основе его роли и назначенных прав. Видимость записи базы знаний определяется правами и условиями доступа, заданными при создании или редактировании. На выходе функция предоставляет индивидуальную для роли пользователя структуру базы знаний - дерево, содержащее исключительно те папки и статьи, для которых успешно пройдена проверка доступа.

При реализации функции должны быть реализованы алгоритмы, описанные в пп. 7.2.1 и 7.2.5 настоящей бизнес постановки.

## 8.5 Создание функции ввода информации пользователем через интерфейс Системы для создания, редактирования, удаления и иной работы по управлению статьями (загрузке руководства пользователя и руководства администратора)

Необходимо реализовать экранные формы администратора Подсистемы для ввода значений при работе со следующими функциями:
