### A.4 Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Целью выполнения работ, необходимых для реализации функционального требования, является обеспечение соответствия формируемых отчетных документов (ЧТЗ) требованиям шаблона за счет введения контроля полноты описаний функций и наличия бизнес-постановок. Доработки затрагивают компоненты модуля «НСИ»:

1. Модальное окно «Изменение ФОИ из НМЦК»;
2. Экранная форма «Перечень ФОИ из НМЦК по этапу».

### 7.1. Основной сценарий работы с ФОИ из НМЦК

- Пользователь в боковом меню выбирает раздел "Работы".
- Система отображает экранную форму "Работы" с таблицей доступных работ.

UI 2.0 Карточка "Работы", вкладка "ФОИ из НМЦК"

Шаг 3. Открытие карточки работы

- Пользователь находит нужную работу в таблице и двойным кликом открывает ее.
- Система отображает карточку работы с несколькими вкладками.

Шаг 4. Работа с ФОИ из НМЦК (для типа работы "Создание/развитие")

- Пользователь переходит на вкладку "ФОИ из НМЦК".
- Пользователь двойным кликом открывает сущность "НМЦК".
- Система отображает экранную форму "Перечень ФОИ из НМЦК по этапу".

UI 3.0 Экранная форма "Перечень ФОИ из НМЦК по этапу" (as-is)

Шаг 5. Копирование ФОИ из НМЦК

- Пользователь нажимает кнопку "Копировать из НМЦК".
- Система копирует значения из раздела "НМЦК фиксированная стоимость" (Редактор ГК).
- Система отображает уведомление : "ФОИ из НМЦК добавлены"
- Система отображает второе уведомление : "Скорректируйте "Краткое описание" ФОИ. Минимальный объем - 300 символов."
- Уведомления остаются на экране до ручного закрытия пользователем.

UI 3.1 Экранная форма "Перечень ФОИ из НМЦК по этапу" (to-be)

Шаг 6. Редактирование ФОИ

- Пользователь находит в таблице функцию, требующую корректировки описания.
- Пользователь двойным кликом открывает функцию для редактирования.
- Система отображает модальное окно "Изменение ФОИ из НМЦК".

UI 4.0 Модальное окно "Изменение ФОИ из НМЦК" (as-is)

UI 4.2 Модальное окно "Изменение ФОИ из НМЦК" в части отображения ошибки при невыполнении условия в 300 символов(to-be)

Шаг 7. Заполнение "Краткого описания"

- Пользователь вводит текст в поле "Краткое описание".
- Пользователь нажимает кнопку "Сохранить/Применить".
- Система проверяет длину введенного текста: Если длина меньше 300 символов : система блокирует сохранение, подсвечивает поле красной рамкой и отображает текст ошибки: "Описание должно содержать не менее 300 символов". Если длина 300 символов или больше : система сохраняет изменения и закрывает модальное окно.

Шаг 8. Прикрепление бизнес-постановок

- Пользователь переходит на вкладку "Бизнес-постановки" в карточке работы.
- Пользователь нажимает кнопку "Добавить бизнес-постановку".
- Пользователь загружает необходимые файлы.
- Пользователь возвращается на вкладку "ФОИ из НМЦК".

Шаг 9. Сохранение изменений

- Пользователь нажимает кнопку "Сохранить/Применить" на экранной форме "Перечень ФОИ из НМЦК по этапу".
- Система проводит проверку: Соответствие объема "Краткого описания" у всех функций (>300 символов) Прикреплённых Бизнес постановок >0?
- При выявлении нарушений система отображает соответствующие уведомления: "Необходимо приложить бизнес-постановки" "Предупреждение"" Ошибка сохранения ! Поле "Краткое описание" должно содержать не менее 300 символов"
- Сохранение блокируется до устранения всех замечаний.

### 7.2.1. Алгоритм проверки наличия 300 символов в поле "Краткое описание" для каждой функции

### Алгоритм реализует клиентскую и серверную валидацию поля "Краткое описание" на соответствие минимальному требованию в 300 символов. Логика проверки идентична алгоритму, реализованному в модуле "Расчеты по заявкам"

2. ### 7.2.2. Алгоритм проверки наличия бизнес-постановок

2. Проверка наличия бизнес-постановок : Система проверяет наличие Бизнес постановки в расчете Есть ли хотя бы одна прикрепленная Бизнес постановка Сохраняет Данные Если <1 Бизнес постановки в расчете Блокирует сохранение данных

1. Модальное окно «Изменение ФОИ из НМЦК»;
2. Экранная форма «Перечень ФОИ из НМЦК по этапу».

### 7.2.1. Алгоритм проверки наличия 300 символов в поле "Краткое описание" для каждой функции

### Алгоритм реализует клиентскую и серверную валидацию поля "Краткое описание" на соответствие минимальному требованию в 300 символов. Логика проверки идентична алгоритму, реализованному в модуле "Расчеты по заявкам"

1. Инициализация проверки : При открытии модального окна "Изменение ФОИ из НМЦК" система инициализирует валидатор для поля "Краткое описание".
2. Валидация при попытке сохранения : При нажатии кнопки "Сохранить/Применить" система последовательно выполняет: Проверку на пустое значение поля (если поле пустое - ошибка) Проверку на соответствие минимальной длине (300 символов) При невыполнении любого условия: Подсвечивает поле красной рамкой Отображает текст ошибки под полем: "Описание должно содержать не менее 300 символов" Блокирует сохранение

### 7.2.2. Алгоритм проверки наличия бизнес-постановок

Алгоритм реализует комплексную проверку наличия прикрепленных бизнес постановок. Логика идентична алгоритму проверки бизнес-постановок в модуле "Расчеты по заявкам"

1. Сбор данных для валидации : При нажатии кнопки "Сохранить/Применить" на форме "Перечень ФОИ из НМЦК по этапу" система собирает: Список всех функций, скопированных из НМЦК Список прикрепленных бизнес-постановок для текущей работы
2. Проверка наличия бизнес-постановок : Система проверяет наличие Бизнес постановки в расчете Есть ли хотя бы одна прикрепленная Бизнес постановка Сохраняет Данные Если <1 Бизнес постановки в расчете Блокирует сохранение данных

# 8. Функции системы

### 8.1. Развитие функции проверки (контроля), которые не приводят к изменению данных в части реализации контроля минимальной длины текста (300 символов) и обязательности заполнения поля "Краткое описание" на модальном окне "Изменение ФОИ из НМЦК"

Обеспечение соответствия формируемых описаний ФОИ требованиям шаблона ЧТЗ путем реализации комплексной валидации данных перед сохранением.

- Функция реализует механизм контроля минимального объема текста в поле "Краткое описание" при редактировании ФОИ из НМЦК.
- Система устанавливает признак "Обязательно" для поля "Краткое описание" в модальном окне "Изменение ФОИ из НМЦК", что визуально индицируется звездочкой (*) рядом с наименованием поля.
- При нажатии на кнопку "Скачать ЧТЗ" в ЧТЗ ИЛИ При нажатии на кнопку "Добавить" в карточке "Работа" вкладка "Шаблоны документов" запускается проверки: Проверка на заполненность поля (отсутствие пустого значения) Проверка на соответствие минимальной длине (300 символов) Проверка наличия прикрепленной бизнес-постановки
- При невыполнении любого из условий система следует сценарию функции 8.2.

### 8.2. Развитие функции уведомления пользователя в части реализации системы всплывающих сообщений на ЭФ "Перечень ФОИ из НМЦК по этапу" для контроля наличия бизнес-постановок и проверки объема "Краткого описания"

Обеспечение своевременного информирования пользователя о требованиях к данным ФОИ из НМЦК и текущем статусе их соответствия регламенту формирования ЧТЗ.

- Функция реализует систему контекстных уведомлений, информирующих пользователя о необходимости дополнения данных для корректного формирования ЧТЗ.
- После выполнения операции копирования ФОИ из НМЦК система автоматически генерирует модальное уведомление с текстом: "ФОИ из НМЦК добавлены.".
- Уведомление является модальным (не закрывается автоматически) и остается на экране до ручного закрытия пользователем (нажатие на кнопку "Закрыть" или иконку "крестик").
- Если хотя бы одна из ФОИ не прошла проверку на кол-во символов в поле "Краткое описание"(кол-во символов < 300), то система отображает пользователю Ошибку с текстом: "Описание ФОИ из НМЦК не соответствуют требованию по минимальному количеству в 300 символов. Перейдите на вкладку "ФОИ из НМЦК" и скорректируйте краткое описание ФОИ".
- Если не отсутствует приложенная бизнес-постановка, то система отображает пользователю Ошибку с текстом: " Необходимо приложить бизнес-постановки ".
- Если не выполнены оба условия не пройдена проверка на кол-во символов в поле "Краткое описание" и отсутствует бизнес-постановка, то отображаем оба уведомления друг под другом.

### 8.3. Развитие функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для ЭФ "Перечень ФОИ из НМЦК"

Добавить на форме "Перечень ФОИ из НМЦК" в реестр "ФОИ из НМЦК" столбец "Описание проверено". Поле с логическим типом данных, в строках отображаются чек-боксы. Логика отображения чек-боксов: - Активирован - если кол-во символов в поле "Краткое описание" по строке >=300 - Деактивирован - если кол-во символов в поле "Краткое описание" по строке <300 При возможности добавить на столбец подсказку со следующим текстом: "Если чек-бокс активирован, то краткое описание составлено корректно. Если чек-бокс не активен, то дополните поле "Краткое описание" до минимального значения в 300 символов."
