## 7.2 Описание алгоритмов

7.2.1 Алгоритм расчета значения в поле "Планируется к оплате" (в Этапе ГК)

Для расчета необходимы следующие параметры:

- " Плановая стоимость работ по этапу " (CostWorkStage) - планируемая или фиксированная стоимость работ на этап
- "Сумма согласованная" (TotalApprovedSum) - согласованная сумма в РСЗ
- "Фактическая стоимость работ по этапу" - стоимость работ для фиксированных Этапов ГК

"Планируется к оплате" = Сумма по полю "Плановая стоимость работ по этапу" для всех Этапов в рамках ГК - Сумма по полю "Фактическая стоимость работ по этапу" для всех Этапов в рамках ГК

Отображает Остаток средств по ГК. От плановой стоимости отнимаем фактическую.

7.2.2 Алгоритм расчета значения в поле "Дней до завершения ГК"

Необходимы значения следующих полей:

- "Длительность исполнения ГК контрагентом (кал.дн)" (DaysToLeftGKEndDate) - кол-во дней исполнения ГК с момента заключения
- "Дата начала" (DateStart) - дата окончания этапа ГК
- "Текущая дата" - дата на текущий момент

"Дней до завершения ГК" = ("Дата начала" + "Длительность исполнения ГК контрагентом (кал.дн)") - "Текущая дата"

Отображение значения "Дней до завершения этапа ГК":

- Если значение "Дней до завершения ГК" < "0", то необходимо подсвечивать поле красным цветом и отображать модуль полученного значения
- Если значение "Дней до завершения ГК" => "0", то отображаем значение без обработок

7.2.3 Алгоритм расчета значения в поле "Дней до завершения этапа ГК"

Необходимы значения следующих полей:

- "Дата окончания Факт" - дата окончания этапа ГК
- "Текущая дата" - дата на текущий момент

"Дней до завершения этапа ГК" = "Дата окончания Факт" - "Текущая дата"

Отображение значения "Дней до завершения этапа ГК":

- Если значение "Дней до завершения этапа ГК" < "0", то необходимо подсвечивать поле красным цветом и отображать модуль полученного значения
- Если значение "Дней до завершения этапа ГК" => "0", то отображаем значение без обработок

7.2.4 Алгоритм расчета значения в поле "Процент готовности документов"

Необходимо рассчитывать готовность отчетных документов в рамках Работы/Заявки.

Готовность ОД в Работе/Заявке = округлить до целого значения ((количество ОД в работе (закупке) в статусе "Подписан" /количество ОД в работе (закупке), статус которых != "Отклонен") * 100%)

Отображение значения:

- Если "Плановая дата окончания Этапа" < "Текущей даты" И "Готовность ОД в Работе/Заявке" != 100%, то система подсвечивает поле "Красным" цветом
- Иначе система подсвечивает поле "Зеленым" цветом

7.2.5 Алгоритм отображения записей в реестре "Обзор текущих показателей"

Система проводит 2 проверки: 1. Проверка на принадлежность ГК к Системе:

Необходимо отображать только те ГК, которые привязаны к Системе

7.3. Проверка на текущую дату в этапе ГК

Необходимы значения следующих полей:

- "Дата начала Факт" - дата начала этапа ГК
- "Дата окончания Факт" - дата окончания этапа ГК
- "Текущая дата" - дата на текущий момент

Принцип отображения записей в реестре:

1. Если "Дата начала Факт"="NULL" (отсутствует) Этап НЕ считается в работе (невозможно определить, когда этап стартовал) - НЕОТОБРАЖАЕМ
2. Если "Дата окончания Факт"="NULL" (отсутствует) Активен, если "Текущая дата" >= "Дата начала Факт" (этап уже начался) - ОТОБРАЖАЕМ Не активен, если "Текущая дата" < "Дата начала Факт" - НЕОТОБРАЖАЕМ
3. Если "Дата начала Факт" > "Дата окончания Факт" Этап НЕ считается в работе при любых обстоятельствах - НЕОТОБРАЖАЕМ
4. Если "Дата начала Факт" <= "Текущая дата" <= "Дата окончания Факт" (текущая дата находится между датой начала и датой окончания) Этап Активен - ОТОБРАЖАЕМ
5. Если "Текущая дата" < "Дата начала Факт" (этап не начался) ИЛИ "Текущая дата" > "Дата окончания Факт" (уже завершён) Этап Не активен - НЕОТОБРАЖАЕМ

## 7.2 Описание алгоритмов

7.2.1 Алгоритм расчета значения в поле "Планируется к оплате" (в Этапе ГК)

Для расчета необходимы следующие параметры:

- " Плановая стоимость работ по этапу " (CostWorkStage) - планируемая или фиксированная стоимость работ на этап
- "Сумма согласованная" (TotalApprovedSum) - согласованная сумма в РСЗ
- "Фактическая стоимость работ по этапу" - стоимость работ для фиксированных Этапов ГК

"Планируется к оплате" = Сумма по полю "Плановая стоимость работ по этапу" для всех Этапов в рамках ГК - Сумма по полю "Фактическая стоимость работ по этапу" для всех Этапов в рамках ГК

Отображает Остаток средств по ГК. От плановой стоимости отнимаем фактическую.

7.2.2 Алгоритм расчета значения в поле "Дней до завершения ГК"

Необходимы значения следующих полей:

- "Длительность исполнения ГК контрагентом (кал.дн)" (DaysToLeftGKEndDate) - кол-во дней исполнения ГК с момента заключения
- "Дата начала" (DateStart) - дата окончания этапа ГК
- "Текущая дата" - дата на текущий момент

"Дней до завершения ГК" = ("Дата начала" + "Длительность исполнения ГК контрагентом (кал.дн)") - "Текущая дата"

Отображение значения "Дней до завершения этапа ГК":

- Если значение "Дней до завершения ГК" < "0", то необходимо подсвечивать поле красным цветом и отображать модуль полученного значения
- Если значение "Дней до завершения ГК" => "0", то отображаем значение без обработок

7.2.3 Алгоритм расчета значения в поле "Дней до завершения этапа ГК"

Необходимы значения следующих полей:

- "Дата окончания Факт" - дата окончания этапа ГК
- "Текущая дата" - дата на текущий момент

"Дней до завершения этапа ГК" = "Дата окончания Факт" - "Текущая дата"

Отображение значения "Дней до завершения этапа ГК":

- Если значение "Дней до завершения этапа ГК" < "0", то необходимо подсвечивать поле красным цветом и отображать модуль полученного значения
- Если значение "Дней до завершения этапа ГК" => "0", то отображаем значение без обработок

7.2.4 Алгоритм расчета значения в поле "Процент готовности документов"

Необходимо рассчитывать готовность отчетных документов в рамках Работы/Заявки.

Готовность ОД в Работе/Заявке = округлить до целого значения ((количество ОД в работе (закупке) в статусе "Подписан" /количество ОД в работе (закупке), статус которых != "Отклонен") * 100%)

Отображение значения:

- Если "Плановая дата окончания Этапа" < "Текущей даты" И "Готовность ОД в Работе/Заявке" != 100%, то система подсвечивает поле "Красным" цветом
- Иначе система подсвечивает поле "Зеленым" цветом

7.2.5 Алгоритм отображения записей в реестре "Обзор текущих показателей"

Система проводит 2 проверки: 1. Проверка на принадлежность ГК к Системе:

Необходимо отображать только те ГК, которые привязаны к Системе

7.3. Проверка на текущую дату в этапе ГК

Необходимы значения следующих полей:

- "Дата начала Факт" - дата начала этапа ГК
- "Дата окончания Факт" - дата окончания этапа ГК
- "Текущая дата" - дата на текущий момент

Принцип отображения записей в реестре:

1. Если "Дата начала Факт"="NULL" (отсутствует) Этап НЕ считается в работе (невозможно определить, когда этап стартовал) - НЕОТОБРАЖАЕМ
2. Если "Дата окончания Факт"="NULL" (отсутствует) Активен, если "Текущая дата" >= "Дата начала Факт" (этап уже начался) - ОТОБРАЖАЕМ Не активен, если "Текущая дата" < "Дата начала Факт" - НЕОТОБРАЖАЕМ
3. Если "Дата начала Факт" > "Дата окончания Факт" Этап НЕ считается в работе при любых обстоятельствах - НЕОТОБРАЖАЕМ
4. Если "Дата начала Факт" <= "Текущая дата" <= "Дата окончания Факт" (текущая дата находится между датой начала и датой окончания) Этап Активен - ОТОБРАЖАЕМ
5. Если "Текущая дата" < "Дата начала Факт" (этап не начался) ИЛИ "Текущая дата" > "Дата окончания Факт" (уже завершён) Этап Не активен - НЕОТОБРАЖАЕМ
