### A.2 Подсистемы

| № варианта | Название варианта | Описание |
|---|---|---|
| 1 | Получение новостей с Телеграм-канала | Система подключается к указанному Телеграм-каналу с использованием API Телеграм и получает последние сообщения. |

| 4 | Переход к полному сообщению | При нажатии на новость в виджете пользователь может быть перенаправлен в Телеграм для подробного просмотра. |

### A.3 Компоненты (объекты доработки)

1. Пользователь открывает домашнюю страницу приложения.
2. На странице отображается виджет с последними новостями, полученными из Телеграм-канала.
3. Виджет содержит краткую информацию (например, заголовок новости и несколько первых строк текста).
4. Пользователь может прокрутить виджет, чтобы увидеть другие новости, если их больше, чем показывается в текущем экране.
5. Пользователь может кликнуть на одну из новостей, чтобы перейти в подробное сообщение в Телеграм-канал.
6. Новость обновляется автоматически через установленный промежуток времени (например, каждые 5-10 минут).

Сценарий 2: Создание и публикация новости в Телеграм канал для администратора

1. Пользователь открывает домашнюю страницу приложения.
2. На странице отображается виджет с последними новостями, полученными из Телеграм-канала.
3. Он вводит текст новости в поле ввода.
4. При необходимости, прикрепляет файлы (фото (jpeg, png, svg и т.д.), видео, документы (docx, doc, excel и т.д.)).
5. Пользователь нажимает кнопку "Отправить".
6. Приложение отправляет новость в Телеграм канал через API.
7. Если новость успешно отправлена, пользователь получает подтверждение.
8. Если произошла ошибка (например, нет прав на публикацию или ошибка подключения), приложение отображает сообщение об ошибке.

### A.4 Цель и концепция решения

1. Интеграция с Телеграм API – система должна уметь подключаться к выбранному Телеграм-каналу с помощью API и извлекать последние сообщения (новости).
2. Автоматическое обновление данных – данные о новостях должны обновляться через установленный интервал времени без вмешательства пользователя.
3. Отображение новостей в виджете – новости должны выводиться в виде компактных карточек с основными сведениями (например, заголовок, краткое содержание).
4. Переход по ссылке – при нажатии на новость пользователь должен быть перенаправлен на полную версию сообщения, используя соответствующую ссылку в Телеграм.
5. Настройки фильтров для администратора – администратор должен иметь возможность настроить, какие новости или темы отображать в виджете, а какие игнорировать.
6. Обработка ошибок – система должна адекватно реагировать на возможные ошибки (например, отсутствие подключения к каналу или проблемы с интернет-соединением).
7. Интерфейс для настройки виджета – должен быть доступен интерфейс для настройки внешнего вида виджета и управления частотой обновления.
8. Динамическая загрузка – виджет должен поддерживать динамическую загрузку новостей при прокрутке, если новостей больше, чем помещается на экране.
9. Интерфейс для создания и отправки новостей Администратора: Администратор может ввести текст новости. Возможность прикрепления файлов (изображения, видео, документы). Кнопка отправки для публикации новости в Телеграм канал. Валидация прав пользователя на публикацию в канале.
10. Обработка ошибок при отправке новостей: Проверка наличия прав пользователя на отправку сообщений в канал. Обработка ошибок при отправке (например, ошибка API, проблемы с сетью). Сообщение пользователю об успешной или неудачной отправке новости.
11. Уведомления о статусе публикации: Уведомление пользователю об успешной публикации. Уведомление в случае ошибки (например, недостаточно прав для публикации или ошибка при подключении к API).
12. Проверка доступности канала и прав пользователя: Система должна проверять, имеет ли пользователь права для создания и отправки сообщений в канал (только администратор может публиковать новости). Обработка ситуаций, когда у пользователя нет прав для публикации новостей в Телеграм канале.
