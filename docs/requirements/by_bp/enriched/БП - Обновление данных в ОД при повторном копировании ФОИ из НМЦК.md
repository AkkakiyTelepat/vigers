4.1. Цели и обоснование необходимости развития

1. Корректное добавление ФОИ при соответствии обязательным условиям.

4.2. Описание проблем и решения

Реализация работ позволяет решить проблему отображения некорректного состава ФОИ в документах. Проблема затрагивает Пользователей, формирующих и актуализирующих расчёты. В результате это приводит к дублированию ФОИ и содержанию устаревших данных в документации. Для устранения проблемы предлагается комплексная автоматизация: проверка на дубли, лишние или недостающие ФОИ в расчетах, синхронизация состава, наследование данных в шаблоны с учётом статусов, блокирующие контроли и управляемое заполнение разделов.

## 7.2. [Описание алгоритмов]

#### 7.2.1. Алгоритм работы механизма проверки на дубли при обновлении функций из НМЦК

При нажатии пользователем кнопки «Копировать из НМЦК» на вкладке «Перечень ФОИ из НМЦК по этапу» инициируется процедура выявления дублирующих ФОИ.

1. Из текущего расчёта извлекается перечень ФОИ.
2. Актуальные ФОИ в НМЦК для этапа ГК загружаются в Перечень ФОИ из НМЦК по этапу.
3. Выполняется полное сопоставление: ФОИ считается дублирующей, если одновременно совпадают значения трёх полей – этап , номер пункта в ТЗ , наименование ФОИ .
4. Результат сравнения сохраняется в сервисе.

#### 7.2.2. Алгоритм добавления/удаления функций в расчёте при копировании из НМЦК

После завершения проверки на дубли  при копировании из НМЦК (п. 8.1) выполняется проверка скопированных ФОИ и в зависимости от результатов выполняются следующие действия:

1. В случае полного совпадения ФОИ в НМЦК и в расчете:

- Добавление в расчет пропускается;
- Существующие в расчете ФОИ сохраняются без изменений.

2. В случае имеющихся отличий:

- Если в расчёте присутствуют ФОИ, отсутствующие в НМЦК (то есть в расчёте больше функций), ФОИ полностью удаляются из расчёта и копируются из НМЦК заново.
- Если в НМЦК присутствуют ФОИ, отсутствующие в расчёте (в НМЦК больше функций), они добавляются в расчёт как новые записи, а те ФОИ, что уже имеются в расчете - не удаляются. При этом для каждой добавляемой ФОИ выполняется проверка согласно п. 5 (описание ≥ 300 символов, наличие бизнес-постановки).

#### 7.2.3. Алгоритм работы механизма обновления данных в ПЗ/ПМИ

1. Сервис фиксирует изменение количества ФОИ во вкладке НМЦК фиксированная стоимость.
2. В случае изменения количества ФОИ во вкладке НМЦК фиксированная стоимость, определяется перечень шаблонов документов, привязанных к работе: ПЗ , ПМИ во вкладке «Шаблоны документов».
3. Для каждого документа проверяется его текущий статус, и, е сли статус:

- «В работе» – выполняется полная перезапись перечня ФОИ внутри документа. Новый состав ФОИ замещает старый.
- «Готово» – документ не изменяется , его содержимое остается прежним.

#### 7.2.4. Алгоритм выведения сообщения, уведомляющего об обновлении функций внутри расчёта

По завершении копирования из НМЦК и по необходимости внесения сервисом изменений согласно п. 2,  в случае, если количество ФОИ в расчёте изменилось, все Пользователи, работающие с этим документом: Аналитик ДИТ, Аналитик Качества, Аналитик Подрядчика, РП ДИТ, Администратор - информируется специальным сообщением:

«Перечень ФОИ был изменен. Требуется обновление страницы для просмотра связанных документов (ПЗ, ПМИ) в статусе „В работе“ выполнено автоматическое обновление. Проверьте актуальность данных в документах.»

#### 7.2.5. Алгоритм доработанной логики проверок при добавлении/удалении ФОИ из расчёта

При операциях добавления новых ФОИ и бизнес-постановок осуществляются следующие обязательные проверки:

1 . Проверка краткого описания

Поле «Краткое описание» должно содержать от 300 символов . Если условие не выполнено, отображается соответствующее уведомление:

2. Проверка бизнес-постановки

Должны быть загружены бизнес-постановки во вкладке «Бизнес-постановки». В случае их отсутствия копирование ФОИ из НМЦК допускается,  выводится соответствующее уведомление.

3. Поведение при копировании из НМЦК

Если новые ФОИ не проходят проверки, они не добавляются в расчёт. Пользователю выводится соответствующее уведомление.

### A.10 Функции системы (п.8, дословно)

В целях реализации бизнес-постановки по обновлению данных в ОД при повторном копировании ФОИ из НМЦК должны быть разработаны следующие функции:

8.1 Развитие функции проверки (контроля) в части создания механизма проверки на дубли при обновлении функций из НМЦК

Для реализации функции необходимо учесть, что при клике на кнопку "Копировать из НМЦК" запускается алгоритм проверки функций в расчете и функций в НМЦК по полному совпадению по критериям:

- этап
- номер пункта в ТЗ
- наименование фои из нмцк/тз

Выявленные актуальные ФОИ из НМЦК для выбранного этапа ГК загружаются в реестр на вкладке «ФОИ из НМЦК» уже согласно функции 8.2.

8.2 Развитие функции проверки (контроля) в части создания алгоритма добавления/удаления функций в расчете при копировании из НМЦК

| Логика | Действия |
|---|---|
| Полное совпадение ФОИ в НМЦК и в расчете | Пропускаем добавление в расчет ФОИ, что уже были в расчете - не трогаем |
| Имеются отличия  ФОИ в НМЦК и в расчете | Если в расчете больше ФОИ, чем в НМЦК - то удаляются ФОИ полностью, ФОИ заново копируются из НМЦК Если в НМЦК больше ФОИ, чем в расчете - то добавляются в расчет новые ФОИ, старые в случае совпадения по пунктам, описанным в Функции 1, не изменяются |

8.3 Развитие алгоритма наследования данных в ПЗ/ПМИ в случае их обновления

Для реализации функции необходимо учесть, что при изменении количества ФОИ во вкладке НМЦК фиксированная стоимость необходимо перезаписывать ФОИ в ПЗ/ПМИ. Должна учитываться логика, при которой:

1. В случае, если документ в статусе "В работе" – выполняется полная перезапись перечня ФОИ внутри документа. Новый состав ФОИ замещает старый.
2. Если документ в статусе "Готово" - документ не изменяется .

8.4 Развитие функции уведомления пользователя в части реализации системы всплывающих сообщений по обновлению функций внутри расчета

Для реализации функции необходимо учесть, что в случае, изменения количества ФОИ во вкладке НМЦК фиксированная стоимость , необходимо информировать Пользователя с помощью вывода уведомления:

В случае, когда перечень ФОИ был изменён Пользователем в реестре Государственных контрактов, связанные с расчётом шаблоны документов  (ПЗ, ПМИ), находившиеся в статусе «В работе», были автоматически обновлены в соответствии с новым перечнем. П ользователю необходимо обновить страницу и проверить актуальность данных в документах.

8.5 Развитие функции проверки (контроля), которые не приводят к изменению данных в части реализации доработки логики проверок при добавлении/удалении ФОИ из расчета

Для реализации функции необходимо учесть, что при добавлении новых ФОИ и бизнес-постановок должны осуществляться проверка наличия достаточной заполненности краткого описания. Оно должно содержать не менее 300 символов. Также во вкладке «Бизнес-постановки» должны быть загружены бизнес-постановки. При отсутствии БП - выводится соответствующее уведомление.

При инициации добавления новых ФОИ Сервис последовательно выполняет обязательные проверки для каждой добавляемой ФОИ:

1. Проверка краткого описания

- Из карточки добавляемой ФОИ извлекается значение поля «Краткое описание».
- Если поле не заполнено или количество символов в нём составляет менее 300 , добавление выводится соответствующее уведомление: «Описание ФОИ должно содержать не менее 300 символов. Пожалуйста, дополните описание». Пользователь возвращается к заполнению краткого описания.

2. Проверка наличия бизнес-постановок

- Если во вкладке «Бизнес-постановки» не были загружены файлы бизнес-постановки: Выводится уведомление: « Для продолжения необходимо загрузить бизнес-постановки. Пожалуйста, приложите файлы во вкладке «Бизнес-постановки » ; Пользователь должен приложить бизнес-постановки и повторно инициировать добавление ФОИ (механизм проверки запустится заново).
- Если бизнес-постановки загружены, проверка считается успешно пройденной.

## 7.2. [Описание алгоритмов]

#### 7.2.1. Алгоритм работы механизма проверки на дубли при обновлении функций из НМЦК

При нажатии пользователем кнопки «Копировать из НМЦК» на вкладке «Перечень ФОИ из НМЦК по этапу» инициируется процедура выявления дублирующих ФОИ.

1. Из текущего расчёта извлекается перечень ФОИ.
2. Актуальные ФОИ в НМЦК для этапа ГК загружаются в Перечень ФОИ из НМЦК по этапу.
3. Выполняется полное сопоставление: ФОИ считается дублирующей, если одновременно совпадают значения трёх полей – этап , номер пункта в ТЗ , наименование ФОИ .
4. Результат сравнения сохраняется в сервисе.

#### 7.2.2. Алгоритм добавления/удаления функций в расчёте при копировании из НМЦК

После завершения проверки на дубли  при копировании из НМЦК (п. 8.1) выполняется проверка скопированных ФОИ и в зависимости от результатов выполняются следующие действия:

1. В случае полного совпадения ФОИ в НМЦК и в расчете:

- Добавление в расчет пропускается;
- Существующие в расчете ФОИ сохраняются без изменений.

2. В случае имеющихся отличий:

- Если в расчёте присутствуют ФОИ, отсутствующие в НМЦК (то есть в расчёте больше функций), ФОИ полностью удаляются из расчёта и копируются из НМЦК заново.
- Если в НМЦК присутствуют ФОИ, отсутствующие в расчёте (в НМЦК больше функций), они добавляются в расчёт как новые записи, а те ФОИ, что уже имеются в расчете - не удаляются. При этом для каждой добавляемой ФОИ выполняется проверка согласно п. 5 (описание ≥ 300 символов, наличие бизнес-постановки).

#### 7.2.3. Алгоритм работы механизма обновления данных в ПЗ/ПМИ

1. Сервис фиксирует изменение количества ФОИ во вкладке НМЦК фиксированная стоимость.
2. В случае изменения количества ФОИ во вкладке НМЦК фиксированная стоимость, определяется перечень шаблонов документов, привязанных к работе: ПЗ , ПМИ во вкладке «Шаблоны документов».
3. Для каждого документа проверяется его текущий статус, и, е сли статус:

- «В работе» – выполняется полная перезапись перечня ФОИ внутри документа. Новый состав ФОИ замещает старый.
- «Готово» – документ не изменяется , его содержимое остается прежним.

#### 7.2.4. Алгоритм выведения сообщения, уведомляющего об обновлении функций внутри расчёта

По завершении копирования из НМЦК и по необходимости внесения сервисом изменений согласно п. 2,  в случае, если количество ФОИ в расчёте изменилось, все Пользователи, работающие с этим документом: Аналитик ДИТ, Аналитик Качества, Аналитик Подрядчика, РП ДИТ, Администратор - информируется специальным сообщением:

«Перечень ФОИ был изменен. Требуется обновление страницы для просмотра связанных документов (ПЗ, ПМИ) в статусе „В работе“ выполнено автоматическое обновление. Проверьте актуальность данных в документах.»

#### 7.2.5. Алгоритм доработанной логики проверок при добавлении/удалении ФОИ из расчёта

При операциях добавления новых ФОИ и бизнес-постановок осуществляются следующие обязательные проверки:

1 . Проверка краткого описания

Поле «Краткое описание» должно содержать от 300 символов . Если условие не выполнено, отображается соответствующее уведомление:

2. Проверка бизнес-постановки

Должны быть загружены бизнес-постановки во вкладке «Бизнес-постановки». В случае их отсутствия копирование ФОИ из НМЦК допускается,  выводится соответствующее уведомление.

3. Поведение при копировании из НМЦК

Если новые ФОИ не проходят проверки, они не добавляются в расчёт. Пользователю выводится соответствующее уведомление.
