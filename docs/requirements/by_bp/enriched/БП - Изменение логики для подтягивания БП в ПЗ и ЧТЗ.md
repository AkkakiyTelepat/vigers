## 7.2. [Описание алгоритмов]

7.1 Развитие алгоритма наследования БП в ЧТЗ для ГК с фиксированной стоимостью

При каждом нажатии кнопки "Сохранить" на ЭФ добавления БП для ГК фиксированной стоимости (рис. 1) алгоритм должен перенести БП в ЭФ формирования ЧТЗ (рис. 3), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ).

Алгоритм переноса БП так же должен корректно срабатывать при нажатии кнопки "Обновить" на ЭФ формирования ЧТЗ (рис. 3).

7.2 Развитие алгоритма наследования БП в ЧТЗ для ГК по заявкам

При изменении статуса РСЗ на статус "Согласовано" , заведенные БП на экранной форме "Итерация" (рис. 2), должны автоматически наследоваться в ЭФ формирования ЧТЗ (рис. 3)

При изменении статуса РСЗ из статуса "Согласовано" в любой другой (например, если РСЗ откатывали через СТП), при каждом последующем нажатии кнопки "Сохранить" на ЭФ "Итерация" (рис. 2) алгоритм должен заново перенести БП в ЭФ формирования ЧТЗ (рис. 3), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ) .

Алгоритм переноса БП так же должен корректно срабатывать при нажатии кнопки "Обновить" на ЭФ формирования ЧТЗ (рис. 3).

7.3 Развитие алгоритма наследования БП в ПЗ для ГК с фиксированной стоимостью

При каждом нажатии кнопки "Сохранить" на ЭФ добавления БП для ГК фиксированной стоимости (рис. 1) алгоритм должен перенести БП в ЭФ формирования ПЗ (рис. 4), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ).

Алгоритм переноса БП так же должен корректно срабатывать при нажатии кнопки "Обновить" на ЭФ формирования ПЗ (рис. 4).

7.4 Развитие алгоритма наследования БП в ПЗ для ГК по заявкам

При изменении статуса РСЗ на статус "Согласовано" , заведенные БП на экранной форме "Итерация" (рис. 2), должны автоматически наследоваться в ЭФ формирования ПЗ (рис. 4)

При изменении статуса РСЗ из статуса "Согласовано" в любой другой, при каждом последующем нажатии кнопки "Сохранить" на ЭФ "Итерация" (рис. 2) алгоритм должен заново перенести БП в ЭФ формирования ПЗ (рис. 4), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ).

## 7.2. [Описание алгоритмов]

7.1 Развитие алгоритма наследования БП в ЧТЗ для ГК с фиксированной стоимостью

При каждом нажатии кнопки "Сохранить" на ЭФ добавления БП для ГК фиксированной стоимости (рис. 1) алгоритм должен перенести БП в ЭФ формирования ЧТЗ (рис. 3), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ).

Алгоритм переноса БП так же должен корректно срабатывать при нажатии кнопки "Обновить" на ЭФ формирования ЧТЗ (рис. 3).

7.2 Развитие алгоритма наследования БП в ЧТЗ для ГК по заявкам

При изменении статуса РСЗ на статус "Согласовано" , заведенные БП на экранной форме "Итерация" (рис. 2), должны автоматически наследоваться в ЭФ формирования ЧТЗ (рис. 3)

При изменении статуса РСЗ из статуса "Согласовано" в любой другой (например, если РСЗ откатывали через СТП), при каждом последующем нажатии кнопки "Сохранить" на ЭФ "Итерация" (рис. 2) алгоритм должен заново перенести БП в ЭФ формирования ЧТЗ (рис. 3), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ) .

Алгоритм переноса БП так же должен корректно срабатывать при нажатии кнопки "Обновить" на ЭФ формирования ЧТЗ (рис. 3).

7.3 Развитие алгоритма наследования БП в ПЗ для ГК с фиксированной стоимостью

При каждом нажатии кнопки "Сохранить" на ЭФ добавления БП для ГК фиксированной стоимости (рис. 1) алгоритм должен перенести БП в ЭФ формирования ПЗ (рис. 4), при этом БП не должны задублироваться с уже перенесенными ранее БП ( работа алгоритма должна быть инкрементной ).

7.4 Развитие алгоритма наследования БП в ПЗ для ГК по заявкам

При изменении статуса РСЗ на статус "Согласовано" , заведенные БП на экранной форме "Итерация" (рис. 2), должны автоматически наследоваться в ЭФ формирования ПЗ (рис. 4)
