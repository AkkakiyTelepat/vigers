### A.4 Цель и концепция решения

## 4.1. Цели и обоснование необходимости развития

Цель работ  снижение нагрузки на операторов службы технической поддержки и сокращение времени освоения сервиса "Калькулятор" пользователями через создание встроенной системы самообслуживания.

Для решения задачи создается раздел "База знаний" с ролевым доступом, где каждый пользователь видит только актуальные для его роли материалы. Внутри раздела реализуются три способа работы с информацией: переход по кнопке на соответствующую страницу в Confluence для онлайн-просмотра, скачивание Word-версии документа для офлайн-работы и просмотр содержимого непосредственно в интерфейсе Калькулятора без переключения на внешние ресурсы.

Для ускорения адаптации новых пользователей создается интерактивная онбординг-презентация по базовому функционалу, уникальная для каждой роли (аналитик ДИТ, аналитик подрядчика, РП ДИТ). Презентация автоматически запускается при первом входе и доступна для повторного прохождения через раздел "База знаний".

Дополнительно в интерфейс встраивается виджет чат-бота ДИТ.Вопрос на базе платформы AutoFAQ с модулем Xplain, который автоматически отвечает на типовые вопросы, используя корпоративную базу знаний MOS.Вики, обеспечивая достоверность ответов не менее 70%.


## 4.2. Описание проблем и решения

1. Неудобный интерфейс текущих инструкций – материалы в Confluence представлены в виде длинных текстов без интерактивных элементов, что затрудняет поиск нужной информации.
2. Отсутствие централизованного инструмента обучения – пользователи вынуждены переключаться между Confluence и чат-ботом в Telegram, что замедляет процесс.
3. Сложность освоения нового функционала – пользователи тратят время на поиск нужных разделов и не получают контекстных подсказок.
4. Рост нагрузки на поддержку – из-за неудобного формата инструкций увеличивается количество повторяющихся запросов.

Решение переносит всю справочную инфраструктуру внутрь Калькулятора: база знаний консолидирует документацию с гибким доступом, интерактивная презентация обучает пользователей основам работы без участия поддержки, чат-бот с AI автоматически обрабатывает типовые запросы, передавая операторам только сложные случаи.

### A.8 Автоматизация бизнес-процессов / варианты использования (п.6)

Бизнес-процесс "Получение технической поддержки"

[BPMN diagram helpdesk powered by viadee ]

Процесс инициируется, когда пользователь авторизуется в сервисе ДИТ.Интеллект. При первом входе в систему автоматически запускается интерактивная онбординг-презентация согласно функции 2.1, уникальная для роли пользователя. Презентация пошагово знакомит с базовым функционалом через контекстные подсказки в соответствии с функциями 2.2 и 2.3, блокируя остальной интерфейс до завершения обучения или пропуска шага по кнопке "Далее".

При выборе подраздела "Интерактивное обучение" система отображает обучающие сценарии, организованные в тематические блоки: "Основные сценарии" (обучение по ролям) и "Новая функциональность" (описание релизов). Каждый блок представлен в двух режимах отображения: карусель для быстрого предпросмотра сценариев с возможностью перелистывания стрелками навигации, и развернутая галерея со всеми сценариями блока. Карточки сценариев визуально различаются по статусу прохождения: не начатые сценарии отображаются белыми карточками с кнопкой "Начать" и прогрессом 0%, сценарии в процессе прохождения - желтыми карточками с кнопкой "Продолжить" и индикатором процента прохождения, завершенные сценарии - зелеными карточками с кнопкой "Завершено" и иконкой повторного прохождения. Пользователь может запустить интересующий сценарий, кликнув по кнопке на карточке в соответствии с функцией 2.7.

Если в Базе знаний ответ не найден или требуется консультация, пользователь открывает виджет чат-бота ДИТ.Вопрос, интегрированный непосредственно в интерфейс Калькулятора, без переключения на внешние ресурсы. Пользователь вводит текстовый вопрос или выбирает готовый сценарий по кнопке в соответствии с функцией 3.2, при необходимости прикрепляя файлы к сообщению согласно функции 3.6.

Запрос автоматически передается в сервис AutoFAQ согласно функции 3.3, где AI-модуль Xplain анализирует вопрос на основе корпоративной базы знаний MOS.Вики. Если модуль может дать достоверный ответ с вероятностью не менее 70%, пользователь моментально получает автоматический ответ в диалоговом окне виджета в соответствии с функцией 3.4, и ошибка решается. Если AI-модуль не может ответить с требуемой достоверностью, запрос автоматически переадресовывается оператору СТП, который отвечает через тот же виджет. При поступлении нового сообщения от оператора на иконке чат-бота отображается счётчик непрочитанных сообщений согласно функции 3.5. ​

### A.9 Пользовательский сценарий и алгоритмы (п.7)

## Пользовательский сценарий работы с виджетом чат-бота "ДИТ.Вопрос" для всех ролей

1. Пользователь авторизуется в сервисе Калькулятор
2. Пользователь работает в системе и у него возникает вопрос или ошибка
3. Пользователь нажимает на иконку чат-бота ДИТ.Вопрос в левой части экрана
4. Открывается диалоговое окно виджета чат-бота
5. Пользователь вводит текстовый вопрос в поле ввода или выбирает готовый сценарий по кнопке: если пользователю необходимо прикрепить файл, то переходим к п.6, если необходимо только отправить текст, то переходим к п.7
6. Пользователь нажимает на кнопку прикрепления файла
7. Пользователь выбирает файл на своем устройстве
8. Файл добавляется к сообщению
9. Пользователь нажимает кнопку "Отправить"
10. Сообщение передается в сервис AutoFAQ
11. Система отображает ответ от AI-модуля Xplain или от оператора СТП в диалоговом окне
12. При поступлении нового сообщения от оператора на иконке чат-бота отображается счётчик непрочитанных сообщений
13. Пользователь просматривает ответ и продолжает работу

## 7.2. [Описание алгоритмов]

### A.10 Функции системы (п.8, дословно)

8.2.1. Создание функции проверки (контроля), которые не приводят к изменению данных для определения первого входа пользователя в систему

При авторизации система проверяет наличие отметки о прохождении базовой онбординг-презентации в профиле пользователя. При отсутствии отметки система запускает базовую интерактивную презентацию. После завершения презентации система устанавливает флаг "обучение пройдено" в профиле пользователя.

8.2.2. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для интерактивной онбординг-презентации с пошаговыми подсказками

Система отображает пошаговые подсказки по базовому функционалу в зависимости от роли пользователя. Каждая подсказка содержит текстовое описание функционала и выделяет активный элемент интерфейса. Подсказки отображаются с затемнением фона и подсветкой целевого элемента.

8.2.3. Создание функции отображения информации с обработкой (изменением) исходных данных, хранимых в системе для навигации по шагам интерактивной презентации

В подсказке отображается кнопка "Далее" для перехода к следующему шагу. При клике система скрывает текущую подсказку и отображает следующую в заданной последовательности. На последнем шаге кнопка "Далее" заменяется на кнопку "Готово". Система фиксирует прогресс прохождения обучения.

8.2.4. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для сценария обучения роли "Аналитик ДИТ"

Для роли "Аналитик ДИТ" система загружает базовый сценарий обучения с подсказками по проверке расчетов и согласованию заявок. Сценарий включает подсказки по функциям проверки расчетов, согласования БП и РСЗ.

8.2.5. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для сценария обучения роли "Аналитик подрядчика"

Для роли "Аналитик подрядчика" система загружает базовый сценарий с подсказками по созданию расчетов и загрузке документов. Сценарий включает подсказки по заполнению формы "Редактор БП", добавлению ФОИ и загрузке файлов.

8.2.6. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для сценария обучения роли "РП ДИТ"

Для роли "РП ДИТ" система загружает базовый сценарий с подсказками по финальному согласованию. Сценарий включает подсказки по проверке и утверждению БП и РСЗ.

8.2.7. Создание функции вызова внешнего сервиса без сохранения данных для запуска интерактивных обучающих сценариев из раздела "Интерактивное обучение"

При выборе обучающего сценария в разделе "Интерактивное обучение" система загружает соответствующую интерактивную презентацию по конкретному бизнес-процессу. Сценарии доступны в зависимости от роли пользователя и охватывают различные бизнес-процессы системы. ​

8.2.8. Создание функции проверки (контроля), которые не приводят к изменению данных для исключения роли "Администратор" из автозапуска обучения

При проверке первого входа система дополнительно проверяет роль пользователя. Если роль "Администратор", автозапуск базовой презентации не выполняется.

8.3.1. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для виджета чат-бота ДИТ.Вопрос

В левом нижнем углу всех страниц Калькулятора отображается иконка чат-бота. При клике по иконке открывается диалоговое окно виджета с историей переписки. В диалоговом окне отображаются готовые сценарии, поле ввода сообщения, кнопки для прикрепления файлов и отправки.

8.3.2. Создание функции ввода информации пользователем через интерфейс системы для отправки сообщений в виджет чат-бота ДИТ.Вопрос

В диалоговом окне чат-бота пользователь вводит текст в поле "Задайте свой вопрос...". При вводе текста активируется кнопка "Отправить". Пользователь может выбрать готовый сценарий из списка кнопок, что автоматически отправляет предустановленный вопрос.

8.3.3. Создание функции передачи информации во внешнюю систему для отправки сообщений в AutoFAQ из виджета чат-бота

При отправке сообщения система формирует запрос к API сервиса AutoFAQ. Передаются параметры: текст сообщения, идентификатор пользователя, контекст сессии. Запрос отправляется асинхронно.

8.3.4. Создание функции получения данных из внешней системы для получения ответов от AutoFAQ в виджет чат-бота

Система получает ответ от AutoFAQ, который генерируется автоматически через Xplain или формируется оператором СТП. Ответ отображается в истории переписки с выравниванием слева и аватаром бота. При получении ответа от оператора система отправляет уведомление пользователю.

8.3.5. Создание функции уведомления пользователя о поступлении новых сообщений в чат-боте ДИТ.Вопрос

При получении нового ответа от оператора СТП, когда виджет закрыт, система отображает уведомление в правом нижнем углу экрана. На иконке чат-бота появляется синий бейдж с числом непрочитанных сообщений. Счётчик обнуляется при открытии диалогового окна чат-бота. Уведомление автоматически исчезает через 5-7 секунд.

8.3.6. Создание функции импорта информации (или файлов) пользователем для прикрепления файлов в чат-боте ДИТ.Вопрос

В диалоговом окне чат-бота отображается иконка скрепки слева от поля ввода. При клике по иконке открывается диалог выбора файла на устройстве пользователя. Система передает файл в AutoFAQ вместе с текстом сообщения.

8.3.7. Создание структуры хранения информации логической группы данных для истории сообщений чат-бота ДИТ.Вопрос

Система сохраняет все сообщения пользователя и ответы от AutoFAQ в базе данных. Для каждого сообщения сохраняются: текст, отправитель, временная метка, статус прочтения. При открытии диалогового окна чат-бота система загружает историю переписки текущего пользователя. История сохраняется между сеансами. ​

# 4. Цель и концепция решения

## 4.1. Цели и обоснование необходимости развития

Цель работ  снижение нагрузки на операторов службы технической поддержки и сокращение времени освоения сервиса "Калькулятор" пользователями через создание встроенной системы самообслуживания.

Для решения задачи создается раздел "База знаний" с ролевым доступом, где каждый пользователь видит только актуальные для его роли материалы. Внутри раздела реализуются три способа работы с информацией: переход по кнопке на соответствующую страницу в Confluence для онлайн-просмотра, скачивание Word-версии документа для офлайн-работы и просмотр содержимого непосредственно в интерфейсе Калькулятора без переключения на внешние ресурсы.

Для ускорения адаптации новых пользователей создается интерактивная онбординг-презентация по базовому функционалу, уникальная для каждой роли (аналитик ДИТ, аналитик подрядчика, РП ДИТ). Презентация автоматически запускается при первом входе и доступна для повторного прохождения через раздел "База знаний".

Дополнительно в интерфейс встраивается виджет чат-бота ДИТ.Вопрос на базе платформы AutoFAQ с модулем Xplain, который автоматически отвечает на типовые вопросы, используя корпоративную базу знаний MOS.Вики, обеспечивая достоверность ответов не менее 70%.

## 4.2. Описание проблем и решения

1. Неудобный интерфейс текущих инструкций – материалы в Confluence представлены в виде длинных текстов без интерактивных элементов, что затрудняет поиск нужной информации.
2. Отсутствие централизованного инструмента обучения – пользователи вынуждены переключаться между Confluence и чат-ботом в Telegram, что замедляет процесс.
3. Сложность освоения нового функционала – пользователи тратят время на поиск нужных разделов и не получают контекстных подсказок.
4. Рост нагрузки на поддержку – из-за неудобного формата инструкций увеличивается количество повторяющихся запросов.

Решение переносит всю справочную инфраструктуру внутрь Калькулятора: база знаний консолидирует документацию с гибким доступом, интерактивная презентация обучает пользователей основам работы без участия поддержки, чат-бот с AI автоматически обрабатывает типовые запросы, передавая операторам только сложные случаи.

# 6. Автоматизация бизнес-процессов

Бизнес-процесс "Получение технической поддержки"

[BPMN diagram helpdesk powered by viadee ]

Процесс инициируется, когда пользователь авторизуется в сервисе ДИТ.Интеллект. При первом входе в систему автоматически запускается интерактивная онбординг-презентация согласно функции 2.1, уникальная для роли пользователя. Презентация пошагово знакомит с базовым функционалом через контекстные подсказки в соответствии с функциями 2.2 и 2.3, блокируя остальной интерфейс до завершения обучения или пропуска шага по кнопке "Далее".

При выборе подраздела "Интерактивное обучение" система отображает обучающие сценарии, организованные в тематические блоки: "Основные сценарии" (обучение по ролям) и "Новая функциональность" (описание релизов). Каждый блок представлен в двух режимах отображения: карусель для быстрого предпросмотра сценариев с возможностью перелистывания стрелками навигации, и развернутая галерея со всеми сценариями блока. Карточки сценариев визуально различаются по статусу прохождения: не начатые сценарии отображаются белыми карточками с кнопкой "Начать" и прогрессом 0%, сценарии в процессе прохождения - желтыми карточками с кнопкой "Продолжить" и индикатором процента прохождения, завершенные сценарии - зелеными карточками с кнопкой "Завершено" и иконкой повторного прохождения. Пользователь может запустить интересующий сценарий, кликнув по кнопке на карточке в соответствии с функцией 2.7.

Если в Базе знаний ответ не найден или требуется консультация, пользователь открывает виджет чат-бота ДИТ.Вопрос, интегрированный непосредственно в интерфейс Калькулятора, без переключения на внешние ресурсы. Пользователь вводит текстовый вопрос или выбирает готовый сценарий по кнопке в соответствии с функцией 3.2, при необходимости прикрепляя файлы к сообщению согласно функции 3.6.

Запрос автоматически передается в сервис AutoFAQ согласно функции 3.3, где AI-модуль Xplain анализирует вопрос на основе корпоративной базы знаний MOS.Вики. Если модуль может дать достоверный ответ с вероятностью не менее 70%, пользователь моментально получает автоматический ответ в диалоговом окне виджета в соответствии с функцией 3.4, и ошибка решается. Если AI-модуль не может ответить с требуемой достоверностью, запрос автоматически переадресовывается оператору СТП, который отвечает через тот же виджет. При поступлении нового сообщения от оператора на иконке чат-бота отображается счётчик непрочитанных сообщений согласно функции 3.5. ​

## Пользовательский сценарий работы с виджетом чат-бота "ДИТ.Вопрос" для всех ролей

1. Пользователь авторизуется в сервисе Калькулятор
2. Пользователь работает в системе и у него возникает вопрос или ошибка
3. Пользователь нажимает на иконку чат-бота ДИТ.Вопрос в левой части экрана
4. Открывается диалоговое окно виджета чат-бота
5. Пользователь вводит текстовый вопрос в поле ввода или выбирает готовый сценарий по кнопке: если пользователю необходимо прикрепить файл, то переходим к п.6, если необходимо только отправить текст, то переходим к п.7
6. Пользователь нажимает на кнопку прикрепления файла
7. Пользователь выбирает файл на своем устройстве
8. Файл добавляется к сообщению
9. Пользователь нажимает кнопку "Отправить"
10. Сообщение передается в сервис AutoFAQ
11. Система отображает ответ от AI-модуля Xplain или от оператора СТП в диалоговом окне
12. При поступлении нового сообщения от оператора на иконке чат-бота отображается счётчик непрочитанных сообщений
13. Пользователь просматривает ответ и продолжает работу

# 8. Функции системы ​

8.2.1. Создание функции проверки (контроля), которые не приводят к изменению данных для определения первого входа пользователя в систему

При авторизации система проверяет наличие отметки о прохождении базовой онбординг-презентации в профиле пользователя. При отсутствии отметки система запускает базовую интерактивную презентацию. После завершения презентации система устанавливает флаг "обучение пройдено" в профиле пользователя.

8.2.2. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для интерактивной онбординг-презентации с пошаговыми подсказками

Система отображает пошаговые подсказки по базовому функционалу в зависимости от роли пользователя. Каждая подсказка содержит текстовое описание функционала и выделяет активный элемент интерфейса. Подсказки отображаются с затемнением фона и подсветкой целевого элемента.

8.2.3. Создание функции отображения информации с обработкой (изменением) исходных данных, хранимых в системе для навигации по шагам интерактивной презентации

В подсказке отображается кнопка "Далее" для перехода к следующему шагу. При клике система скрывает текущую подсказку и отображает следующую в заданной последовательности. На последнем шаге кнопка "Далее" заменяется на кнопку "Готово". Система фиксирует прогресс прохождения обучения.

8.2.4. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для сценария обучения роли "Аналитик ДИТ"

Для роли "Аналитик ДИТ" система загружает базовый сценарий обучения с подсказками по проверке расчетов и согласованию заявок. Сценарий включает подсказки по функциям проверки расчетов, согласования БП и РСЗ.

8.2.5. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для сценария обучения роли "Аналитик подрядчика"

Для роли "Аналитик подрядчика" система загружает базовый сценарий с подсказками по созданию расчетов и загрузке документов. Сценарий включает подсказки по заполнению формы "Редактор БП", добавлению ФОИ и загрузке файлов.

8.2.6. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для сценария обучения роли "РП ДИТ"

Для роли "РП ДИТ" система загружает базовый сценарий с подсказками по финальному согласованию. Сценарий включает подсказки по проверке и утверждению БП и РСЗ.

8.2.7. Создание функции вызова внешнего сервиса без сохранения данных для запуска интерактивных обучающих сценариев из раздела "Интерактивное обучение"

При выборе обучающего сценария в разделе "Интерактивное обучение" система загружает соответствующую интерактивную презентацию по конкретному бизнес-процессу. Сценарии доступны в зависимости от роли пользователя и охватывают различные бизнес-процессы системы. ​

8.2.8. Создание функции проверки (контроля), которые не приводят к изменению данных для исключения роли "Администратор" из автозапуска обучения

При проверке первого входа система дополнительно проверяет роль пользователя. Если роль "Администратор", автозапуск базовой презентации не выполняется.

8.3.1. Создание функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах ИС для виджета чат-бота ДИТ.Вопрос

В левом нижнем углу всех страниц Калькулятора отображается иконка чат-бота. При клике по иконке открывается диалоговое окно виджета с историей переписки. В диалоговом окне отображаются готовые сценарии, поле ввода сообщения, кнопки для прикрепления файлов и отправки.

8.3.2. Создание функции ввода информации пользователем через интерфейс системы для отправки сообщений в виджет чат-бота ДИТ.Вопрос

В диалоговом окне чат-бота пользователь вводит текст в поле "Задайте свой вопрос...". При вводе текста активируется кнопка "Отправить". Пользователь может выбрать готовый сценарий из списка кнопок, что автоматически отправляет предустановленный вопрос.

8.3.3. Создание функции передачи информации во внешнюю систему для отправки сообщений в AutoFAQ из виджета чат-бота

При отправке сообщения система формирует запрос к API сервиса AutoFAQ. Передаются параметры: текст сообщения, идентификатор пользователя, контекст сессии. Запрос отправляется асинхронно.

8.3.4. Создание функции получения данных из внешней системы для получения ответов от AutoFAQ в виджет чат-бота

Система получает ответ от AutoFAQ, который генерируется автоматически через Xplain или формируется оператором СТП. Ответ отображается в истории переписки с выравниванием слева и аватаром бота. При получении ответа от оператора система отправляет уведомление пользователю.

8.3.5. Создание функции уведомления пользователя о поступлении новых сообщений в чат-боте ДИТ.Вопрос

При получении нового ответа от оператора СТП, когда виджет закрыт, система отображает уведомление в правом нижнем углу экрана. На иконке чат-бота появляется синий бейдж с числом непрочитанных сообщений. Счётчик обнуляется при открытии диалогового окна чат-бота. Уведомление автоматически исчезает через 5-7 секунд.

8.3.6. Создание функции импорта информации (или файлов) пользователем для прикрепления файлов в чат-боте ДИТ.Вопрос

В диалоговом окне чат-бота отображается иконка скрепки слева от поля ввода. При клике по иконке открывается диалог выбора файла на устройстве пользователя. Система передает файл в AutoFAQ вместе с текстом сообщения.

8.3.7. Создание структуры хранения информации логической группы данных для истории сообщений чат-бота ДИТ.Вопрос

Система сохраняет все сообщения пользователя и ответы от AutoFAQ в базе данных. Для каждого сообщения сохраняются: текст, отправитель, временная метка, статус прочтения. При открытии диалогового окна чат-бота система загружает историю переписки текущего пользователя. История сохраняется между сеансами. ​
