### A.2 Подсистемы

Сервис "ДИТ.Калькулятор"

### A.3 Компоненты (объекты доработки)

Модуль формирования отчетной документации:

- печатная форма ЧТЗ
- печатная форма ПЗ
- печатная форма ПМИ

### A.4 Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Целью выполнения работ, необходимых для реализации функционального требования, является приведение отображения незаполненных полей в ЭФ Редакторе ЧТЗ/ПЗ/ПМИ и пустых таблиц в выгружаемых документах к единому виду — значению undefined. Доработка затрагивает компонент выгрузки документов, который предназначен для выполнения обеспечения единообразного представления отсутствующих данных во всех типах выгружаемых документов.

4.2. Описание проблем и решения

В документах отсутствующие данные отображаются разными значениями (Null, «Не заполнено», «Отсутствует описание функционального требования» и другими), из-за чего Пользователь не имеет чёткого единого индикатора отсутствия данных. Для устранения проблемы предлагается привести все варианты отображения незаполненных полей к единому виду — undefined, а таблицы без данных к общему формату.

### A.5 Бизнес-цели и автоматизируемые процессы (из таблицы п.5)



Автоматизируемые процессы: Формирование печатных форм документов ЧТЗ, ПЗ, ПМИ с унифицированной подстановкой значений в незаполненные поля и пустые таблицы Схема процесса в нотации BPMN 2.0 (as is – to be) приведена в п. 6 данной постановки.

### A.6 Пользовательские требования (User Stories)

- **УТ:** 1. Пользователь авторизуется в сервисе «Калькулятор». 2. Система отображает боковую панель навигации. Пользователь выбирает пункт «Расчет по методике 3-р» – открывается меню второго уровня. 3. Пользователь в меню второго уровня выбирает «Работы». Система отображает экранную форму «Работы» с перечнем работ, сгруппированных по ГК. 4. Пользователь двойным кликом ЛКМ открывает строку работы. Система отображает экранную форму «Заявка»/ «Работа» 5. Пользователь переходит на вкладку «Шаблоны документов» экранной формы заявки/работы. Система отображает экранную форму «Шаблоны документов». 6. Пользователь выбирает тип документа: ЧТЗ, ПЗ или ПМИ. Система отображает соответствующую экранную форму Редактора (ЧТЗ, ПЗ или ПМИ). 7. Пользователю, в зависим ости от открытого им документа, могут быть доступны следующие кнопки: "Скачать ЧТЗ", "Скачать архив (ЧТЗ + Приложения)", "Скачать ПЗ", "Скачать архив (ПЗ + СП + БП)", "Скачать архив (ПЗ + Приложения)", "Скачать ПМИ (предварительные)". Пользователь нажимает одну из представленных кнопок, запуская процесс скачивания документации. 8. Система получает данные из Калькулятора, проверяет заполненность полей: если значение поля отсутствует (пустое), подставляет в него единое значение «undefined». Для таблиц, не содержащих ни одной заполненной строки, система формирует одну строку данных, во все ячейки которой подставлено значение «undefined». 9. Система формирует и выгружает запрошенный документ или архив с документами.

#### 8.6 Развитие ЭФ «Редактор ПМИ» в части создания строки «undefined» для таблиц без данных

При выгрузке ПМИ Система проверяет наличие таблиц без данных. # 4. Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Целью выполнения работ, необходимых для реализации функционального требования, является приведение отображения незаполненных полей в ЭФ Редакторе ЧТЗ/ПЗ/ПМИ и пустых таблиц в выгружаемых документах к единому виду — значению undefined. Доработка затрагивает компонент выгрузки документов, который предназначен для выполнения обеспечения единообразного представления отсутствующих данных во всех типах выгружаемых документов.

4.2. Описание проблем и решения

В документах отсутствующие данные отображаются разными значениями (Null, «Не заполнено», «Отсутствует описание функционального требования» и другими), из-за чего Пользователь не имеет чёткого единого индикатора отсутствия данных. Для устранения проблемы предлагается привести все варианты отображения незаполненных полей к единому виду — undefined, а таблицы без данных к общему формату.
