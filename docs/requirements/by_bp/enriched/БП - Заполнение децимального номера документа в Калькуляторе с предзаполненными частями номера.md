### A.4 Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Цель - повысить удобство использования сервиса. Исключить лишние шаги по ручному заполнению децимального номера документа для пользователей.

4.2. Описание проблем и решения

На текущий момент пользователю приходится вручную заполнять децимальный номер документа для ЧТЗ, ПЗ, ПМИ. Предлагается автоматизировать процесс заполнения этого поля разделив его на несколько полей, часть их которых будет предзаполнена.

8.6. Создание алгоритма предзаполнения децимального номера для документов ЧТЗ, ПЗ, ПМИ

Необходимо изменить логику заполнения децимального номера (пример расположения номера в печатной форме указан на рисунке 15) для документов ЧТЗ, ПЗ, ПМИ.

Если раньше  децимальный номер заполнялся пользователем вручную в поле "Шифр документа без ЛУ" в экранных формах формирования документов, то теперь необходимо разделить единое поле на 8 различных, часть из которых должны предзаполняться системой автоматически:

- " Код организации разработчика " - поле должно автоматически предзаполняться системой на основе значения, указанного в НСИ в реестре организаций, в карточке организации, в поле "ОГРН" (показано на рисунке 13).
- " Номер ОКВЭД закупки " - поле должно автоматически предзаполняться системой на основе значения, указанного в НСИ в реестре государственных контрактов, в карточке контракта, поле "ОКВЭД закупки" (рисунок 2).
- " Порядковый регистрационный номер системы " - заполняется вручную, предзаполнение отсутствует. Необходимо предусмотреть ФЛК (поле должно состоять из 3-х цифр). Доступный для заполнения диапазон значений - от 001 до 999. Поле обязательно для заполнения.
- " Код документа " - поле должно автоматически предзаполняться системой, для документа с типом ПЗ - всегда указывается значение " П2 ", для документа с типом ПМИ - всегда указывается значение " ПМ ", для документа с типом ЧТЗ - всегда указывается значение " ПТ ".
- " Порядковый номер документа одного наименования " - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Номер редакции документа "  - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Номер части документа "  - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Признак документа, выполненного на машинных носителях "  - заполняется вручную, предзаполнение отсутствует. Необходимо предусмотреть ФЛК (возможно заполнить только символом М ). Поле не обязательно для заполнения.

После заполнения пользователем всех полей, алгоритм должен "соединить" значения, указанные в полях в единый децимальный номер и отобразить его в печатных формах документа (рисунок 15).

Формат получившегося номера: A.B.C.D.E.F-G.М , где А - " Код организации разработчика ", B - " Номер ОКВЭД закупки ", C - " Порядковый регистрационный номер системы " , D - " Код документа " , Е - " Порядковый номер документа одного наименования " , F - " Номер редакции документа " , G - " Номер части документа " , M - " Признак документа, выполненного на машинных носителях ".

Важно! При соединении, заполненных пользователем полей в единый номер, в печатной форме номер должен отображаться с разделителями в виде точек, в формате: A.B.C.D.E.F-G.М. Исключение, разделитель между полями F и G, в этом случае разделителем должен являться символ "-".

- " Номер ОКВЭД закупки " - поле должно автоматически предзаполняться системой на основе значения, указанного в НСИ в реестре государственных контрактов, в карточке контракта, поле "ОКВЭД закупки" (рисунок 2).
- " Порядковый регистрационный номер системы " - заполняется вручную, предзаполнение отсутствует. Необходимо предусмотреть ФЛК (поле должно состоять из 3-х цифр). Доступный для заполнения диапазон значений - от 001 до 999. Поле обязательно для заполнения.
- " Код документа " - поле должно автоматически предзаполняться системой, для документа с типом ПЗ - всегда указывается значение " ПМ ".
- " Порядковый номер документа одного наименования " - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Номер редакции документа "  - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Номер части документа "  - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Признак документа, выполненного на машинных носителях "  - заполняется вручную, предзаполнение отсутствует. Необходимо предусмотреть ФЛК (возможно заполнить только символом М ). Поле не обязательно для заполнения.

8.6. Создание алгоритма предзаполнения децимального номера для документов ЧТЗ, ПЗ, ПМИ

Необходимо изменить логику заполнения децимального номера (пример расположения номера в печатной форме указан на рисунке 15) для документов ЧТЗ, ПЗ, ПМИ.

Если раньше  децимальный номер заполнялся пользователем вручную в поле "Шифр документа без ЛУ" в экранных формах формирования документов, то теперь необходимо разделить единое поле на 8 различных, часть из которых должны предзаполняться системой автоматически:

- " Код организации разработчика " - поле должно автоматически предзаполняться системой на основе значения, указанного в НСИ в реестре организаций, в карточке организации, в поле "ОГРН" (показано на рисунке 13).
- " Номер ОКВЭД закупки " - поле должно автоматически предзаполняться системой на основе значения, указанного в НСИ в реестре государственных контрактов, в карточке контракта, поле "ОКВЭД закупки" (рисунок 2).
- " Порядковый регистрационный номер системы " - заполняется вручную, предзаполнение отсутствует. Необходимо предусмотреть ФЛК (поле должно состоять из 3-х цифр). Доступный для заполнения диапазон значений - от 001 до 999. Поле обязательно для заполнения.
- " Код документа " - поле должно автоматически предзаполняться системой, для документа с типом ПЗ - всегда указывается значение " П2 ", для документа с типом ПМИ - всегда указывается значение " ПМ ", для документа с типом ЧТЗ - всегда указывается значение " ПТ ".
- " Порядковый номер документа одного наименования " - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Номер редакции документа "  - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Номер части документа "  - заполняется вручную, предзаполнение отсутствует. Поле не обязательно для заполнения.
- " Признак документа, выполненного на машинных носителях "  - заполняется вручную, предзаполнение отсутствует. Необходимо предусмотреть ФЛК (возможно заполнить только символом М ). Поле не обязательно для заполнения.

После заполнения пользователем всех полей, алгоритм должен "соединить" значения, указанные в полях в единый децимальный номер и отобразить его в печатных формах документа (рисунок 15).

Формат получившегося номера: A.B.C.D.E.F-G.М , где А - " Код организации разработчика ", B - " Номер ОКВЭД закупки ", C - " Порядковый регистрационный номер системы " , D - " Код документа " , Е - " Порядковый номер документа одного наименования " , F - " Номер редакции документа " , G - " Номер части документа " , M - " Признак документа, выполненного на машинных носителях ".

Важно! При соединении, заполненных пользователем полей в единый номер, в печатной форме номер должен отображаться с разделителями в виде точек, в формате: A.B.C.D.E.F-G.М. Исключение, разделитель между полями F и G, в этом случае разделителем должен являться символ "-".
