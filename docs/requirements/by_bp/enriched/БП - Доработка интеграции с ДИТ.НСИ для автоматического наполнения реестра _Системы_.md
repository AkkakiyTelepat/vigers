## 7.2 Описание алгоритмов

### A.10 Функции системы (п.8, дословно)

8.1.1 Развитие интеграции с ДИТ.НСИ в части получения данных для автоматического создания карточки "Система"

Необходимо настроить получение минимального набора данных для создания карточки "Система" и автоматизировать процесс создания карточек(записей) в реестре "Системы"

Для этого необходимо получать следующий атрибутивный состав, который описан в таблице 1

Таблица 1 - Список полей необходимых для получения из ДИТ.НСИ

|  | Наименование поля в ДИТ.Калькулятор | Наименование поля в ДИТ.НСИ | Примечания/Ограничения |
|---|---|---|---|
| 1 | Полное наименование Системы (Name) | Полное наименование ИС |  |
| 2 | Краткое наименование Системы (ShortName) | Сокращенное наименование ИС | Опционально, при наличии в ДИТ.НСИ данного значения |
| 3 | РИРС (Code) | Идентификатор (номер) в Едином реестре информационных ресурсов и систем (РИРС) г. Москвы | Опционально, при наличии в ДИТ.НСИ данного значения |

1. Автоматическое обновление

Триггер: Ежедневно в 01:00

Исполнитель: Система ДИТ.Калькулятор

Сценарий:

1. В 01:00 каждого дня система Калькулятор инициирует процесс обновления реестра Системы
2. Кальк отправляет запрос в НСИ на обновление данных
3. Валидация и ответ НСИ: НСИ проверяет наличие записей и отправляет отчет в Кальк
4. Обработка ответа (логика для Калька): Для каждой полученной Системы из ответа НСИ: Проверить наличие Системы в реестре Если Система найдена в БД Калькулятора, то выполнить обновление всех полей в карточке Системы данными из НСИ Если Система не найден в БД Калькулятора, то выполнить создание новой записи в реестре Системы
5. Логирование: По итогам цикла формируется запись в журнале синхронизации (количество обработанных, обновленных, добавленных записей)
6. Система помечает статус синхронизации как «Успешно»

Исключения:

1. Таймаут или ошибка НСИ: Если сервис НСИ не отвечает или отвечает ошибкой (5xx, 4xx), то процесс синхронизации останавливается, статус помечается как «Ошибка связи». Повторные попытки связи необходимо настроить по следующему принципу: 3 попытки с интервалом 10 минут, после чего необходима отправка уведомления администратору

2. Ручное обновление по Краткому наименованию Системы ИЛИ по РИРС

Триггер: Пользователь нажимает кнопку «Добавить» в интерфейсе реестра Системы

Актор: Пользователи с ролями «Администратор НСИ», «Администратор», «Руководитель проекта (ДИТ)»

Предусловие: Пользователь аутентифицирован и авторизован в системе ДИТ.Калькулятор

Сценарий:

1. Пользователь нажимает кнопку «Добавить» в реестре Системы
2. Система отображает модальное окно со следующими элементами: Заголовок: «Введите идентификатор Системы» Поле выбора: «Тип идентификатора» Поле ввода: «Краткое наименование системы» ИЛИ «РИРС» Кнопка «Применить» Кнопка «Отменить» Элемент закрытия модального окна
3. Пользователь вводит краткое наименование системы ИЛИ РИРС
4. Система валидирует вводимые значения (возможно создание проверок для поля)
5. Пользователь нажимает на кнопку «Применить»
6. Кальк отправляет запрос с введенным пользователем кратким наименованием системы ИЛИ РИРС
7. Валидация ответа от НСИ: НСИ вернул запись об объекте: Кальк проводит поиск по краткому наименованию системы ИЛИ РИРС в реестре Системы: Если запись с таким идентификатором (наименование ИЛИ РИРС) найдена, то система обновляет данные в карточке Системы, закрывает модальное окно и отображает пользователю сообщение с текстом: Если было указано Краткое наименование Системы: «Данные по системе <Краткое наименование системы> успешно обновлены». Иначе система создает новую запись в реестре Системы и отображает пользователю сообщение: «Система <Краткое наименование системы> создана» Если был указан РИРС: «Данные по системе <РИРС> успешно обновлены». Иначе система создает новую запись в реестре Системы и отображает пользователю сообщение: «Система <РИРС> создана» Логирование: Фиксируются действия пользователя

Исключения:

1. Если пользователь нажал «Применить», не введя краткое наименование системы ИЛИ РИРС, то система подсвечивает поле ошибкой: Если было указано Краткое наименование Системы: «Необходимо ввести краткое наименование системы» Если был указан РИРС: «Необходимо ввести РИРС»
2. Краткое наименование системы ИЛИ РИРС не найден в НСИ: Если сервис НСИ отвечает ошибкой 404 или пустым телом ответа, то Кальк не создает и не обновляет записи в реестре и отображает пользователю сообщение об ошибке с текстом: Если было указано Краткое наименование Системы:  «Ошибка обновления. Система с наименованием <Краткое наименование системы> не найдена. Проверьте корректность ввода или обратитесь к администратору сервиса» при этом модальное окно не закрывается и поле ввода активно Если был указан РИРС: «Ошибка обновления. Система с номером РИРС <РИРС> не найдена. Проверьте корректность ввода или обратитесь к администратору сервиса» при этом модальное окно не закрывается и поле ввода активно
3. Таймаут или ошибка НСИ: Если сервис НСИ не отвечает или отвечает ошибкой (5xx), то Кальк отображает пользователю ошибку с текстом: «Временная ошибка. Повторите попытку позже»

При отработке интеграции создаются записи в реестре Системы.

# 8. Функции системы

8.1.1 Развитие интеграции с ДИТ.НСИ в части получения данных для автоматического создания карточки "Система"

Необходимо настроить получение минимального набора данных для создания карточки "Система" и автоматизировать процесс создания карточек(записей) в реестре "Системы"

Для этого необходимо получать следующий атрибутивный состав, который описан в таблице 1

Таблица 1 - Список полей необходимых для получения из ДИТ.НСИ

|  | Наименование поля в ДИТ.Калькулятор | Наименование поля в ДИТ.НСИ | Примечания/Ограничения |
|---|---|---|---|
| 1 | Полное наименование Системы (Name) | Полное наименование ИС |  |
| 2 | Краткое наименование Системы (ShortName) | Сокращенное наименование ИС | Опционально, при наличии в ДИТ.НСИ данного значения |
| 3 | РИРС (Code) | Идентификатор (номер) в Едином реестре информационных ресурсов и систем (РИРС) г. Москвы | Опционально, при наличии в ДИТ.НСИ данного значения |

1. Автоматическое обновление

Триггер: Ежедневно в 01:00

Исполнитель: Система ДИТ.Калькулятор

Сценарий:

1. В 01:00 каждого дня система Калькулятор инициирует процесс обновления реестра Системы
2. Кальк отправляет запрос в НСИ на обновление данных
3. Валидация и ответ НСИ: НСИ проверяет наличие записей и отправляет отчет в Кальк
4. Обработка ответа (логика для Калька): Для каждой полученной Системы из ответа НСИ: Проверить наличие Системы в реестре Если Система найдена в БД Калькулятора, то выполнить обновление всех полей в карточке Системы данными из НСИ Если Система не найден в БД Калькулятора, то выполнить создание новой записи в реестре Системы
5. Логирование: По итогам цикла формируется запись в журнале синхронизации (количество обработанных, обновленных, добавленных записей)
6. Система помечает статус синхронизации как «Успешно»

Исключения:

1. Таймаут или ошибка НСИ: Если сервис НСИ не отвечает или отвечает ошибкой (5xx, 4xx), то процесс синхронизации останавливается, статус помечается как «Ошибка связи». Повторные попытки связи необходимо настроить по следующему принципу: 3 попытки с интервалом 10 минут, после чего необходима отправка уведомления администратору

2. Ручное обновление по Краткому наименованию Системы ИЛИ по РИРС

Триггер: Пользователь нажимает кнопку «Добавить» в интерфейсе реестра Системы

Актор: Пользователи с ролями «Администратор НСИ», «Администратор», «Руководитель проекта (ДИТ)»

Предусловие: Пользователь аутентифицирован и авторизован в системе ДИТ.Калькулятор

Сценарий:

1. Пользователь нажимает кнопку «Добавить» в реестре Системы
2. Система отображает модальное окно со следующими элементами: Заголовок: «Введите идентификатор Системы» Поле выбора: «Тип идентификатора» Поле ввода: «Краткое наименование системы» ИЛИ «РИРС» Кнопка «Применить» Кнопка «Отменить» Элемент закрытия модального окна
3. Пользователь вводит краткое наименование системы ИЛИ РИРС
4. Система валидирует вводимые значения (возможно создание проверок для поля)
5. Пользователь нажимает на кнопку «Применить»
6. Кальк отправляет запрос с введенным пользователем кратким наименованием системы ИЛИ РИРС
7. Валидация ответа от НСИ: НСИ вернул запись об объекте: Кальк проводит поиск по краткому наименованию системы ИЛИ РИРС в реестре Системы: Если запись с таким идентификатором (наименование ИЛИ РИРС) найдена, то система обновляет данные в карточке Системы, закрывает модальное окно и отображает пользователю сообщение с текстом: Если было указано Краткое наименование Системы: «Данные по системе <Краткое наименование системы> успешно обновлены». Иначе система создает новую запись в реестре Системы и отображает пользователю сообщение: «Система <Краткое наименование системы> создана» Если был указан РИРС: «Данные по системе <РИРС> успешно обновлены». Иначе система создает новую запись в реестре Системы и отображает пользователю сообщение: «Система <РИРС> создана» Логирование: Фиксируются действия пользователя

Исключения:

1. Если пользователь нажал «Применить», не введя краткое наименование системы ИЛИ РИРС, то система подсвечивает поле ошибкой: Если было указано Краткое наименование Системы: «Необходимо ввести краткое наименование системы» Если был указан РИРС: «Необходимо ввести РИРС»
2. Краткое наименование системы ИЛИ РИРС не найден в НСИ: Если сервис НСИ отвечает ошибкой 404 или пустым телом ответа, то Кальк не создает и не обновляет записи в реестре и отображает пользователю сообщение об ошибке с текстом: Если было указано Краткое наименование Системы:  «Ошибка обновления. Система с наименованием <Краткое наименование системы> не найдена. Проверьте корректность ввода или обратитесь к администратору сервиса» при этом модальное окно не закрывается и поле ввода активно Если был указан РИРС: «Ошибка обновления. Система с номером РИРС <РИРС> не найдена. Проверьте корректность ввода или обратитесь к администратору сервиса» при этом модальное окно не закрывается и поле ввода активно
3. Таймаут или ошибка НСИ: Если сервис НСИ не отвечает или отвечает ошибкой (5xx), то Кальк отображает пользователю ошибку с текстом: «Временная ошибка. Повторите попытку позже»

При отработке интеграции создаются записи в реестре Системы.

НСИ проверяет наличие записей и отправляет отчет в Калькулятор. Статус помечается как «Ошибка связи». Выполняется 3 повторные попытки с интервалом 10 минут. После неудачных попыток отправляется уведомление администратору |
| 4 | Открытие формы для ручного добавления системы | Пользователь с ролью «Администратор», «Администратор НСИ» или «Руководитель проектов (ДИТ)» нажимает кнопку «Добавить» в реестре «Системы» | Открывается модальное окно с заголовком «Введите идентификатор Системы». В окне присутствуют: поле выбора «Тип идентификатора», поле ввода значения (динамически изменяющее подпись в зависимости от выбранного типа), кнопка «Применить», кнопка «Отменить», элемент закрытия окна (крестик) |
| 5 | Выбор типа идентификатора и отображение соответствующего поля ввода | Пользователь в модальном окне выбирает значение «Тип идентификатора»: «РИРС» или «Краткое наименование Системы» | При выборе «РИРС» система отображает дополнительное поле ввода с подписью «РИРС» (ожидается числовой ввод). При выборе «Краткое наименование Системы» отображается поле ввода с подписью «Краткое наименование Системы» (текстовый ввод) |

Если запись найдена: данные обновляются в карточке существующей системы (если найдена в реестре) или создается новая запись, модальное окно закрывается, пользователю показывается сообщение: «Данные по системе <наименование> успешно обновлены» (если обновление) или «Система <наименование> создана» (если создание). Если запись не найдена (ошибка 404 или пустой ответ): модальное окно не закрывается, поле ввода остается активным, отображается сообщение: «Ошибка обновления. Система с наименованием <наименование> не найдена. Проверьте корректность ввода или обратитесь к администратору сервиса» |
| 7 | Ручное добавление системы по РИРС | Пользователь в модальном окне выбирает тип «РИРС», вводит числовой идентификатор (РИРС) и нажимает «Применить» | Система отправляет запрос в НСИ для поиска системы по РИРС.
