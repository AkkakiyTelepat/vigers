### A.4 Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Цель - настроить фильтрацию ФОИ в зависимости от выбора типа Методики (старая, новая) и использования Уровня языка разработки (высокий, сверхвысокий Low Code).

Обоснование - на основании данных, указанных в НМЦК, настроить отображение ФОИ таким образом, чтобы у аналитика (подрядчика) не было необходимости в справочнике ФОИ настраивать фильтрацию по признакам "Старая методика расчета" и "Признак low code".

Выбор доступных ФОИ должен быть определен сведениями, внесенными Администратором системы в НСИ Калькулятора, а именно сведения о типе Методики расчета НМЦК (старая, новая) и уровня языке разработки подсистем (высокий, сверхвысокий Low code).

4.2. Описание проблем и решения

Проблема - Аналитик (подрядчик) при формировании РСЗ и выборе каждой ФОИ из справочника дополнительно указывает два признака "Старая методика расчета" и "Признак low code" . Это увеличивает время подготовки расчета подрядчикам.

При этом оба признака уже имеются в характеристиках ГК и могут быть применимы для РСЗ.

Так признак "Старая методика расчета" указан при формировании ГК в НСИ Калькулятор.

"Признак low code" указан в характеристиках подсистем НСИ Калькулятор.

Решение - выводить пользователю только тот перечень ФОИ, который удовлетворяет установленным признакам "Старая методика расчета" и "Признак low code".

### A.9 Пользовательский сценарий и алгоритмы (п.7)

Действия Администратора при настройке ГК

1. Авторизация под ролью "Администратор".
2. Создание/редактирование ГК: Перейти в раздел: "Расчет по Методике 3-Р" - "НСИ" - "Реестр Государственные контракты". Нажать "Добавить" для создания нового ГК.
3. Указание типа методики: Если ГК использует старую методику (до изменений от 01.11.2023), активировать флаг: "Не учитывать изменения Методики 3-Р, вступившие в силу 01.11.2023". Для новой методики флаг не ставится.
4. Настройка подсистем ГК: В разделе "Общие сведения" добавить подсистемы, относящиеся к контракту. Для каждой подсистемы указать: Уровень языка разработки ("высокий" или "сверхвысокий Low-code"). Коэффициенты для расчета по Методике 3-Р (включая коэффициент языка разработки).

Действия Аналитика (Подрядчика) при формировании расчета

1. Авторизация под ролью "Аналитик (Подрядчик)".
2. Создание расчета: Перейти в раздел: "Расчет по Методике 3-Р" - "Работы". Нажать "Добавить" для создания новой заявки. В заявке нажать "Создать расчет".
3. Выбор ФОИ для итерации: Перейти в раздел "Итерации" созданного расчета. Нажать "Добавить" для выбора ФОИ.
4. Автоматическая фильтрация ФОИ:

(is-as):

- Аналитик вручную выбирал признаки "Старая методика расчета" и "Признак low code" в справочнике ФОИ. В списке ФОИ видит все доступные комбинации ФОИ

(to-be):

- Система автоматически отображает только релевантные ФОИ, соответствующие параметрам ГК: Тип методики (старая/новая), заданный Администратором. Уровень языка разработки (Low-code/высокий), указанный для подсистем ГК. Ручная фильтрация исключена - пользователь видит только подходящие варианты.

## 7.2. [Описание алгоритмов]

1. Получение параметров ГК: Система определяет, какая методика применяется для текущего ГК: Если в настройках ГК активирована галка «Не учитывать изменения Методики 3-Р от 01.11.2023», используется старая методика. Если галка не активирована - новая методика. - Система собирает уровни языка разработки для всех подсистем ГК (например: «Low-code» для одних подсистем и «высокий» для других).
2. Фильтрация справочника ФОИ: Для каждой ФОИ из общего справочника система проверяет два условия: а) Соответствие типу методики: - Если для ГК выбрана старая методика, в список попадают только ФОИ, отмеченные как «Старая методика расчета». - Если выбрана новая методика - только ФОИ без этой отметки. б) Соответствие уровню языка разработки: - ФОИ включается в результат, если её уровень языка разработки (например, «Low-code») совпадает хотя бы с одним из уровней, указанных в подсистемах ГК.

### A.10 Функции системы (п.8, дословно)

#### 8.1. Развитие функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах Системы в части фильтрации ФОИ по типу Методики и уровню языка разработки Low code

Функция обеспечивает динамическое формирование списка доступных ФОИ в интерфейсе выбора на основе параметров ГК , заданных Администратором в разделе НСИ. Система автоматически анализирует:

- Тип методики расчета («старая» или «новая»), определяемый наличием/отсутствием галки «Не учитывать изменения Методики 3-Р от 01.11.2023» в настройках ГК.
- Уровни языка разработки («высокий» или «сверхвысокий Low-code»), указанные для подсистем ГК в НСИ.

В модальном окне «Выбор из справочника» скрываются поля ручной фильтрации («Старая методика расчета», «Признак Low-code»).

# 4. Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Цель - настроить фильтрацию ФОИ в зависимости от выбора типа Методики (старая, новая) и использования Уровня языка разработки (высокий, сверхвысокий Low Code).

Обоснование - на основании данных, указанных в НМЦК, настроить отображение ФОИ таким образом, чтобы у аналитика (подрядчика) не было необходимости в справочнике ФОИ настраивать фильтрацию по признакам "Старая методика расчета" и "Признак low code".

Выбор доступных ФОИ должен быть определен сведениями, внесенными Администратором системы в НСИ Калькулятора, а именно сведения о типе Методики расчета НМЦК (старая, новая) и уровня языке разработки подсистем (высокий, сверхвысокий Low code).

4.2. Описание проблем и решения

Проблема - Аналитик (подрядчик) при формировании РСЗ и выборе каждой ФОИ из справочника дополнительно указывает два признака "Старая методика расчета" и "Признак low code" . Это увеличивает время подготовки расчета подрядчикам.

При этом оба признака уже имеются в характеристиках ГК и могут быть применимы для РСЗ.

Так признак "Старая методика расчета" указан при формировании ГК в НСИ Калькулятор.

"Признак low code" указан в характеристиках подсистем НСИ Калькулятор.

Решение - выводить пользователю только тот перечень ФОИ, который удовлетворяет установленным признакам "Старая методика расчета" и "Признак low code".

## 7.2. [Описание алгоритмов]

1. Получение параметров ГК: Система определяет, какая методика применяется для текущего ГК: Если в настройках ГК активирована галка «Не учитывать изменения Методики 3-Р от 01.11.2023», используется старая методика. Если галка не активирована - новая методика. - Система собирает уровни языка разработки для всех подсистем ГК (например: «Low-code» для одних подсистем и «высокий» для других).
2. Фильтрация справочника ФОИ: Для каждой ФОИ из общего справочника система проверяет два условия: а) Соответствие типу методики: - Если для ГК выбрана старая методика, в список попадают только ФОИ, отмеченные как «Старая методика расчета». - Если выбрана новая методика - только ФОИ без этой отметки. б) Соответствие уровню языка разработки: - ФОИ включается в результат, если её уровень языка разработки (например, «Low-code») совпадает хотя бы с одним из уровней, указанных в подсистемах ГК.

# 8. Функции системы

#### 8.1. Развитие функции отображения информации пользователю в таком же виде, как она хранится во внутренних файлах Системы в части фильтрации ФОИ по типу Методики и уровню языка разработки Low code

Функция обеспечивает динамическое формирование списка доступных ФОИ в интерфейсе выбора на основе параметров ГК , заданных Администратором в разделе НСИ. Система автоматически анализирует:

- Тип методики расчета («старая» или «новая»), определяемый наличием/отсутствием галки «Не учитывать изменения Методики 3-Р от 01.11.2023» в настройках ГК.
- Уровни языка разработки («высокий» или «сверхвысокий Low-code»), указанные для подсистем ГК в НСИ.

В модальном окне «Выбор из справочника» скрываются поля ручной фильтрации («Старая методика расчета», «Признак Low-code»).

Пользователь видит только отфильтрованный перечень ФОИ без возможности изменения критериев отбора и скрытыми столбцами фильтров.

#### 8.2 Развитие функции ввода информации пользователем через интерфейс системы в части обязательного выбора уровня языка разработки для подсистем

Функция обеспечивает модификацию пользовательских интерфейсов ввода данных для настройки подсистем Государственных контрактов. Реализует обязательный выбор уровня языка разработки из предопределенных значений с последующей автоматической синхронизацией данных во всех связанных интерфейсах.

Изменение затрагивает:

- модальное окно  «Добавление подсистемы»
- модальное окно «Отчетная подсистема»

1. Изменение типа поля «Уровень языка разработки» с текстового на обязательный выпадающий список
2. Блокировка сохранения подсистемы без выбора значения
3. Автоматическое скрытие поля в окне «Коэффициенты» с подтягиванием данных из настроек подсистемы
4. Синхронизация всех связанных расчетов при изменении уровня языка
