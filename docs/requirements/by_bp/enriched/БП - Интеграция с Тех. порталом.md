### A.4 Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Создание единой, непротиворечивой и автоматизированной интеграции между смежными системами ДИТ позволяет перейти от разрозненного управления данными к сквозному процессу.

Интеграция между Тех. порталом и ДИТ.Калькулятор исключит двойной ввод данных по ГК, сократит временной цикл между заключение ГК по закупке с отображением всей информации по ГК в ДИТ.Калькулятор за счет автоматической передачи актуальных данных между системами.

РП ДИТ смогут увидеть как распределение денег между годами и этапами ГК, так и фактические выплаты, что позволит отслеживать расходование бюджетных средств в рамках исполнения ГК и своевременно предпринимать действия для избежания невыполнения плановых показателей.

### A.7.1 Раздел 5 «Требования к результату» полностью (дословно)

Обеспечить в ДИТ.Интеллект возможность работы с данными из Тех. портал по наполнению справочной информации в ДИТ.Калькулятор. При этом возможность работы с финансовой информация по ГК в рамках закупки для корректного формирования РСЗ по исполнению ГК . Механизмы работы с данными из Тех. портал должны в дальнейшим допускать тиражирование на запросы из других сервисов ДИТ.Интеллект.

8.2 Создание функций запроса, обработки ответа на запрос и хранения ответов на запрос от Тех. портал

8.2.1 Создание функции автоматический запрос в Тех. портал

Функция формирует запрос по формату взаимодействия, размещает его в очереди исходящих сообщений. Запись о размещении запроса в очереди создается в таблице журнала взаимодействия с Тех. портал.

С периодичностью в 5 минут функция должна опрашивать очередь входящих сообщений Тех. портал. При наличии новых записей функция считывает сообщение и создает запись в таблице журнала взаимодействия с Тех. портал.

8.2.2 Создание функции хранения данных Журнала взаимодействия с Тех. портал

С целью управления процессом взаимодействия с Тех. портал в ДИТ.Калькулятор должен быть реализован Журнал взаимодействия с Тех. портал со следующей структурой данных:

| № | Поле |
|---|---|
| 1 | Идентификатор запроса в Тех. портал |
| 2 | Дата запроса |
| 3 | XML-сообщение запроса |
| 4 | Статус запроса |
| 5 | Дата ответа |
| 6 | XML-сообщение ответа |
| 7 | Статус проверки ответа |

8.2.3 Создание функции проверки полученного из Тех. портал ответа на запрос

Функция должна осуществлять следующие проверки входящего сообщения:

- на соответствие схеме обязательных атрибутов
- на соответствие идентификаторов полученного ответа отправленному запросу

В случае выявления ошибок система направляет во внешнюю ИС сообщение с указанием кода ошибки.

В случае несоответствия введенных параметров правилам проверки функция возвращает соответствующее сообщение об ошибке
