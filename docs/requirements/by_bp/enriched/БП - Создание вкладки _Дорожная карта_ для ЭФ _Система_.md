## 7.2. Описание алгоритмов

#### 7.2.1 Алгоритм построения иерархической структуры данных в реестре "Задачи Jira"

1. Определение задач уровня = 0

Выделяются все задачи, которые не имеют родителя в рамках полученных данных. Для каждой из них:

- Родитель отсутствует – записываем значение NULL (parentId = NULL)
- Уровень устанавливаем равным 0 (level = 0)

2. Присвоение атрибутов

Начиная с каждой задачи с уровнем = 0, последовательно проходим по всем её потомкам, затем по потомкам потомков и т.д. Для каждого потомка:

- Родителем записывается та задача, в атрибут children котjрой входила задача (в parentId указываем issueID родителя)
- Уровень вычисляется как уровень родителя + 1

По мере обхода каждой задаче присваиваются значения в два поля:

- parentId – идентификатор родительской задачи
- level – числовое значение уровня вложенности

#### 7.2.2 Алгоритм построения реестра "Дорожная карта" на ЭФ "Системы"

Предусловия: Пользователь выбрал значение из списка в поле "Дорожная карта"

Логика:

1. Система просматривает связь дорожной карты с задачами в реестре "Задачи в дорожной карте"
2. Система отображает в поле "Дорожная карта" выбранное пользователем значение
3. Система собирает реестр для отображения по следующему принципу: В се задачи группируются под своими родителями (под задачами с level = 0). Далее для каждой задачи определяются дочерние задачи, которые ссылаются на неё. В результате формируется многоуровневая структура, отражающая вложенность
4. Система отображает следующий набор полей в реестре: Тип задачи, Наименование задачи, Номер задачи(код задачи Jira), Статус задачи, Компонент, Планируемая дата выполнения работ, Дата решения, Исполнитель, Наименование спринта, Релиз
5. Система сортирует записи в реестре, описание в пункте 7.2.3

7.2.3 Алгоритм сортировки данных в реестре "Дорожная карта" на ЭФ "Системы"

Предусловия: Получены данные по Дорожной карте, Задачам Jira и отработал алгоритм " Алгоритм построения иерархической структуры данных в реестре "Задачи Jira""

#### 8.1.5 Развитие интеграции с Jira в части получения данных по Дорожным картам( Structure ) и Задачам Jira

1. Автоматическое обновление

Триггер: Каждые 3 часа

Исполнитель: Система ДИТ.Калькулятор

Сценарий:

1. Каждые 3 часа каждого дня сервис ДИТ.Калькулятор инициирует процесс обновления реестров Дорожная карта или Задачи Jira
2. ДИТ.Калькулятор отправляет запрос в Jira на обновление данных
3. Валидация и ответ Jira: Jira проверяет наличие записей и отправляет отчет в ДИТ.Калькулятор
4. Обработка ответа (логика для ДИТ.Калькулятор): Для каждой полученной Дорожной карты или Задачи Jira из ответа Jira: Проверить наличие Дорожной карты или Задачи Jira в соответствующих реестрах Если найдено совпадение в БД ДИТ.Калькулятор, то выполнить обновление всех полей в карточке Дорожной карты или Задачи Jira данными из Jira Если не найдено в БД ДИТ.Калькулятор, то выполнить создание новой записи в реестрах Дорожной карты или Задачи Jira
5. Логирование: По итогам цикла формируется запись в журнале синхронизации (количество обработанных, обновленных, добавленных записей)
6. Система помечает статус синхронизации как «Успешно»

Исключения:

1. Таймаут или ошибка Jira: Если сервис Jira не отвечает или отвечает ошибкой (5xx, 4xx), то процесс синхронизации останавливается, статус помечается как «Ошибка связи». Повторные попытки связи необходимо настроить по следующему принципу: 3 попытки с интервалом 10 минут, после чего необходима отправка уведомления администратору

## 7.2. Описание алгоритмов

#### 7.2.1 Алгоритм построения иерархической структуры данных в реестре "Задачи Jira"

1. Определение задач уровня = 0

Выделяются все задачи, которые не имеют родителя в рамках полученных данных. Для каждой из них:

- Родитель отсутствует – записываем значение NULL (parentId = NULL)
- Уровень устанавливаем равным 0 (level = 0)

2. Присвоение атрибутов

Начиная с каждой задачи с уровнем = 0, последовательно проходим по всем её потомкам, затем по потомкам потомков и т.д. Для каждого потомка:

- Родителем записывается та задача, в атрибут children котjрой входила задача (в parentId указываем issueID родителя)
- Уровень вычисляется как уровень родителя + 1

По мере обхода каждой задаче присваиваются значения в два поля:

- parentId – идентификатор родительской задачи
- level – числовое значение уровня вложенности

#### 7.2.2 Алгоритм построения реестра "Дорожная карта" на ЭФ "Системы"

Предусловия: Пользователь выбрал значение из списка в поле "Дорожная карта"

Логика:

1. Система просматривает связь дорожной карты с задачами в реестре "Задачи в дорожной карте"
2. Система отображает в поле "Дорожная карта" выбранное пользователем значение
3. Система собирает реестр для отображения по следующему принципу: В се задачи группируются под своими родителями (под задачами с level = 0). Далее для каждой задачи определяются дочерние задачи, которые ссылаются на неё. В результате формируется многоуровневая структура, отражающая вложенность
4. Система отображает следующий набор полей в реестре: Тип задачи, Наименование задачи, Номер задачи(код задачи Jira), Статус задачи, Компонент, Планируемая дата выполнения работ, Дата решения, Исполнитель, Наименование спринта, Релиз
5. Система сортирует записи в реестре, описание в пункте 7.2.3

7.2.3 Алгоритм сортировки данных в реестре "Дорожная карта" на ЭФ "Системы"

Предусловия: Получены данные по Дорожной карте, Задачам Jira и отработал алгоритм " Алгоритм построения иерархической структуры данных в реестре "Задачи Jira""

Запуск: При выборе значения в поле "Дорожная карта" на ЭФ "Система" на вкладке "Дорожная карта"

Логика:

1. Система сортирует значения в реестре по связке значений: Для каждой связки "parentId" И "level система сортирует записи в реестре по возрастанию значения в поле "Планируемая дата выполнения работ" (для дат ASC)

#### 7.2.4 Алгоритм определение значения в поле "Просрочка"

Логика:

- Если " Планируемая дата выполнения" < Текущей даты, то Система отображает значение "Просрочка", необходима индикация поля, поле подсвечивается Красным цветом
- Если "Планируемая дата выполнения" >= Текущей дате, то Система отображает значение "В сроке", необходима индикация поля, поле подсвечивается Зеленым цветом

#### 8.1.5 Развитие интеграции с Jira в части получения данных по Дорожным картам( Structure ) и Задачам Jira

1. Автоматическое обновление

Триггер: Каждые 3 часа

Исполнитель: Система ДИТ.Калькулятор

Сценарий:

1. Каждые 3 часа каждого дня сервис ДИТ.Калькулятор инициирует процесс обновления реестров Дорожная карта или Задачи Jira
2. ДИТ.Калькулятор отправляет запрос в Jira на обновление данных
3. Валидация и ответ Jira: Jira проверяет наличие записей и отправляет отчет в ДИТ.Калькулятор
4. Обработка ответа (логика для ДИТ.Калькулятор): Для каждой полученной Дорожной карты или Задачи Jira из ответа Jira: Проверить наличие Дорожной карты или Задачи Jira в соответствующих реестрах Если найдено совпадение в БД ДИТ.Калькулятор, то выполнить обновление всех полей в карточке Дорожной карты или Задачи Jira данными из Jira Если не найдено в БД ДИТ.Калькулятор, то выполнить создание новой записи в реестрах Дорожной карты или Задачи Jira
5. Логирование: По итогам цикла формируется запись в журнале синхронизации (количество обработанных, обновленных, добавленных записей)
6. Система помечает статус синхронизации как «Успешно»

Исключения:

1. Таймаут или ошибка Jira: Если сервис Jira не отвечает или отвечает ошибкой (5xx, 4xx), то процесс синхронизации останавливается, статус помечается как «Ошибка связи». Повторные попытки связи необходимо настроить по следующему принципу: 3 попытки с интервалом 10 минут, после чего необходима отправка уведомления администратору
