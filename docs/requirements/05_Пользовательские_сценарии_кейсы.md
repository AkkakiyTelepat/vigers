# 05. Пользовательские сценарии / кейсы (Use Cases)

Сценарии реконструированы из разделов «Функции системы» (п.8), «Требования к результату» (п.6) и таблиц вариантов использования источников. Акторы указаны так, как в источниках.

## UC-01. Создание Закупки и автоматическое появление ГК (`БП - Создание реестра _Закупки_`)
**Актор:** Администратор.
**Основной сценарий:** НСИ → Контракты и задания → «Закупки» → «Добавить» → заполнить «Наименование закупки», «Ссылку на закупку в ПРГ» (обязательно), при наличии — «Номер ГК» (до 20 символов) → Сохранить (валидация). При заполненном номере система автоматически создаёт запись в реестре ГК со статусом «Черновик».
**Исключения:** (a) пара наименование+ссылка уже существует — создание запрещено; (b) номер ГК уже есть в реестре ГК — обновление записей не производится; (c) «Номер ГК» = NULL — закупка остаётся «В работе».

## UC-02. Проведение ГК по жизненному циклу (`БП - Создание статусной модели для Закупки, ГК…`)
**Акторы:** Администратор, Руководитель проекта (ДИТ), Система.
1. ГК создан (авто/вручную) → «Черновик».
2. РП/Администратор переводит в «Согласование РП» (при проверке заполнения обязательных полей; неполные данные блокируют перевод — `БП - Изменение логики заведения ГК v2`).
3. После согласования — «В работе»; этапы ГК автоматически переходят «Черновик» → «В работе».
4. Этап получает «Оплачен» автоматически по данным СПУ (Stage Points/Name = «Оплата по…»); Работа/Заявка — «Оплачен» автоматически при «Оплачено» Этапа ГК.
5. Все связанные этапы оплачены → ГК «Исполнено» → через 10 календарных дней автоархивация; этапы и работы архивируются вслед за ГК/этапом.
**Альтернативы:** ручной перевод в «Корзину» и восстановление; удаление только через Корзину (Администратор).

## UC-03. Формирование РСЗ по заявке (`БП - Формирование РСЗ по заявке… v2`, `БП - Работа с расчетами…`, `БП - Добавить возможность загружать ФОИ из Excel…`)
**Акторы:** Аналитик (Подрядчика), Аналитик (ДИТ), РП ДИТ, Администратор.
1. Открыть карточку расчёта (ЭФ «Итерация») → добавить ФОИ: из справочника/НМЦК, кнопкой «Добавить пустую ФОИ» (выбор Подсистемы + ФТ → автозаполнение от типовой ФОИ, статус «Черновик»), либо загрузкой Excel (парсинг на ЭФ «Итерация»).
2. Отредактировать in-line «Уточняющую часть» и «Краткое описание» (только «Черновик») → перевести в «В работа» (валидация непустоты).
3. Перевести ФОИ «На согласование» → Аналитик ДИТ проверяет: «Согласовано» либо «Не согласовано» + замечание (справочник замечаний, модальное окно «Применить/Отмена»).
4. Согласованная ФОИ перепривязывается к актуальной итерации; при создании новой итерации — массовая перепривязка.
5. РП рассматривает расчёт («на согласовании у РП»): может проверить коэффициенты (UC-06), редактировать «Размер команды»; далее «Согласовано РП» → «Согласовано».
**Исключения:** расчёт в статусе «Согласовано» — изменение статусов ФОИ заблокировано (обращение в СТП); откат статуса делает Администратор без создания новой итерации.

## UC-04. Замена ФОИ/ФТ из НМЦК при согласовании заявки (`БП - замена ФОИ из НМЦК…`)
**Актор:** Аналитик (Подрядчика)/Аналитик (ДИТ).
1. Вкладка «Задачи заявки» → выбрать задачу из НМЦК → «Заменить» → указать новую задачу/ФОИ → сохранить (исходное значение сохраняется, отображается группировкой).
**Исключения:** (a) у задачи есть связанные ФОИ/БП → блокировка замены с текстом сообщения; (b) чек-бокс «Заменить ФОИ» выключен → поля «ФОИ» и «Уточняющая часть» заблокированы; (c) удаление исходной задачи → каскадное удаление замены (блокируется при наличии ФОИ/БП у замены).
**Постусловие:** запись появляется в «Реестре замен ФОИ» по ГК; доступна выгрузка в Excel (пустой реестр → файл с заголовками).

## UC-05. Обоснование дублирующихся US (`БП — Проверка US не только в задачах заявки…`)
**Актор:** Аналитик (Подрядчика).
1. Добавляет задачи (US) в работу/заявку → система сравнивает US с задачами других заявок/работ ГК (включая работы без заявок и вкладки НМЦК).
2. При совпадении: строки подсвечены красным, сообщение «Добавлены задачи, присутствующие в предыдущих работах. Обоснуйте дублирование.», заполнение «Обоснование дублирования задачи» обязательно.
3. Сохранение блокируется до заполнения обоснования.
**Исключение:** исторические дубли проверяются только при изменении состава записей (не при просмотре) — DITINT-2272.

## UC-06. Проверка коэффициентов расчёта перед согласованием РП (`БП - Проверка заполненности НСИ…`)
**Акторы:** РП ДИТ, Администратор.
1. Расчёт в статусе «на согласовании у РП» → кнопка «Проверить коэффициенты расчета».
2. Выполняются проверки блоков «Создание/Развитие» и «Рефакторинг» (+ по подсистемам МТ1–МТ8) согласно BR-NSI-02/03.
3. Успех: кнопка зелёная, «Проверка выполнена успешно. Коэффициенты корректны».
**Исключения:** ошибки → модальное окно с перечнем недостающих данных (динамический текст, копирование, скролл) и кнопкой «Обратиться в ДИТ.Вопрос» (редирект в Telegram @dit_int_bot); перевод статуса РСЗ остаётся заблокированным даже после закрытия окна.

## UC-07. Выставление и выгрузка замечаний к РСЗ (`БП - Внедрение справочника замечаний к РСЗ`, `БП - Выгрузка замечаний к РСЗ`)
**Акторы:** Аналитик (ДИТ), Аналитик (Подрядчика).
1. Аналитик ДИТ переводит ФОИ в «Не согласовано» → модальное окно замечания (поле текста, «Применить»/«Отмена»).
2. Выгрузка замечаний: многошаговый мастер → две таблицы (замечания к ФОИ; общие комментарии); при нескольких итерациях — порядок от последней к первой.
3. Для согласованного РСЗ: специальные правила включения комментариев к согласованным ФОИ / только к РСЗ.

## UC-08. Создание служебного задания и внутренних работ (`БП - Карточка служебного задания (СЗ)`, `БП - Создание реестра _Внутренние работы_`, `БП - Создание статусной модели для СЗ…`)
**Акторы:** Руководитель проекта, Администратор НСИ, Администратор.
1. НСИ → «Служебные задания» → создать СЗ (статус «В работе» автоматически) → создать Этапы СЗ («В работе»).
2. Создать Внутреннюю работу («Черновик») → РП вносит задачи → «В работе» → по завершении → «Завершено».
3. Автоархивация: СЗ — через 60 календарных дней после «Завершено»; Этапы СЗ и Внутренние работы — в момент перевода связанного объекта в архив.
4. Внутри СЗ доступны те же операции задач/ФОИ/БП и замен из НМЦК, что и в заявках.
**Исключения:** удаление — только через «Корзину» с восстановлением; реализация контура — строго после статусной модели ГК-линейки.

## UC-09. Импорт Систем из ДИТ.НСИ (`БП - Доработка интеграции с ДИТ.НСИ…`)
**Акторы:** Система, Администратор.
1. Автономный цикл: получить данные НСИ → сравнить с БД Калькулятора → существующая Система обновляется полностью, новая создаётся → запись в журнал синхронизации.
2. Ручной импорт: кнопка → выбор типа идентификатора (краткое наименование / РИРС) → запрос → предпросмотр → подтверждение импорта.
**Исключения:** нецифровой РИРС → «Введен не корректный РИРС»; пустое поле → «Необходимо ввести …»; ошибка соединения → ретрай ×3 (интервал 10 мин) → уведомление администратору, статус цикла «Ошибка связи».

## UC-10. Инициация и согласование документа через СПУР (`БП_СП интеграция… СПУР…`)
**Акторы:** Аналитик (Подрядчика)/пользователь Калькулятора, Пользователь СПУР, Система.
1. **UC-1 (инициация):** пользователь нажимает «Перейти к формированию шаблона» → проверка статуса/обязательных полей/отсутствия запрета нового цикла → запрос в СПУР (calculatorDocumentId, тип/вид, предзаполненные поля, инициатор, correlationId) → создан новый экземпляр.
2. **UC-2 (дозаполнение/согласование):** пользователь СПУР заполняет поля и отправляет на согласование → СПУР валидирует → обратная синхронизация в Калькулятор (spurDocumentId, статус, все поля, время, correlationId) → Калькулятор сохраняет и блокирует функционал.
3. **UC-3 (откат):** событие отката из СПУР → снятие блокировки; новый цикл → новый экземпляр; старые экземпляры сохраняются, но не синхронизируются.
**Исключения:** A2 — нет прав на отправку; A3 — отклонение бизнес-валидации СПУР; таймаут API → «частично успешная операция» + автоповтор/ручное восстановление; E1 — Калькулятор недоступен → контроль рассинхронизации службой сопровождения; E3 — часть полей не сохранена → повторная полная синхронизация, запрет подтверждения частичного результата без явного правила.

## UC-11. Формирование децимального номера ЧТЗ/ПЗ/ПМИ (`БП - Заполнение децимального номера…`)
**Актор:** Аналитик (Подрядчика)/Администратор.
1. Открыть ЭФ формирования документа → система предзаполнила «Код организации разработчика» (ОГРН), «Номер ОКВЭД закупки», «Код документа» (ПТ/П2/ПМ).
2. Пользователь вручную вводит порядковый регистрационный номер системы (3 цифры 001–999) и необязательные поля; признак машинных носителей — только «М».
3. Сохранение → шифр собирается из 8 полей.
**Исключение:** нарушение ФЛК → поле не сохраняется до исправления; отсутствие ОКВЭД в ГК блокирует автозаполнение (поле обязательно при добавлении ГК).

## UC-12. Выгрузка ПОЗ с корректной ставкой НДС (`БП - изменение ставки НДС…`)
**Актор:** Аналитик (Подрядчика), Система.
1. Согласование расчёта завершено → скачивание ПОЗ → система выбирает шаблон (новая методика → 22%; старая → 20%; согласованные в 2025 по новой логике дат → 20%) → подстановка ставки в ПФ и РСЗ.
**Исключение (частные случаи ЭДО):** расхождение фактической даты согласования в ЭДО → изменение ставки только через обращение в СТП.

## UC-13. Работа с Базой знаний и онбординг (`БП - База Знаний Калькулятора`, `БП MVP1…`)
**Акторы:** Любой пользователь, Администратор.
1. Первый вход → автозапуск презентации обучения (кроме Администратора).
2. Разделы: база знаний (поиск, встроенный просмотр, переход в Confluence), руководства, обучающие сценарии (галерея «по статусам»/«по тематикам», прогресс карточек).
3. Администратор создаёт папки/статьи, назначает права по ролям; пользователь видит только разрешённое.
4. Если ответ не найден → обращение в службу технической поддержки / раздел «Помощь» (чат-бот, эскалация оператору).
**Исключения:** удаление непустой папки запрещено (ЭФ предупреждения); публикация новостей/управление — только Администратор.

## UC-14. Мониторинг бюджетов и сроков (`БП - Календарный план ГК/СЗ`, `БП - Создание дашборда _Бюджеты и закупки_`)
**Акторы:** РП, Руководитель направления/продукта, Администрация.
1. Открыть календарный план → увидеть этапы с датами, готовностью ОД, «днями до окончания» (расчёт по формуле BR-MISC-05, подсветка просрочек красным).
2. Дашборд «Бюджеты и закупки»: выбрать ИС → диаграммы бюджета (текущий/плановый/следующий год: средства в закупке / в ГК (выплачено/ожидает оплаты/остаток) / неиспользованный остаток лимита) → таблица этапов с днями до окончания.
3. Финансовые данные берутся из СПУ (сопоставление полей).

## UC-15. Планирование загрузки команды (`БП на реализацию диаграмм распределения сотрудников по проектам`)
**Акторы:** Администратор (управление данными), остальные (просмотр).
1. Открыть страницу диаграмм → карточки сводки (сотрудники с 1 проектом/несколькими, проекты без сотрудников, среднее число проектов, In-house, Outstaff).
2. Таблица по проектам: цветовая индикация строк (зелёный/жёлтый/красный), клик → детализация ФИО и долей (0,25/0,5/1).
3. Фильтр по ролям и типу занятости; агрегирующие столбцы считаются автоматически.

## UC-16. Публикация и просмотр новостей Telegram (`БП на вывод данных из ТГ канала`)
**Акторы:** Администратор (публикация), пользователи (просмотр).
1. Администратор публикует новость (текст + файлы) через интерфейс с валидацией прав.
2. Виджет на главной странице показывает последние сообщения (автообновление по интервалу, подгрузка при прокрутке); клик по карточке → переход в Telegram.
**Исключения:** ошибка API/сети → уведомление; нет прав → сообщение об ошибке публикации.

## UC-17. Комплектная выгрузка ЧТЗ с приложениями (`БП - При выгрузке ЧТЗ…`, `БП - Незаполненные данные…`)
**Актор:** Аналитик (Подрядчика)/Администратор.
1. Выгрузить ЧТЗ → предложение выгрузить архивом комплект (ЧТЗ + все БП из приложения).
2. В документах комплекта незаполненные поля и пустые таблицы выводятся как «undefined».

## UC-18. Переходы и навигация (`БП - Модернизация логики переходов…`, `БП - Добавить возможность перехода к ГК…`, `БП - Названия US сделать кликабельными`)
1. Из заявки/расчёта/ЧТЗ/ПЗ/Редактора ТЗ — кнопка «Перейти к карточке ГК» с сохранением истории (кнопка «Назад»).
2. Клик по названию US → карточка задачи MosTrek/M3.
3. ЭФ «Итерации» — переход за меньшее число действий; вкладка «Ресурсное планирование» — только РП ДИТ.
