# 07. Противоречия, допущения и открытые вопросы (Conflicts / Assumptions / Open Issues)

Раздел составлен по методу K. Wiegers: выявление конфликтов требований, двусмысленностей, допущений и пробелов. Все позиции подтверждены цитатами/фактами из файлов репозитория.

## 7.1. Конфликты (Contradictions между документами)

**C-1. Окно изменения статусов ФОИ относительно статуса РСЗ.**
- `БП - Изменение процесса работы с ФОИ внутри итераций`: блокировка изменения статусов ФОИ при статусе расчёта «Согласовано»; Аналитик ДИТ может менять статус согласованной ФОИ, пока расчёт ≠ «Согласовано».
- `БП — Изменение статуса ФОИ пока РСЗ на согласовании`: менять статус ФОИ можно, пока РСЗ находится на шаге **«Согласовано РП»** и до перехода в «Доработка»/«Согласовано».
- Формулировки задают разные границы разрешения (≠ «Согласовано» vs = «Согласовано РП»). Требуется арбитраж владельцев требований.

**C-2. Дублирование содержания двух БП.**
Функциональный блок «Проверка US не только в задачах заявки…» полностью продублирован в тексте `БП — Изменение статуса ФОИ пока РСЗ на согласовании` (разделы проблематики и решения совпадают). Неясно, какая из постановок является источником истины; риск реализации в разных циклах и расхождения детализации.

**C-3. Право редактирования карточки ГК у Администратора.**
`БП - Изменение логики заведения ГК v1 (архив)`: «Все поля в карточке ГК заблокированы для редактирования роли "Администратор"» — противоречит множеству других БП, где Администратор явно обладает полными правами редактирования и перевода статусов ГК (статусная модель, интеграции, откаты). Документ помечен архивным, но прямого опровержения нет.

**C-4. Периодичность обновления Telegram-виджета.**
В `БП на вывод данных из ТГ канала` встречаются три разных значения: «раз в 1–5 минут», «через установленный интервал (например, каждые 5–10 минут)», «раз в 10 минут». Итоговое значение не зафиксировано.

**C-5. Ставка НДС: два конкурирующих правила.**
В одной БП (`БП - изменение ставки НДС…`) одновременно заданы:
- правило по **дате согласования РСЗ** (2025 → 20%, 2026/несогласованные → 22%);
- правило п.8.1 по **типу методики** («для всех ПОЗ по новой методике независимо от даты — 22%; по старой — 20%»).
Для случая «новая методика + согласовано в 2025» два правила дают разные результаты (20% vs 22%). В источнике приоритет не определён.

**C-6. Определение термина «ФТ».**
В глоссариях документов ФТ трактуется как «Функциональные требования», «Функциональное требование» и «Функциональные точки» одновременно (см. 7.2). Это критично для правил сверки «Количество ФТ» (`БП - Разделение полей ФТ…`) и формулировок НМЦК.

**C-7. Посторонний фрагмент в БП о диаграммах.**
В `БП на реализацию диаграмм распределения сотрудников по проектам` присутствует абзац про «координаты объекта на карте в реестре имущественных торгов» — содержимое из другой предметной области (вероятно, ошибка копирования шаблона). Требует очистки перед использованием документа как спецификации.

**C-8. Непоследовательные наименования ролей.**
Одна и та же роль именуется по-разному в разных документах: «Аналитик (Подрядчика)» / «Аналитик Подрядчика» / «Подрядчик»; «РП ДИТ» / «Руководитель проекта (ДИТ)» / «Руководитель проектов» / «РП»; «Аналитик (ДИТ)» / «Аналитик ДИТ» / «Аналитик качества (ДИТ)» / «Аналитик Качества». Ни один документ не содержит итогового перечня ролей (матрица вынесена во внешний артефакт).

**C-9. Два разных документа про Базу знаний.**
`БП MVP1 _Создание модуля «База знаний»_ на основе функционала БЗ ДиС` и `БП - База Знаний Калькулятора` описывают пересекающийся функционал с разными акцентами (первая — структура папок/прав/Markdown; вторая — онбординг, обучающие сценарии, Confluence, помощь СТП). Не указано, какая из них первична и дополняют ли они друг друга.

**C-10. Статус «Отменено» у Закупки.**
Таблица статусной модели Закупки упоминает автоматический переход «В работе → Отменено», но строка статуса «Отменено» в таблице отсутствует; определение условий перехода не приведено.

## 7.3. Двусмысленности и усечённые формулировки (Ambiguities)

- **A-1.** Условия автопереходов в статусных моделях записаны неполно: «Автоматически при условии: Система сравнивает полученные дан…» (ГК), «Все Этапы связанные с ГК в статус…» (Исполнено), «если Stage Points/Name="Оплата по…» (Этап ГК), «Номер ГК = NULL И "Закупка от…"» (Закупка). Полные условия в источниках отсутствуют.
- **A-2.** «Оплачен» и «Оплачено» используются как разные написания одного статуса в таблице Этапа ГК.
- **A-3.** Списки ролей доступа к разделам Архива обрываются («Руководите…»), точный состав не восстановим из текста.
- **A-4.** Периодичность запроса новых ГК в ДИТ.НСИ: «раз в определённый период времени» — конкретное значение не указано.
- **A-5.** Размер модального окна: «по возможности реализовать динамический размер» — обязательность не определена.
- **A-6.** Формулировка «Статус РСЗ блокинуется» (опечатка) — неясно, означает ли блокировку перевода статуса или редактирования данных.
- **A-7.** В `БП - Незаполненные данные…` перечни полей для ПЗ/ПМИ частично оформлены как «Иные поля, для которых undefined заполнять не требуется» без раскрытия списка — граница применения правила размыта.
- **A-8.** Правило выгрузки замечаний: «комментарии от последней итерации к первой» + специальные случаи для согласованного РСЗ — алгоритм приоритета описан текстом без формальной матрицы.

## 7.5. Допущения источников (Assumptions, сделанные авторами БП)

1. Данные СПУ/Техпортала sufficiently полны для автозаполнения карточек ГК; при отсутствии — ручной ввод допускается (`Интеграция с СПУ/Тех. порталом`).
2. Синхронизация ДИТ.Мета ограничивается опубликованными и актуальными записями — unpublished структуры считаются недействительными для ОИО.
3. Ввод коэффициентов временно остаётся за Администратором «до передачи РП» — двойственная ответственность не урегулирована (`Изменение реестра подсистем`, `Разделение полей ФТ…`).
4. Согласованные в ЭДО документы являются внешним источником истины по дате фактического согласования (частные случаи НДС решаются вручную через СТП).
5. Пользователи подрядчика связаны с контрагентами в системе (выбор ответственного подрядчика из связанных пользователей).

## 7.6. Открытые вопросы (Open Issues)

- **OI-1.** Матрица ролей и полномочий многократно упоминается как отдельный артефакт, но отсутствует в репозитории — без неё нельзя верифицировать большинство прав доступа.
- **OI-2.** Не определены измеримые NFR (время отклика, ёмкость, SLA интеграций, RTO/RPO).
- **OI-3.** Не заданы правила миграции исторических данных при вводе статусных моделей (кроме частичного правила DITINT-2272).
- **OI-4.** Не определена судьба архивной версии БП заведения ГК v1: чем именно её заменяет v2 — перечислено неполно.
- **OI-5.** Для чата-ассистента «Помощь» не указаны: модель бота, SLA ответа оператора, хранение переписки.
- **OI-6.** Не определён источник данных для карточек «Проекты» (в отличие от Систем из НСИ) и правила их синхронизации с МосТреком.
- **OI-7.** Таблица «Реестр целевые показатели» ЧТЗ: требования к заполнению изменены, но финальная спецификация полей в извлечённом тексте неполна.
- **OI-8.** Не зафиксировано поведение при параллельном редактировании ФОИ двумя пользователями (in-line таблица) — конкурентность не описана ни в одной БП.
- **OI-9.** Правила округления стоимости (кроме чел.-мес. до 2 знаков) нигде не заданы; формат «4 475 580,36 ₽» встречается как пример без нормативного правила.
- **OI-10.** Не определён процесс отмены/возврата Закупки из «Отменено» (статус упомянут, но не описан).
