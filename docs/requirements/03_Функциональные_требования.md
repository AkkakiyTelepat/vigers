# 03. Функциональные требования (Feature List)

Требования сгруппированы по модулям. Идентификаторы FR даны для трассировки; источник — файл БП. Формулировки опираются на разделы «Требования к результату», «Функции системы», «Описание алгоритмов».

## 3.1. Модуль НСИ: Государственные контракты, Закупки, Этапы

**FR-NSI-01. Реестр «Закупки»** (`БП - Создание реестра _Закупки_`)
- Создать справочник «Реестр закупок» в разделе НСИ/Контракты и задания; доступ только для Администратора.
- Поля карточки: Наименование закупки (текст, обязательно); Ссылка на закупку в ПРГ (текст, обязательно, невалидируемая ссылка); Номер ГК (текст, необязательно, до 20 символов, валидация при сохранении).
- Уникальность: нельзя создать записи с идентичным наименованием и ссылкой; можно с одинаковым наименованием и разными ссылками; дубликаты пар (наименование+ссылка) запрещены.
- При заполнении «Номер ГК» автоматически создавать запись в реестре ГК со статусом «Черновик»; если номер уже есть в ГК — обновление записей не производится.
- Столбцы реестра: № п/п, Наименование закупки, Ссылка на закупку в ПРГ, Номер ГК, Статус закупки; сортировка по умолчанию — по статусу (В работе → Завершено → Корзина).

**FR-NSI-02. Статусные модели объектов НСИ** (`БП - Создание статусной модели для Закупки, ГК, Этапа ГК и Работа/Заявка`; `БП - Создание статусной модели для СЗ, Этапа СЗ и Внутренней работы`) — подробно описаны в файле `04_Бизнес_правила_ограничения.md`, §4.1–4.2 (статусные модели вынесены в бизнес-правила как наиболее детализированные требования).

**FR-NSI-03. Изменение логики заведения ГК v2** (`БП - Изменение логики заведения ГК v2`)
- В «Редактор ГК» добавить поля, автозаполняемые из СПУ по выбору номера ГК; при отсутствии сведений — ручной ввод.
- Сущность «Закупки» связывается с сущностью «Государственный контракт».
- Периодический запрос в ДИТ.НСИ о наличии новых ГК («раз в определённый период времени» — значение не указано).
- Чек-бокс активности функционального блока «Рефакторинг»: активен — блок отображается, неактивен — скрыт.
- Несоответствие обязательных полей требованиям блокирует перевод ГК в статус «На согласовании РП».

**FR-NSI-04. Переход к ГК по клику** (`БП - Добавить возможность перехода к ГК путем нажатия на его номер в Заявке/расчете`)
- Кнопка «Перейти к карточке ГК» должна присутствовать на ЭФ «Работа», «Расчет стоимости заявки», «ЧТЗ», «ПЗ», «Редактор ТЗ», «Реестр Государственные контракты».
- При переходе сохраняется история просмотренных ЭФ (кнопка «Назад»).

**FR-NSI-05. Реестр «Системы» + интеграция с ДИТ.НСИ** (`БП - Доработка интеграции с ДИТ.НСИ…`, `БП - Развитие карточки _Система_`)
- Автономное создание/обновление карточек Систем по данным НСИ: если Система найдена в БД Калькулятора — обновить все поля; если нет — создать новую запись.
- Ручной импорт конкретной карточки: выбор типа идентификатора («Краткое наименование Системы» или «РИРС») → запрос в НСИ → предпросмотр данных → подтверждение импорта.
- Валидации: РИРС — только цифры, иначе ошибка «Введен не корректный РИРС»; пустое поле ввода — ошибка «Необходимо ввести краткое наименование системы» / «Необходимо ввести РИРС»; при ошибке запроса отправка не выполняется.
- Журнал синхронизации: количество обработанных/обновлённых/добавленных записей, статус цикла («Успешно» / «Ошибка связи»).
- Карточка «Система»: развитие атрибутов (в т.ч. роли участников — рекомендация выбора из справочника ролей).

**FR-NSI-06. Объединённый реестр «Системы и Проекты»** (`БП — Объединение реестров _Реестр Системы_ и _Реестр Проекты_`)
- Единая таблица с колонкой «Тип» (Система/Проект), группировка по типу; неприменимые столбцы для типа — пустые ячейки (например, РИРС для Проекта, Дата начала проекта для Системы).
- Поиск, сортировка, пагинация по единому набору; пустой реестр — сообщение «Данные для отображения отсутствуют. Для создания новой записи, воспользуйтесь действием «Добавить»».
- Действия «Добавить» (выбор типа), редактирование, удаление с диалогом подтверждения (отмена — без изменений).

**FR-NSI-07. Реестр «Проекты»** (`БП - Развитие карточки _Проект_(не ИС)`)
- Новый объект НСИ «Проект» (не ИС) с карточкой и реестром; атрибуты участников с ролями; связь с работами/заявками.

**FR-NSI-08. Справочник «Тип работ»** (`БП - Создание справочника _Тип работ_ в ДИТ.Калькулятор`)
- Справочник из 2 полей, доступен только Администратору; автоматическое наполнение значениями из связанных карточек Работ (поле «Тип работ»).

**FR-NSI-09. Изменение реестра подсистем** (`БП - Изменение реестра подсистем`)
- Отображение коэффициентов трудоёмкости по методике 3-Р непосредственно в реестре подсистем редактора ГК (ЭФ «Коэффициенты для расчета по методике 3-Р»); подготовка к передаче ввода коэффициентов РП.

**FR-NSI-10. Разделение полей ФТ в подсистемах** (`БП - Разделение полей ФТ в подсистемах (на развитие и рефакторинг)`)
- Заменить общее «Количество ФТ в подсистеме» на два поля: «на развитие» и «на рефакторинг» (целые ≥ 0).
- При сохранении ЭФ «Коэффициенты для расчета по методике 3-Р» автоматически рассчитывать суммы ФТ по развитию/рефакторингу во вкладках «НМЦК по Заявке» и «НМЦК фиксированная стоимость» и сверять с полями подсистемы; несоответствие — уведомление, соответствие — «Данные успешно сохранены» + доступ к формированию расчёта/отчётных документов.
- Фильтрация реестра ГК по столбцу «Старая методика расчета» (Да/Нет).

**FR-NSI-11. Уровень языка разработки и фильтрация ФОИ** (`БП - Фильтрация ФОИ по low-code и типу методики`)
- В подсистемах ГК: обязательное поле «Уровень языка разработки» («сверхвысокий (Low-code)» / «высокий/низкий (не Low-code)»), по умолчанию — текущее значение; изменение синхронизируется со всеми связанными расчётами.
- Тип методики определяется галкой «Не учитывать изменения Методики 3-Р от 01.11.2023» в настройках ГК.
- Справочник ФОИ фильтруется автоматически: старая методика → только ФОИ с отметкой «Старая методика расчета»; новая → без отметки; плюс соответствие уровню языка разработки.
- Поля ручной фильтрации («Старая методика расчета», «Признак Low-code») удалены из интерфейса модального окна «Выбор из справочника».

**FR-NSI-12. Дорожная карта в карточке «Система»** (`БП - Создание вкладки _Дорожная карта_ для ЭФ _Система_`)
- Вкладка «Дорожная карта»: справочник дорожных карт и задач Jira; ручное добавление записей для Администратора и Администратора НСИ (ЭФ добавления/редактирования); интеграция с задачами МосТрек/Jira.

**FR-NSI-13. Вкладка «Бюджеты и закупки» в карточке «Система»** (`БП - Создание вкладки _Бюджеты и закупки_ в карточке _Системы_`)
- Консолидация бюджетов по Системе: закупки, ГК, лимиты; доступ для перечисленных ролей (см. 02 §2.3 п.8); реализация после внедрения СЗ/Внутренних работ.

## 3.2. Модуль «Работы/Заявки»: задачи, этапы, периоды

**FR-WORK-01. Вкладка «Задачи заявки»** (`БП - Реализация вкладки _Задачи заявки_`)
- Хранение перечня задач МосТрек (US), относящихся к заявке; привязка функций (ФОИ) и бизнес-постановок к задачам; контроль полноты покрытия задач расчётом.

**FR-WORK-02. Проверка US на дублирование** (`БП — Проверка US не только в задачах заявки, но и в работах без заявки`; `БП — Изменение статуса ФОИ пока РСЗ на согласовании` — содержит тот же функциональный блок)
- Система проверяет US на дублирование среди Заявок и Работ в рамках ГК (включая работы без заявок и вкладки «НМЦК по заявке», «Перечень ФОИ из НМЦК по этапу», «НМЦК фиксированная стоимость»).
- При совпадении: информационное сообщение «Добавлены задачи, присутствующие в предыдущих работах. Обоснуйте дублирование.», строки-дубликаты выделены красным, поле «Обоснование дублирования задачи» становится обязательным, поле «Дублируемая задача» заполняется ссылками на дублируемую сущность; сохранение блокируется до заполнения.
- Исторические дубли (созданные до внедрения проверки): обработка только при изменении состава записей (DITINT-2272); при чисто просмотровых действиях проверка не выполняется.
- Поля «Обоснование…» и «Дублируемая задача» редактируемы, если доступна основная сущность и у пользователя есть права.

**FR-WORK-03. Запрет дублей наименований работ** (`БП - Запрет возможности формирования двух работ с одинаковым наименованием по одному Этапу`)
- Алгоритм ФЛК при создании заявки: проверка наименования работы на дублирование в рамках одного ГК; запрет создания дубля.
- Ограничение длины поля «Номер заявки» — максимум 3 символа.

**FR-WORK-04. Ограничение периодов работ сроком этапа** (`БП - В интерфейсе РП периоды работы по всем заявкам в рамках одного этапа не могут быть дольше, чем срок этапа по ГК`)
- ФЛК на экранной форме добавления периодов работы: даты не могут выходить за срок этапа по ГК (пользователь не должен иметь возможности заполнить карточку «добавление периодов работы по заявке» датами, превышающими срок этапа).

**FR-WORK-05. Названия US кликабельны** (`БП - Названия US сделать кликабельными`)
- Прямой переход в карточку задачи MosTrek/M3 по клику на название US из карточки заявки и расчёта.

**FR-WORK-06. Модернизация переходов между ЭФ** (`БП - Модернизация логики переходов между экранными формами в расчетах`)
- Переход к ЭФ «Итерации» за меньшее число действий; новые кнопки навигации; вкладка «Ресурсное планирование» на ЭФ «Работа» (только РП ДИТ).

**FR-WORK-07. Корректировка интерфейса расчёта для РП** (`БП - Корректировка интерфейса расчета для РП`)
- Интерфейс карточки расчёта адаптирован под задачи РП (отображение сводных показателей, управление согласованием).

**FR-WORK-08. Размер команды** (`БП - Изменение блока _Размер команды_`)
- Два реестра: «Размер команды (по созданию/развитию)» и «Размер команды (по рефакторингу)»; условия отображения — наличие в актуальной итерации (или в согласованных функциях предыдущих итераций) хотя бы одной функции без признака рефакторинга / с признаком.
- Если есть оба вида функций — отображаются оба реестра; оба обязательны для заполнения при наличии; текст уведомления: «Необходимо заполнить блок - "Размер команды"».
- Редактирование значений доступно РП ДИТ в статусе «Согласование РП»; блокируется при переводе в «На согласовании аналитика».

## 3.3. Модуль расчётов стоимости (РСЗ, ФОИ, итерации)

**FR-CALC-01. Формирование РСЗ по заявке v2** (`БП - Формирование РСЗ по заявке (с функциями из НМЦК и/или прочими) v2`)
- Добавление ФОИ в расчёт из НМЦК и вручную; список ФОИ с полями; столбец «Стоимость» — только для Администратора; статусная workflow ФОИ расчёта.

**FR-CALC-02. Импорт ФОИ из Excel** (`БП - Добавить возможность загружать ФОИ из Excel в Калькулятор`)
- Загрузка файла Excel со списком ФОИ; парсинг системой и помещение на ЭФ «Итерация» так же, как при ручном заполнении.

**FR-CALC-03. In-line работа с таблицей ФОИ («как в Excel»)** (`БП - Работа с расчетами, как с таблицами в Excel`)
- Кнопка «Добавить пустую ФОИ» → мини-окно с обязательными полями «Подсистема» и «Функциональное требование» → создание записи со статусом «Черновик» и автозаполнением всех полей (Наименование, Тип ФОИ, Тип НМЦК, Признак low-code, НМЦК и др.) на основе типовой ФОИ, связанной с выбранным ФТ.
- В таблице редактируемыми являются только «Уточняющая часть наименования» и «Краткое описание»; in-line доступно только для статуса «Черновик»; для «В работе», «На согласовании», «Согласовано» — только через модальное окно.
- При переводе в статус «В работа» — валидация заполненности обоих полей; при пустых — запрет перевода и сообщение об ошибке.

**FR-CALC-04. Предзаполнение вкладки «Бизнес-постановки» в РСЗ** (`БП - предзаполнение вкладки _Бизнес-постановки_ в РСЗ`)
- Автоподтягивание БП из связанных задач; поле «Функциональное требование» заблокировано для автоперенесённых БП, редактируемо для добавленных вручную кнопкой «Добавить»; несколько БП на задачу; подсказка при наведении на иконку вопроса (текст приведён в источнике).

**FR-CALC-05. Замена ФОИ/ФТ из НМЦК** (`БП - замена ФОИ из НМЦК при согласовании Заявки`, `БП - Карточка служебного задания (СЗ)` — аналогичный функционал)
- Кнопка «Заменить» на вкладке «Задачи заявки», столбец «Задача из НМЦК», группировка исходной и новой задачи; сохранение ссылки на исходное значение.
- Блокировка замены, если у задачи есть связанные ФОИ и/или БП: «Замена задачи невозможна: в расчёт стоимости заявки внесены функции обработки информации и/или бизнес-постановки, связанные с данной задачей. Удалите…».
- Каскадное удаление: при удалении исходной задачи удаётся связанная новая; блокируется при наличии ФОИ/БП у новой задачи.
- Реестр замен ФОИ по ГК (кнопка «Реестр замен ФОИ») с выгрузкой в Excel; если замен нет — файл только с заголовками; печатная форма без изменений, если замен задач не было (DITINT-2261).
- Если чек-бокс «Заменить ФОИ» выключен — поля «ФОИ» и «Уточняющая часть наименования ФОИ» заблокированы, доступно только «Краткое описание».

**FR-CALC-06. Обновление данных в ОД при повторном копировании ФОИ из НМЦК** (`БП - Обновление данных в ОД при повторном копировании ФОИ из НМЦК`)
- Пользователи: Аналитик Подрядчика, Аналитик Качества; при повторном копировании ФОИ данные в отчётной документации обновляются корректно (без дублей/устаревания).

**FR-CALC-07. Проверка описания ФОИ из НМЦК ≥ 300 символов** (`БП - Проверка описания ФОИ из НМЦК на 300 символов`)
- Валидация минимальной длины описания ФОИ (300 символов) при использовании из НМЦК.

**FR-CALC-08. Статусы ФОИ с фиксированной стоимостью** (`БП - Статус ФОИ с фиксированной стоимостью`)
- Статусы: «Новый» → «На проверке» → «Согласовано» / «Не согласовано»; «На доработке» (при возврате); «Отклонено» (финальный, при отказе подрядчика).
- Переходы задаются матрицей «Из статуса → В статус → Кто может перевести» (см. 04 §4.4).
- Ответственный аналитик назначается администратором, один на весь перечень ФОИ фиксированной стоимости ГК; ответственный подрядчик выбирается из связанных с контрагентом пользователей.
- Массовые операции; хранение истории статусов; уведомления по email (шаблоны в источнике).

**FR-CALC-09. Перепривязка ФОИ к актуальной итерации** (`БП - Изменение процесса работы с ФОИ внутри итераций`)
- Таблица связей ФОИ–итерация; при согласовании ФОИ — удаление старой привязки и создание привязки к актуальной итерации (сохраняется ID актуальной итерации в атрибуте «ID итерации»); если ФОИ уже в актуальной итерации — перепривязка не выполняется.
- При создании новой итерации — массовая перепривязка всех согласованных ФОИ.
- Откат статуса расчёта из «Согласовано» блокирует изменение статусов ФОИ с сообщением: «Изменение статусов ФОИ недоступно. Расчёт находится в статусе 'Согласовано'. Для внесения изменений создайте обращение в СТП.»
- Откат статуса не создаёт новую итерацию автоматически; новая итерация создаётся только при переводе расчёта из «На согласовании» в «В работе» (при отклонении).
- Права: см. 02 §2.3 п.5–6.

**FR-CALC-10. Изменение статуса ФОИ пока РСЗ на согласовании (этап «Согласовано РП»)** (`БП — Изменение статуса ФОИ пока РСЗ на согласовании`)

- UC-3: откат согласования → событие отката → снятие блокировки; новый цикл создаёт новый экземпляр; старые экземпляры не удаляются, но исключаются из актуальной синхронизации.
- Исключения: A2 — нет прав на отправку; A3 — бизнес-валидация СПУР отклонила; таймаут/недоступность API → «частично успешная операция», восстановление связью вручную/автоповтором; E1 — Калькулятор недоступен при обратной синхронизации (контроль рассинхронизации службой сопровождения); E3 — часть полей не сохранена: запрет подтверждать частично успешную синхронизацию без явно определённого правила; повторная полная синхронизация.
- Требования: защита от повторной обработки одного сообщения и дублирующего создания экземпляров при техническом повторе; correlationId в каждом вызове; аудит.

- Диаграммы бюджета системы за текущий/плановый/следующий год в разрезе: средства в закупке; средства в ГК (выплаченные фактически / согласованные расчёты, ожидающие оплаты / остаток невыплаченного); неиспользованный остаток.

- Ролевая видимость данных; регулярность использования — ежедневно.

**FR-AN-04. Диаграммы распределения сотрудников по проектам** (`БП на реализацию диаграмм распределения сотрудников по проектам`)
- Страница: дашборд (карточки: сотрудники с 1 проектом; с несколькими; проекты без сотрудников; среднее число проектов на аналитика; In-house; Outstaff) + таблица с фильтрацией по всем столбцам.
- Широкая таблица ролей загрузки (Тимлид, Продуктовый аналитик по направлениям Отрасль/Экономика/Технологии, Бизнес-аналитик, Системный аналитик, Аналитик данных, Дизайнер) с разрезом In-house/Outstaff; агрегирующие столбцы считаются автоматически как сумма In-house + Outstaff; видимость столбцов зависит от выбранного фильтра сотрудников.
- Цветовая индикация строк: зелёный — один сотрудник на проекте; жёлтый — несколько; красный — нет сотрудников. Детализация по клику — ФИО и доли (0,25 / 0,5 / 1) + Outstaff.
- Примечание: в тексте БП встречается абзац про «координаты объекта на карте в реестре имущественных торгов» — он не относится к тематике Калькулятора (см. Conflict C-7).
