# 4. Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Цель:

Обеспечить полноту и корректность данных в нормативно-справочной информации (НСИ), используемой при расчете стоимости работ, с целью исключения ошибок в РСЗ из-за отсутствующих или незаполненных критических коэффициентов. Обоснование: В текущей практике расчёты в сервисе зависят от данных, вносимых сотрудниками СТП в НСИ. Отсутствие обязательных значений приводит к занижению или завышению стоимости работ, что создаёт риски: - подрыва доверия к системе как инструменту автоматизированного расчёта; - финансовых потерь и претензий со стороны подрядчиков; - необходимости ручной перепроверки формул вне системы. Факт выявления ошибки подрядчиком путём ручного расчёта свидетельствует о недостаточности контроля на стороне системы. Внедрение проверки заполненности необходимых полей НСИ перед выполнением расчёта позволит предотвращать формирование некорректных РСЗ и обеспечит надёжность и репутацию сервиса как достоверного инструмента расчёта.

4.2. Описание проблем и решения

В ходе расчёта стоимости работ подрядчик выявил занижение итоговой суммы из-за неполного заполнения НСИ - ряда критически важных коэффициентов, необходимых для корректной работы алгоритма расчёта. Поскольку доступ к заполнению НСИ имеют только сотрудники СТП, подрядчик не может проверить или дополнить данные. Ошибка была обнаружена лишь при ручном пересчёте по формулам, что указывает на отсутствие в системе механизма контроля полноты входных данных.

Решение: Внедрить автоматическую проверку заполненности полей НСИ, используемых в расчёте РСЗ. Проверка должна выполняться перед согласованием расчёта: при обнаружении пустых значений в НСИ, участвующих в расчете РСЗ, система блокирует перевод статуса РСЗ и уведомляет пользователя о невозможности отправки РСЗ на согласование и необходимости заполнить недостающие данные в НСИ администратором. Это исключит возможность генерации некорректных расчётов и обеспечит достоверность результатов.

# 8. Функции системы

8.1 Развитие ЭФ Итераций в части добавления кнопки "Проверить коэффициенты расчета" для расчетов в статусе "На согласовании у РП"

Для расчетов в статусе "на согласовании у РП" необходимо реализовать кнопку "Проверить коэффициенты расчета", кнопка должна отображаться на месте кнопок "Расчет стоимости заявки" и "Протокол стоимости заявки", которые не активны для расчетов в данном статусе (рис. 6).

Кнопка должна отображаться пользователям с ролями РП ДИТ и Администратор. По умолчанию цвет кнопки - серый, после успешной проверки цвет кнопки должен меняться на зелёный, а пользователю должно отображаться уведомление: "Проверка выполнена успешно.Коэффициенты корректны"

При нажатии кнопки должны запускаться алгоритмы проверки, описанные в пунктах 8.2-8.4.

Перевод расчета из статуса "на согласовании у РП" в статус "на согласовании аналитика" должен быть заблокирован для роли РП ДИТ, до момента пока пользователь не нажмет на кнопку "Проверить коэффициенты расчета". При этом при попытке пользователя изменить статус расчета до запуска проверки, должно появляться всплывающее уведомление с текстом " Для перевода статуса необходимо проверить коэффициенты расчета, нажмите кнопку "Проверить коэффициенты расчета" ".

При наведении мыши на иконку подсказки на кнопке "Проверить коэффициенты расчета", должна появляться подсказка с текстом: "Кнопка запускает алгоритм проверки корректности заведения коэффициентов для данного расчета в НСИ Калькулятора. Пожалуйста, нажмите на кнопку перед переводом расчета на согласование аналитику".

8.2 Создание функции проверки (контроля), которые не приводят к изменению данных в части проверки заполнения параметром НСИ для РСЗ в части ФОИ по развитию (созданию)

Условие активации проверки. Логика алгоритма:

- В составе ФОИ в заявке РСЗ есть хотя бы одна функция с признаком «рефакторинг» = false (т.е. работа по созданию/развитию).
- Если все функции имеют признак рефакторинга (true) - данная проверка не выполняется.

Проверяемые данные: Система должна проверить наличие и корректность следующих полей в разделе: Реестр «Государственные контракты» → Вкладка «Доп. сведения по ГК» → Блок «Создание/Развитие» (рис. 1):

- Стоимость 1 чел-мес работ по созданию / развитию Системы, руб
- Итого количество функц. точек на создание / развитие Системы
- Общие расчетные трудозатраты на создание / развитие Системы

Значения перечисленных полей не должны быть равны 0.

Проверяется значение коэффициента пересчета (перерасчета):

- Значение должно быть больше 0 и не превышать 1.

Поведение системы при выявлении ошибок: Если хотя бы одно из проверяемых полей пустое/нулевое или коэффициент вне допустимого диапазона:

- Отображается модальное уведомление (рис. 3).
- Статус РСЗ блокинуется .

Алгоритм проверки должен активироваться при нажатии на кнопку "Проверить коэффициенты расчета" (рис. 6)

8.4 Создание функции проверки (контроля), которые не приводят к изменению данных в части проверки заполнения параметром НСИ для РСЗ в части ФОИ по рефакторингу

Условие активации проверки Логика алгоритма:

- В составе ФОИ в заявке РСЗ есть хотя бы одна функция с признаком «рефакторинг» = true.
- Если все функции имеют признак рефакторинга (false) - данная проверка не выполняется.

Проверяемые данные: 1) Общие поля (в реестре «Государственные контракты») Раздел: «Доп. сведения по ГК» → Блок «Рефакторинг» (рис. 2.1):

- Стоимость 1 чел-мес работ по рефакторингу функций Системы, руб
- Итого количество функц. точек на рефакторинг функций Системы
- Общие расчетные трудозатраты на рефакторинг функций Системы

Все значения должны быть ненулевыми и не пустыми.

2) Поля по подсистемам (в реестре «Подсистемы» в карточке подсистемы в блоке: «Коэффициенты для расчета по Методике 3-Р» для выбранного ГК (рис. 2.2).

Для каждой подсистемы, функции которой добавлены в РСЗ, должны быть заполнены:

- Уровень языка разработки
- Коэффициент переписывания программного кода
- Количество ФТ в подсистеме
- Коэффициенты трудоёмкости (МТ1–МТ8):

Должно быть ровно 8 записей - по одному коэффициенту от МТ1 до МТ8. Не допускаются:

- Отсутствие любого из типов,
- Значения null или 0.

Поведение системы при выявлении ошибок: Если хотя бы одно из проверяемых полей не заполнено, имеет нулевое значение или нарушена структура коэффициентов:

- Отображается модальное уведомление (рис. 4).
- Статус РСЗ остаётся прежним.

Алгоритм проверки должен активироваться при нажатии на кнопку "Проверить коэффициенты расчета" (рис. 6).
