# 4. Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Цель:

Обеспечить полноту и корректность данных в нормативно-справочной информации (НСИ), используемой при расчете стоимости работ, с целью исключения ошибок в РСЗ из-за отсутствующих или незаполненных критических коэффициентов. Обоснование: В текущей практике расчёты в сервисе зависят от данных, вносимых сотрудниками СТП в НСИ. Отсутствие обязательных значений приводит к занижению или завышению стоимости работ, что создаёт риски: - подрыва доверия к системе как инструменту автоматизированного расчёта; - финансовых потерь и претензий со стороны подрядчиков; - необходимости ручной перепроверки формул вне системы. Факт выявления ошибки подрядчиком путём ручного расчёта свидетельствует о недостаточности контроля на стороне системы. Внедрение проверки заполненности необходимых полей НСИ перед выполнением расчёта позволит предотвращать формирование некорректных РСЗ и обеспечит надёжность и репутацию сервиса как достоверного инструмента расчёта.

4.2. Описание проблем и решения

В ходе расчёта стоимости работ подрядчик выявил занижение итоговой суммы из-за неполного заполнения НСИ - ряда критически важных коэффициентов, необходимых для корректной работы алгоритма расчёта. Поскольку доступ к заполнению НСИ имеют только сотрудники СТП, подрядчик не может проверить или дополнить данные. Ошибка была обнаружена лишь при ручном пересчёте по формулам, что указывает на отсутствие в системе механизма контроля полноты входных данных.

Решение: Внедрить статусную модель для сущности ГК. Внедрить автоматическую проверку заполненности полей НСИ, используемых в расчёте РСЗ.

8.1 Развитие модального окна "Добавление ГК" в части добавления поля "Тип работ по ГК"

Необходимо доработать модальное окно "Добавление ГК" добавлением нового поля "Тип работ по ГК" (рис. 2). Поле должно быть обязательно для заполнения и содержать 3 справочных значения доступных пользователю для выбора:

- Создание/Развитие
- Создание/Развитие + Рефакторинг
- Рефакторинг

Новые поля:

| Наименование поля | Логика заполнения | Тип данных | Обязательность |
|---|---|---|---|
| Тип работ по ГК | Заполняется пользователем справочными значениями из модального окна, открывающегося при нажатии на соответствующий элемент | Справочные значения: Создание/Развитие Создание/Развитие + Рефакторинг Рефакторинг | Да |

При написании СП, необходимо учесть, что для реализации доработки потребуется создание справочника типов работ по ГК

8.3 Создание алгоритмов ФЛК для полей вкладки "Доп. сведения" в редакторе ГК

Необходимо создать алгоритмы ФЛК для полей блоков "Создание/Развитие" и "Рефакторинг" во вкладке "доп. сведения по ГК" в ЭФ "Редактор ГК". ФЛК должен быть установлен на разные поля в зависимости от значения указанного в поле "Тип работ по ГК" при создании ГК.

Суть работы алгоритма:

1) ФЛК при указанном типе работ по ГК "Создание/Развитие":

Поля:

- Стоимость 1 чел-мес работ по созданию / развитию Системы, руб
- Итого количество функц. точек на создание / развитие Системы
- Общие расчетные трудозатраты на создание / развитие Системы

Значения перечисленных полей не должны быть равны 0 или пустыми.

- коэффициент пересчета:

Значение должно быть больше 0 и не превышать 1.

2) ФЛК при указанном типе работ по ГК "Рефакторинг":

Поля:

- Стоимость 1 чел-мес работ по рефакторингу функций Системы, руб
- Итого количество функц. точек на рефакторинг функций Системы
- Общие расчетные трудозатраты на рефакторинг функций Системы

Значения перечисленных полей не должны быть равны 0 или пустыми.

3) ФЛК при указанном типе работ по ГК " Создание/Развитие + Рефакторинг ":

Поля:

- Стоимость 1 чел-мес работ по созданию / развитию Системы, руб
- Итого количество функц. точек на создание / развитие Системы
- Общие расчетные трудозатраты на создание / развитие Системы
- Стоимость 1 чел-мес работ по рефакторингу функций Системы, руб
- Итого количество функц. точек на рефакторинг функций Системы
- Общие расчетные трудозатраты на рефакторинг функций Системы

Значения перечисленных полей не должны быть равны 0 или пустыми.

- коэффициент пересчета:

Значение должно быть больше 0 и не превышать 1.

Результат работы алгоритма:

В случае если значение хотя бы одно из перечисленных выше полей не соответствует описанным требованиям:

- Перевод ГК в статус "На согласовании РП" блокируется
- Пользователю высвечивается всплывающая системная ошибка

Текст ошибки:

1) Для ГК с типом работ "Создание/Развитие" :

"Необходимо заполнить блок информации "Создание/развитие" на вкладке "Доп. сведения по ГК""

2) Для ГК с типом работ "Рефакторинг" :

"Необходимо заполнить блок информации "Рефакторинг" на вкладке "Доп. сведения по ГК""

2) Для ГК с типом работ "Создание/Развитие + Рефакторинг" :

"Необходимо заполнить блоки информации: "Создание/развитие" и "Рефакторинг" на вкладке "Доп. сведения по ГК""
