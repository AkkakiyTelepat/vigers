# 4. Цель и концепция решения

4.1. Цели и обоснование необходимости развития

Целью выполнения работ, необходимых для реализации функционального требования является реализация выбора руководителем проекта задач, включенных в заявку и затрагивает вкладку "Задачи заявки".

Задачи заявки предназначены для выполнения следующих задач:

- Привязка руководителем проекта задач из МосТрека к заявке;
- Выгрузка заявки по установленному шаблону;
- Привязка функций в РСЗ к задачам из вкладки "Задачи заявки";
- Загрузка БП в РСЗ в рамках задач из вкладки "Задачи заявки"
- Проверка добавления функций в РСЗ для каждой задачи заявки;
- Проверка добавления БП для каждой задачи заявки.

4.2. Описание проблем и решения

Не все задачи заявки попадают в РСЗ и ОД. В связи с этим необходимо вывести список задач по заявке для отдельного контроля и проверки.

# 6. Автоматизация бизнес-процессов

Текущий бизнес - процесс "Создание расчета стоимости" as-is:

Описание процесса:

Процесс инициируется, когда Руководитель проекта ДИТ вносит в систему информацию об этапе государственного контракта . На основании этих данных аналитик подрядчика создает заявку, заполняя сведения об ответственных лицах и закрепленном руководителе проекта от ДИТ. После формирования заявки аналитик подрядчика приступает к расчету ее стоимости: добавляет функции обработки информации в расчетную итерацию, прикрепляет соответствующие бизнес-постановки, обосновывающие включенные функции, и направляет расчет на согласование РП ДИТ.

РП ДИТ, в свою очередь, указывает в заявке периоды выполнения работ, бюджет, количество задействованных сотрудников подрядчика, а также назначает ответственного за проект аналитика ДИТ. При проверке расчета руководитель учитывает цветовые индикаторы трудоемкости и принимает решение о его статусе. Если расчет содержит недочеты, РП ДИТ переводит его в статус «На доработку», после чего аналитик подрядчика вносит необходимые корректировки в ФОИ и повторно направляет документ на согласование. Если замечаний нет, расчет переводится в статус «На согласовании аналитика».

Далее аналитик ДИТ проверяет соответствие внесенных ФОИ прикрепленным бизнес-постановкам. Если расчет корректен, он последовательно согласовывает каждую ФОИ, а затем весь документ, переводя его в статус «Согласовано». При наличии замечаний аналитик ДИТ отклоняет соответствующие ФОИ (статус «На доработку») с указанием причины. Аналитик подрядчика вносит правки и вновь направляет расчет на проверку РП ДИТ.

Если РП ДИТ согласен с внесенными изменениями, он переводит расчет в статус «На согласование аналитика» для повторной проверки. В случае несогласия документ возвращается на доработку.

После согласования расчетно-сметной документации (РСЗ) становятся доступными для выгрузки ПОЗ и РСЗ, которые могут быть скачаны любым пользователем, имеющим доступ к данному ГК. Одновременно для аналитика подрядчика открывается возможность выгрузки ЧТЗ, который вместе с ПЗ и ПМИ становится доступен для заполнения после создания РСЗ. После согласования ЧТЗ становятся доступны для выгрузки ПЗ и ПМИ, а их заполнение и проверка завершаются переводом статуса документов в «Готово».

Бизнес - процесс "Создание расчета стоимости" to-be:

Процесс после доработки (изменения выделены жирным шрифтом):

# 8. Функции системы

8.1 Создание функции ввода информации пользователем через интерфейс системы на вкладке "Задачи заявки" на  ЭФ "Работа".

Необходимо разработать вкладку "Задачи заявки" на ЭФ "Работа".

Путь до ЭФ: главная - расчет по методике 3-Р- Работы (Заявки) - ЭФ "Работа" - вкладка "Задачи заявки"

Макет вкладки "Задачи заявки" представлен на рисунке 1.

Форма разрабатывается с целью контроля и проверки попадания всех задач заявки в РСЗ и ОД.

Логика работы вкладки:

- Пользователь с ролью "РП ДИТ" будет добавлять на данную вкладку задачи заявки и удалять их при необходимости. Данная возможность также должна быть доступна администратору.
- Должна быть создана возможность сформировать печатную форму заявки, скачать которую могут пользователи с ролями "РП ДИТ", "Аналитик ДИТ", "Аналитик подрядчика" и администратор.
- Просматривать ЭФ могут пользователи с ролями "РП ДИТ", "Аналитик ДИТ", "Аналитик подрядчика" и администратор.

В верхней части вкладки "Задачи заявки" необходимо создать кнопки "Добавить", "Удалить" и "Скачать заявку":

- Кнопка "Добавить" будет доступна пользователю с ролью "РП ДИТ" и администратору. По нажатию кнопки должно открываться модальное окно "Справочник задач" (п.8.2 постановки);

Поле "Дата заявки (ЭДО)" должно быть редактируемым для пользователя с ролью "РП ДИТ". (выбор из календаря или ввод даты с клавиатуры)

Поле "РП от ДИТ" должно заполняться автоматически - Фамилией и именем пользователя , который создал работу (заявку) (так как теперь создать работу по заявке может только РП).

Поле "Сотрудник от подрядчика" должно быть доступно для редактирования пользователю с ролью Аналитик подрядчика.

Проверку заполнения "Ответственные лица по заявке" необходимо изменить:

В текущей реализации она выполняется при попытке сохранить изменения в карточке заявки (работы).

Поскольку теперь изначально РП будет заполнять задачи заявки. То событие для запуска проверки необходимо изменить:

1. Пользователь изменяет статус РСЗ на "Согласование РП"
2. Система выполняет проверку заполнения вкладки "Ответственные лица по заявке"

2.1 Если поля "Сотрудник подрядчика" и "Сотрудник заказчика" на вкладке "Ответственные лица по заявке"  заполнены - система переводит статус расчета

2.2 Если поля "Сотрудник подрядчика" и "Сотрудник заказчика" на вкладке "Ответственные лица по заявке" не заполнены - система выводит предупреждение (рисунок 14) и не переводит статус.

8.12 Создание функции проверки (контроля), которые не приводят к изменению данных в части проверки наличия задачи US  в других заявках

Необходимо реализовать проверку добавления  для каждой задачи, добавленной на вкладку "Задачи заявки".

Описание проверки:

1. Пользователь добавляет задачи на вкладку "задачи заявки".
2. Система выполняет проверку, что в других заявках текущего ГК, во вкладке "Задачи заявки" отсутствуют добавленные пользователем задачи.

2.1 Если хотя бы одна из добавленных задач присутствует в хотя бы одной иной заявке текущего ГК во вкладке "Задачи заявки" - Система выводит статичное уведомление с текстом: " Обратите внимание, добавлены задачи, присутствующие в предыдущих заявках! " и активирует чек-бокс "Наличие в других заявках" в строке с соответствующей задачей/задачами.

Макет уведомления представлен на рисунке 14.

Текст уведомления не должен пропадать до тех пор, пока в реестре присевает хотя бы одна задача с активным признаком "Наличие в других заявках".
