# 4. Цель и концепция решения

4.1. Цели и обоснование необходимости развития

В данный момент в ДИТ.Калькулятор присутствует возможность работы только по Государственным контрактам (работа через Подрядчиков) и нет функционала по работе в рамках Служебных заданий (реализация доработок внутренними силами ДИТ).

Для решения данной проблемы необходимо доработать ДИТ.Калькулятор в части создания Служебного задания и доработки сопутствующих сущностей для реализации процесса работы со Служебным заданием в ДИТ.Калькулятор

## 7.2. [Описание алгоритмов]

7.2.1 Алгоритм автоматического формирования реестра "План мероприятий" при создании "Внутренней работы".

При создании карточки "Внутренняя работа" необходимо автоматически формировать и наполнять строками реестр "План мероприятий" в карточке "Внутренняя работа" на вкладке "План мероприятий".

1. Система определяет значение поля "Подтип работы" и значения поля "Обязательность"(Если значение = ДА)

2.1 Система создает на вкладке "План мероприятий" реестр "План мероприятий"

2.2 Система наполняет реестр карточками(строками) "Мероприятие" в соответствии со значениями справочника "Мероприятие"

2.3 Система рассчитывает значение поля "Плановая дата завершения Мероприятия"(алгоритм описан в пункте 7.2.2)

2.4 Система отображает реестр "План мероприятий"(для "Подтипа работ" = "Внутренняя работа")

7.2.2 Алгоритм определения формулы для расчета значения в поле "Плановая дата завершения Мероприятия".

Реестр "План мероприятий" заполняется справочными значениями(НСИ) из справочника "Мероприятия" в соответствии со значением указанным в поле "Подтип работы" на форме "Создание работы".

1.Системам определяет значение поля "Признак расчета". Если значение="Начало этапа", то система при расчете значения поля "Плановая дата завершения Мероприятия" использует значение в поле "Плановая дата начала"(сущности Этап ГК, который соответствует сущности Работа в которой создается мероприятие) переходим к шагу 2.1. Если значение="Окончание этапа", то система при расчете значения поля "Плановая дата завершения Мероприятия" использует значение в поле "Плановая дата окончания"(сущности Этап ГК, который соответствует сущности Работа в которой создается мероприятие)  переходим к шагу 3.1.

2.1 Система определяет значение поля "Операция". Если значение="Вычитание", то система при расчете значения поля "Плановая дата завершения Мероприятия" использует операцию "Вычитание" переходим к шагу 2.2. Если значение="Сложение", то система при расчете значения поля "Плановая дата завершения Мероприятия" использует операцию "Сложение" переходим к шагу 2.3.

2.2 Система производит расчет значения для поля "Плановая дата завершения Мероприятия" с использованием операции "Вычитание" по формуле: "Значение поля "Плановая дата начала"(сущности Этап ГК)" - "Значение поля "Кол-во дней"(сущности Мероприятие)"

2.3 Система производит расчет значения для поля "Плановая дата завершения Мероприятия" с использованием операции "Сложение" по формуле: "Значение поля "Плановая дата начала"(сущности Этап ГК)" + "Значение поля "Кол-во дней"(сущности Мероприятие)"

3.1 Система определяет значение поля "Операция". Если значение="Вычитание", то система при расчете значения поля "Плановая дата завершения Мероприятия" использует операцию "Вычитание" переходим к шагу 3.2. Если значение="Сложение", то система при расчете значения поля "Плановая дата завершения Мероприятия" использует операцию "Сложение" переходим к шагу 3.3.

3.2 Система производит расчет значения для поля "Плановая дата завершения Мероприятия" с использованием операции "Вычитание" по формуле: "Значение поля "Плановая дата окончания"(сущности Этап ГК)" - "Значение поля "Кол-во дней"(сущности Мероприятие)"

3.3 Система производит расчет значения для поля "Плановая дата завершения Мероприятия" с использованием операции "Сложение" по формуле: "Значение поля "Плановая дата окончания"(сущности Этап ГК)" + "Значение поля "Кол-во дней"(сущности Мероприятие)"

7.2.3 Алгоритм расчёта значения поля «Готовность мероприятия»

Поле «Готовность мероприятия» отображает процент завершённости мероприятия на основе статусов привязанных документов (ОД и СД).

1. Система определяет общее количество документов, привязанных к мероприятию (включая ОД и СД).
2. Система подсчитывает количество документов со статусом «Подписано».
3. Система рассчитывает процент готовности по формуле: «Готовность» = (Количество документов со статусом «Подписано» / Общее количество документов) × 100.
4. Если все документы имеют статус «Подписано», система устанавливает флаг «Готовность мероприятия» = Готово.
5. Если хотя бы один документ не подписан, флаг «Готовность мероприятия» = В работе.
