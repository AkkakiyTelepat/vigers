# 4. Цель и концепция решения

4.1.   Цели и обоснование необходимости развития

Целью является создание общей формы просмотра для реестров Систем и Проектов. Записи из обоих реестров будут отображаться в одной таблице с общими столбцами, при этом структура базы данных и раздельное хранение записей сохранятся без изменений.

Сейчас Системы и Проекты отображаются в качестве двух отдельных реестрах, на разных вкладках, у каждого свой набор столбцов. Чтобы найти нужную запись, пользователю приходится переключаться между вкладками. При поиске записи по названию, если тип неизвестен, пользователь вынужден проверять данные в каждом реестре.

4.2.   Описание проблем и решения

Реализация позволит пользователю видеть все Системы и Проекты в одном списке, искать и фильтровать записи по любому из общих столбцов, не переключаясь между вкладками. При этом сохранится возможность просматривать и фильтровать список, оставляя только Системы или только Проекты.

# 7. Пользовательский сценарий (путь)

1. Сценарий просмотра объекта "Реестр Систем и Проектов"

Предусловие: пользователь авторизован в системе, имеет доступ к объекту (подробнее: Матрица ролей и полномочий ) и находится на главной странице.

1. Пользователь нажимает на кнопку главного меню.
2. Система отображает раскрывшееся меню с доступными разделами.
3. Пользователь выбирает раздел "НСИ".
4. Система отображает список доступных подразделов.
5. Пользователь выбирает подраздел "Реестр Систем и Проектов".
6. Система запрашивает данные из таблиц "Реестр Системы" и "Реестр Проекты" в базе данных.
7. Система формирует единый список записей и структуру таблицы со столбцами: Тип записи, Наименование, Краткое наименование, Назначение, Код проекта в Jira, РИРС, Дата начала проекта, Последнее обновление карточки.
8. Для каждой строки система определяет Тип записи ("Система" или "Проект").
9. Система заполняет столбцы данными из соответствующего исходного реестра. Если столбец не применим к типу записи (например, РИРС – для Проекта, Дата начала проекта – для Системы), система оставляет ячейку пустой.
10. Система отображает пользователю вкладку "Реестр Систем и Проектов" со сформированной таблицей.

Исключения и ошибки:

8. Если ни в одном из реестров нет записей, система выводит пустую таблицу с информационным сообщением "Данные для отображения отсутствуют. Для создания новой записи, воспользуйтесь действием «Добавить»".

2. Сценарий фильтрации записей "Реестр Систем и Проектов"

Предусловие: пользователь авторизован в системе, имеет доступ к объекту (подробнее: Матрица ролей и полномочий ) и находится на вкладке "Реестр Систем и Проектов", список загружен.

1. Пользователь вводит значение в строку фильтра под нужным столбцом (Наименование, Краткое наименование, Назначение, Код проекта в Jira, РИРС, Дата начала проекта, Последнее обновление карточки) или выбирает значение в фильтре столбца "Тип записи" (Все/Система/Проект).
2. Система фильтрует список, оставляет только записи, соответствующие всем заданным условиям фильтрации одновременно.
3. Система обновляет счётчик количества найденных записей.
4. Система отображает отфильтрованный список пользователю.

Исключения и ошибки:

2. Если совпадений не найдено, система выводит пустую таблицу с информационным сообщением "Данные для отображения отсутствуют. Для создания новой записи, воспользуйтесь действием «Добавить»".

4. Пользователь может очистить фильтры и вернуться к полному списку.

2.1. Сценарий сброса фильтров в объекте "Реестр Систем и Проектов"

Предусловие: пользователь авторизован в системе, имеет доступ к объекту (подробнее: Матрица ролей и полномочий ) и находится на вкладке "Реестр Систем и Проектов", применены один или несколько фильтров.

1. Пользователь выбирает необходимый столбец и в поисковой строке нажимает кнопку "Очистить значение".
2. Система очищает установленные значения фильтра.
3. Система отображает список записей без учёта ранее применённых условий фильтрации.

Исключения и ошибки:

1. Для сброса всех фильтров сразу необходимо нажать кнопку "Обновить".

2.2. Сценарий пагинации в объекте "Реестр Систем и Проектов"

Предусловие: пользователь авторизован в системе, имеет доступ к объекту (подробнее: Матрица ролей и полномочий ) и находится на вкладке "Реестр Систем и Проектов", общее количество записей превышает значение, установленное для отображения на одной странице.

1. Система отображает записи постранично.
2. Пользователь переключается между страницами с помощью элементов навигации (вперёд/назад, по номеру страницы).
3. Пользователь выбирает количество записей для отображения на одной странице из выпадающего списка (например, 10, 25, 50, 100).
4. Система обновляет отображение списка в соответствии с выбранными параметрами пагинации.
5. Система отображает общее количество записей и текущий диапазон отображаемых записей (например, 1–50 из 281).

Исключения и ошибки:

1. Если в реестре нет записей, элементы пагинации не отображаются, система выводит пустую таблицу с информационным сообщением "Данные для отображения отсутствуют. Для создания новой записи, воспользуйтесь действием «Добавить»".
2. При ручном вводе номера страницы система не позволяет указать значение, превышающее общее количество страниц.

2.3. Сценарий сортировки записей в объекте " Реестр Систем и Проектов"

Предусловие: пользователь авторизован в системе, имеет доступ к объекту (подробнее: Матрица ролей и полномочий ) и находится на вкладке "Реестр Систем и Проектов", список загружен.

1. Пользователь нажимает на заголовок столбца, по которому необходимо отсортировать записи (Тип записи, Наименование, Краткое наименование, Назначение, Код проекта в Jira, РИРС, Дата начала проекта, Последнее обновление карточки).
2. Система сортирует список по выбранному столбцу в порядке возрастания.
3. Система обновляет список.
4. Пользователь повторно нажимает на заголовок.
5. Система меняет порядок сортировки на убывание.
6. Система визуально отображает направление сортировки (например, стрелкой вверх/вниз рядом с названием столбца).
7. Система обновляет список.

Исключения и ошибки:

2. Если в реестре нет записей, сортировка не выполняется, система сохраняет пустую таблицу с сообщением "Данные для отображения отсутствуют. Для создания новой записи, воспользуйтесь действием «Добавить»".

3. Сценарий перехода в карточку Системы/Проекта в объекте "Реестр Систем и Проектов"

Предусловие: пользователь авторизован в системе, имеет доступ к объекту (подробнее: Матрица ролей и полномочий ) и находится на вкладке "Реестр Систем и Проектов", список загружен.

1. Пользователь нажимает на строку с записью.
2. При клике на строку с записью типа "Система" система открывает экранную форму карточки Системы с данными выбранной записи; при клике на запись типа "Проект" – карточку Проекта.

4. Сценарий добавления записи

Предусловие: пользователь авторизован в системе, имеет доступ к объекту и соответствующие разрешения (подробнее: Матрица ролей и полномочий) и находится на вкладке "Реестр Систем и Проектов", список загружен.

1. Пользователь нажимает кнопку "Добавить".
2. Система открывает модальное окно с выбором типа записи: "Система" или "Проект".
3. Пользователь выбирает тип записи.
4. Система открывает модальное окно с соответствующей формой (редактор карточки Системы или редактор карточки Проекта).
5. Пользователь заполняет поля и сохраняет запись.
6. Система создает запись в соответствующей таблице исходного реестра.
7. Система обновляет список, новая запись отображается в таблице.

Исключения и ошибки:

5. Если пользователь не заполнил обязательные поля, система блокирует сохранение и выводит информационное сообщение об обязательности заполнения полей.

5. Если пользователь нажимает кнопку "Отмена" или закрывает модальное окно, система закрывает форму без сохранения изменений.

5. Система обновляет запись в соответствующей таблице исходного реестра.
6. Система обновляет список, изменения отображаются в таблице.

Исключения и ошибки:

4. Если пользователь не заполнил обязательные поля, система блокирует сохранение и выводит информационное сообщение об обязательности заполнения полей.

4. Если пользователь нажимает кнопку "Отмена" или закрывает модальное окно, система закрывает форму без сохранения изменений.

4.2. Сценарий удаления записи

# 8. Функции системы

8.1. Формирование объединенного списка записей Систем и Проектов

Система должна отображать записи из двух реестров ("Реестр Системы" и "Реестр Проекты") в одной таблице на новой вкладке "Реестр Систем и Проектов". Данные для таблицы формируются на основе маппинга полей, указанного в Таблице 2.

Структура и хранение данных в исходных таблицах не меняются. Новая таблица является агригационной витриной для исходных данных.

8.2. Автоматическое определение типа записи

Система должна автоматически определять и заполнять поле "Тип записи" ("Система" или "Проект") для каждой строки объединенного списка в зависимости от исходной таблицы.

8.3. Условное отображение специфичных полей

Система должна условно отображать специфичные поля:

- "РИРС" – только для записей типа "Система".
- "Дата начала проекта" – только для записей типа "Проект". Для неприменимых типов записей ячейки должны оставаться пустыми.

8.4. Фильтрация данных

Система должна предоставлять пользователю возможность фильтрации отображаемого списка. Фильтрация должна включать два способа фильтрации, которые применяются одновременно:

1. Фильтр по полю "Тип записи" : выпадающий список с вариантами выбора: "Все", "Система", "Проект".
2. Текстовый поиск по столбцам: поиск по всем столбцам таблицы, кроме "Тип записи". Поиск должен работать по частичному совпадению, без учета регистра.

8.5. Сортировка по любому столбцу

Система должна обеспечивать сортировку списка по любому из отображаемых столбцов (по возрастанию/убыванию) при клике на заголовок столбца, с визуальным отображением направления сортировки.

8.6. Управление записями (Добавление/Редактирование /Удаление)

Система должна предоставлять пользователям с ролями, имеющими соответствующие разрешения (подробнее: Матрица ролей и полномочий ), возможность управлять записями в "Реестр Систем и Проектов".

Добавление записи

При нажатии на кнопку "Добавить" система должна открывать модальное окно с выбором типа записи ("Система" или "Проект"). После выбора типа система должна открывать соответствующую экранную форму для создания новой записи (редактор карточки Системы или редактор карточки Проекта).

Редактирование записи

При выборе строки и нажатии на кнопку "Редактировать" система должна открывать форму редактирования, соответствующую типу выбранной записи (редактор карточки Системы для записей типа "Система", редактор карточки Проекта для записей типа "Проект"). Кнопка "Редактировать" должна быть доступна только при выборе одной строки.

Удаление записи

При выборе строки и нажатии на кнопку "Удалить" система должна выполнять удаление записи из соответствующего исходного реестра. Кнопка "Удалить" должна быть доступна только при выборе одной строки. Перед удалением система должна выводить модальное окно "Удаление" с информационным сообщением: "Удалить выбранную запись?".

# 9. [Требования к информации (данным)]

Объединенная форма является формой просмотра (отчётом/представлением) и не создаёт новую сущность хранения данных. Данные Систем и Проектов физически не дублируются и не переносятся в отдельную таблицу — они по-прежнему хранятся раздельно, в существующих таблицах справочников "Реестр Системы" и "Реестр Проекты". Создание, редактирование и удаление записей выполняются только через существующие экранные формы "Редактор Системы" и "Редактор Проекта".
