# 1. Цель и концепция решения

1.1. Цели и обоснование необходимости развития

Целью выполнения работ, необходимых для реализации функционального требования является отображение информации о распределении аналитиков по проектам, количество проектов на конкретном сотруднике, среднее количество проектов на 1 аналитика, вывод информации в случае, если у аналитика систем больше среднего значения по управлению.

# 4. Пользовательский сценарий (путь)

1. Шаг 1: Пользователь входит в систему и открывает страницу с распределением сотрудников по проектам.
2. Шаг 2: В верхней части страницы отображаются блоки с карточками: Карточки с метками: Количество сотрудников с 1 проектом Количество сотрудников с несколькими проектами Количество проектов без сотрудников Среднее количество проектов на аналитика Количество In-house сотрудников Количество Outstaff сотрудников

Эти данные должны динамически изменяться при изменении фильтров и чекбоксов.

1. Шаг 3: Пользователь может скрывать или показывать отдельные категории через чекбоксы (In-house, Outstaff, все сотрудники). После изменения фильтров данные на дашборде и в таблице автоматически обновляются.
2. Шаг 4: Под дашбордом находится таблица, которая содержит подробные данные: Продукт Проект Подпроект Направление в аналитике Тимлид аналитиков Продуктовый аналитик (Отрасль) Продуктовый аналитик (Экономика) Продуктовый аналитик (Технологии) Бизнес-аналитик, Системный аналитик, Аналитик данных, Дизайнер
3. Шаг 5: Пользователь может отфильтровать таблицу по любому из этих столбцов. Например, он может выбрать конкретный проект или продукт и увидеть только те строки, которые соответствуют выбранному фильтру.
4. Шаг 6: Строки таблицы окрашиваются в зависимости от количества сотрудников на проекте: Зеленый: если на проекте только один сотрудник. Желтый: если на проекте несколько сотрудников. Красный: если проект не имеет сотрудников.
5. Шаг 7: При нажатии на запись в таблице система должна показать подробную информацию о том, сколько сотрудников работают на проекте с ФИО по сотрудникам ДИТ и показателем по сотрудникам Outstaff. Например: Тимлид аналитиков ФИО1 - 0,25 Outstaff: 1 Продуктовый аналитик (на направление, не ИС Отрасль) ФИО1 - 1 ФИО2 - 0,5 Outstaff: 1 (если один Outstaff сотрудник работает на один проект)
6. Шаг 8: Пользователь может снова изменить значение(In-house, Outstaff, все сотрудники) или фильтры, чтобы увидеть, как изменяются данные для разных типов сотрудников.

## 5.1. Пользовательские интерфейсы

# 8. Функции системы

1. Отображение блоков с карточками (дашборд): Система должна обеспечивать динамическое обновление карточек с метками (например, количество сотрудников с одним проектом, количество проектов без сотрудников и т.д.). Для каждого из показателей система должна рассчитывать актуальные данные и отображать их в виде чисел.
2. Интерактивная таблица: Фильтрация по столбцам: Пользователь должен иметь возможность фильтровать таблицу по любому столбцу. Для этого должны быть реализованы выпадающие списки или текстовые поля для ввода значений для фильтрации. Цветовая индикация: Каждая строка таблицы должна быть окрашена в зависимости от количества сотрудников на проекте: Зеленый (1 проект на сотрудника) Желтый (несколько проектов на сотрудника) Красный (нет сотрудников на проекте). Интерактивность: При нажатии на строку таблицы система должна раскрывать подробности, показывая информацию о сотрудниках, работающих на проекте, с разбивкой по типу (In-house/Outstaff/Все сотрудники).
3. Чекбоксы для фильтрации по типам сотрудников: Чекбоксы должны позволять фильтровать данные по типу сотрудников: In-house , Outstaff, Все сотрудники . При выборе чекбоксов система должна пересчитывать и показывать обновленные данные по всем показателям, связанным с типами сотрудников.
4. Динамическое обновление данных: Все изменения, связанные с фильтрацией или выбором чекбоксов, должны немедленно отражаться на всех элементах страницы (дашборд и таблица).

Функция должна обеспечивать проверку наличие права на указание координат объекта на карте в карточке объекта в реестре имущественных торгов. Пользователь с данным правом должен иметь возможность задать координаты объекта на карте в карточке объекта.
