# 7. Пользовательский сценарий (путь)

Предусловия: Пользователь авторизован в Сервисе под ролями Администратор, Администратор НСИ, Руководитель проекта (ДИТ), Аналитик (ДИТ), Аналитик качества (ДИТ) и находится на ЭФ карточка "Система"("Расчет по методике 3-Р/НСИ/Системы/Система)

1. Пользователь кликает на вкладку "Бюджеты и закупки"

2. Пользователь просматривает информация на вкладке "Бюджеты и закупки". При наличии внутренних разработок по Системе становится доступна подвкладка "Внутренняя разработка" и пользователь имеет возможность переключения между подвкладками:

- Подвкладка "Внешняя разработка" - пункт 3.1
- Подвкладка "Внутренняя разработка" - пункт 3.2

3.1 Пользователь нажимает на подвкладку "Внешняя разработка". При необходимости пользователь переходит к просмотру следующих блоков на вкладке:

- Блок "Бюджеты системы" - пункт 3.1.1
- Блок "Текущие ГК" - пункт 3.1.2
- Блок "На закупке" - пункт 3.1.3
- Блок "Архивные ГК" - пункт 3.1.4

3.1.1 Пользователь просматривает прогресс-бары с разбивкой по годам на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Бюджеты системы"

3.1.2 Пользователь просматривает список карточек ГК на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Текущие ГК". При необходимости пользователь может воспользоваться следующими функциями блока:

- Воспользоваться функциями поиска или фильтрации в блоке для поиска ГК - пункт 3.1.2.1
- Просмотреть информацию по ГК - пункт 3.1.2.2
- Перейти в карточку "Редактор ГК" - пункт 3.1.2.3

3.1.2.1 Пользователь использует функции поиска, фильтрации

3.1.2.2 Пользователь просматривает информацию по ГК на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Текущие ГК" карточка "ГК"

3.1.2.3 Пользователь нажимает на кнопку "Перейти к ГК" на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Текущие ГК" карточка "ГК"

3.1.3 Пользователь просматривает список карточек Закупок на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "На закупке". При необходимости пользователь может воспользоваться следующими функциями блока:

- Воспользоваться функциями поиска или фильтрации в блоке для поиска Закупки - пункт 3.1.3.1
- Просмотреть информацию по Закупке - пункт 3.1.3.2

3.1.3.1 Пользователь использует функции поиска, фильтрации

3.1.3.2 Пользователь просматривает информацию в карточке Закупки на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "В стадии Закупки" карточка "Закупка"

3.1.4 Пользователь просматривает список карточек ГК в статусе Архив на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Архивные ГК". При необходимости пользователь может воспользоваться следующими функциями блока:

- Воспользоваться функциями поиска или фильтрации в блоке для поиска Архивных ГК - пункт 3.1.4.1
- Просмотреть информацию по Архивному ГК - пункт 3.1.4.2
- Перейти в карточку "Архивный ГК" - пункт 3.1.4.3

3.1.4.1 Пользователь использует функции поиска, фильтрации

3.1.4.2 Пользователь просматривает информацию по Архивному ГК на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Архивные ГК" карточка "Архивный ГК"

3.1.4.3 Пользователь нажимает на кнопку "Перейти к ГК" на вкладке "Бюджеты и закупки" подвкладке "Внешняя разработка" блок "Архивные ГК" карточка "Архивный ГК"

3.2 Пользователь нажимает на подвкладку "Внутренняя разработка". При необходимости пользователь переходит к просмотру следующих блоков на вкладке:

- Блок "Бюджеты системы" - пункт 3.2.1
- Блок "В работе" - пункт 3.2.2
- Блок "Выполненные работы" - пункт 3.2.3

3.2.1 Пользователь просматривает прогресс-бары с разбивкой по годам на вкладке "Бюджеты и закупки" подвкладке "Внутренняя разработка" блок "Бюджеты системы"

3.2.2 Пользователь просматривает список карточек ГК на вкладке "Бюджеты и закупки" подвкладке "Внутренняя разработка" блок "В работе". При необходимости пользователь может воспользоваться следующими функциями блока:

- Воспользоваться функциями поиска или фильтрации в блоке для поиска Циклов разработки- пункт 3.2.2.1
- Просмотреть информацию по Циклу разработки- пункт 3.2.2.2

3.2.2.1 Пользователь использует функции поиска, фильтрации

3.2.2.2 Пользователь просматривает информацию по Циклу разработки на вкладке "Бюджеты и закупки" подвклакде "Внутренняя разработка" блок "Текущие ГК" карточка "Цикл разработки"

3.2.3 Пользователь просматривает список карточек Закупок на вкладке "Бюджеты и закупки" подвкладке "Внутренняя разработка" блок "Выполненные работы". При необходимости пользователь может воспользоваться следующими функциями блока:

- Воспользоваться функциями поиска или фильтрации в блоке для поиска Завершенного цикла разработки- пункт 3.2.3.1
- Просмотреть информацию по Завершенному циклу разработки - пункт 3.2.3.2

3.2.3.1 Пользователь использует функции поиска, фильтрации

3.2.3.2 Пользователь просматривает информацию по Завершенному циклу разработки на вкладке "Бюджеты и закупки" подвкладке "Внутренняя разработка" блок "Выполненные работы" карточка "Завершенный цикл разработки"

#### 8.1.3 Развитие интеграции с ДИТ.НСИ

Необходимо настроить автоматическое наполнение справочников по интеграции с ДИТ.НСИ

Цель доработки:  Автоматизировать наполнение справочников "Проекты СПУ" и "Финансовый показатель в проекте СПУ"

Необходимо настроить автоматическое наполнение справочников "Проекты СПУ" и "Финансовый показатель в проекте СПУ"

Маппинг полей для наполнения справочников представлен в таблице 3.1

Ограничения по обновлению данных для конкретных справочников описаны в разделах с описанием справочника 8.1.4, 8.1.6

Описание работы интеграционного взаимодействия:

Триггер: Каждые 3 часа

Исполнитель: Система ДИТ.Калькулятор

Сценарий:

1. Каждые 3 часа каждого дня сервис ДИТ.Калькулятор инициирует процесс обновления реестров "Проекты СПУ" и "Финансовый показатель в проекте СПУ"
2. ДИТ.Калькулятор отправляет запрос в ДИТ.НСИ на обновление данных
3. Валидация и ответ ДИТ.НСИ: ДИТ.НСИ проверяет наличие записей и отправляет отчет в ДИТ.Калькулятор
4. Обработка ответа (логика для ДИТ.Калькулятор): Для каждой полученного Проекта СПУ или Финансового показателя в проекте СПУ из ответа ДИТ.НСИ: Проверить наличие Проекта СПУ или Финансового показателя в проекте СПУ в соответствующих реестрах Если найдено совпадение в БД ДИТ.Калькулятор, то выполнить обновление всех полей в карточке Проекта СПУ или Финансового показателя в проекте СПУ данными из ДИТ.НСИ Если не найдено в БД ДИТ.Калькулятор, то выполнить создание новой записи в реестрах Проекты СПУ или Финансовые показатели в проекте СПУ
5. Логирование: По итогам цикла формируется запись в журнале синхронизации (количество обработанных, обновленных, добавленных записей)
6. Система помечает статус синхронизации как «Успешно»

Исключения:

1. Таймаут или ошибка ДИТ.НСИ: Если сервис ДИТ.НСИ не отвечает или отвечает ошибкой (5xx, 4xx), то процесс синхронизации останавливается, статус помечается как «Ошибка связи». Повторные попытки связи необходимо настроить по следующему принципу: 3 попытки с интервалом 10 минут, после чего необходима отправка уведомления администратору

Справочник должен иметь следующий набор полей описанный в таблице 1.16

Доступ к справочнику должны иметь только пользователи с ролью Администратор и Администратор НСИ, подробнее про разрешения описано в таблице 1.15

Система заполняет справочник автоматически из таблицы ДИТ.НСИ - СПУ\Реестр финансовых показателей Контракт/Проект (financial_configs)

Проверки при обновлении данных в справочнике:

1. Проверка со значениями справочника "Проекты СПУ": При обновлении данных система проверяет значение поля "Код проекта" из справочника "Проекты СПУ" и значение "FinancialConfigParent" из таблицы "СПУ\Реестр финансовых показателей Контракт/Проект (financial_configs)". Если значению "FinancialConfigParent" не найдено соответствующее значение "Код проекта", то система не добавляет запись с этим "FinancialConfigParent" в справочник "Финансовый показатель в проекте СПУ" (Бизнесовый смысл: не загружать данные по проектам СПУ, которые по каким либо причинам не были загружены в НСИ ДИТ.Калькулятор)
2. Проверка со значениями справочника "Финансовые показатели":  При обновлении данных система проверяет значение поля "Наименование финансового показателя" из таблицы "Финансовые показатели" и значение в поле "FinancialConfigName" из таблицы "СПУ\Реестр финансовых показателей Контракт/Проект (financial_configs)". Если значению "FinancialConfigName" не найдено соответствующее значение "Наименование финансового показателя", то система не добавляет запись с этим "FinancialConfigName" в справочник "Финансовый показатель в проекте СПУ" (Бизнесовый смысл: не загружать данные по Финансовым показателям, которые по каким либо причинам не были загружены в НСИ ДИТ.Калькулятор)
